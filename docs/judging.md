# 審査基準と、その証拠の置き場所

キックオフ(2026年11月2日)で示された審査基準の細目と、それぞれの証拠がこのリポジトリのどこにあるかを表にした。`mm-judge` はこの表で採点する。マイルストーンを閉じるたびに「証拠」の列を更新する。

| 基準 | 細目 | 証拠 |
|---|---|---|
| インパクト(30%) | 課題が自分の暮らしや日本の具体的な現場から出発しているか | `docs/design.md` の「何を作るか」「この形に決めた理由」 |
| | テーマ2の場合、届いていなかった具体的な人を想定し、その人を阻んでいた壁を取り除いているか | 同上。母という実際の使い手 |
| | 誰が、どんな場面で、どれくらい困っているかが具体的か | 警察庁の確定値(`docs/design.md`)、母の利用の記録(未) |
| | ハッカソン後も誰がどんな場面で使い続けるかを言えるか | 母と家族の利用の記録(未) |
| デモ(25%) | 「誰の、どんな課題を、どう解決するか」が冒頭で明確か | `docs/design.md` の「デモの流れ」 |
| | 前提知識のない人でも、操作の流れで価値が分かるか | 体験モード(未) |
| | 最後まで見たくなる動画か | 動画(未) |
| Claude の活用(25%) | 基本を超えた創造的な使い方を見せているか | 作品の中の Claude の使い分け(`docs/design.md`)、ハーネス(`docs/harness.md`) |
| | Claude Code を開発の中心に据え、何が可能になったかを示せているか | `docs/dev-log.md`、`docs/claude-usage.md`、コミットの Co-Authored-By、PR のレビュー記録 |
| | モデルや機能(Skills、サブエージェント、MCP、フック)を目的に応じて使い分けているか | `.claude/`、`CLAUDE.md` のモデルの表、`docs/harness.md` |
| 深さと実行力(20%) | 試行錯誤を重ねて磨き上げた跡が見えるか | `docs/dev-log.md`、`eval/RESULTS.md` の推移、Issues と PR |
| | 設計と実装がしっかりしていて丁寧か | テスト、`docs/plan.md` のつなぎ目の約束 |
| | 困っている人が安心してそのまま使える形か | 母が手助けなしで使えたかの記録(未)、データの扱い |

運営はキックオフで、深さと実行力は「リポジトリの中まで見て判断する」と説明した。デモ動画は作ったものを伝える「唯一と言って過言ではない」手段だとも話していた。
