# 設計

2026年11月1日に、キックオフ前の構想の検討として決めた設計。主催者の FAQ に従ってキックオフ前はリポジトリの外に置き、開発スタート後の2026年11月3日にこのリポジトリへ写した(運営はキックオフで、事前に作った仕様文書や構想は使ってよいと説明している)。写すときに、家族の個人的な情報を伏せ、作者の手元にしかないファイルへのリンクを外した。コードはすべて開発スタート後に書く。

前提は応募時の構想と、主催者が示したテーマ、ルール、審査基準。実装の順番とつなぎ目は [`plan.md`](plan.md) にある。

## 何を作るか

離れて住む母の iPhone を、母が何もしなくても詐欺から守り、スマホの困りごとには声で答え、毎朝の笑顔で家族とつなぐ iOS アプリ。家族(作者、妹など)は同じアプリで母の笑顔を受け取り、危ない知らせや答えきれない相談を知って、母に電話する。

## 作品の筋

「毎日つながっている家族だから、母が気づけないときに、家族が代わりに気づいて動ける」。主役を先に仕上げ、周りの機能は残りの時間で入れる(2026年11月5日に変えた。下の「点数の見立てと伸ばし方」)。デモと説明はこの1本の筋で通す。主役は一番被害の大きいニセ警察詐欺の場面。長い電話が終わるとアプリが「さっきの電話、大丈夫だった？」と母に聞き、母がそのまま「警察から電話があった」と話すだけで、AI が筋書きを見抜いて電話を切るよう伝え、家族に何の相談でどれだけ危ないかが届く。家族は母に電話し、話したあと「解決」を押す。母が偽のページを開くと、Safari の拡張が「開かないで」を重ねる。銀行のサイトへの接続を見る DNS(#11)は作っていない。SMS の自動検知は2つ目の場面にし、毎朝の笑顔は「毎日つながっている」を見せる脇役にする。

テーマは2つ目の「本来、誰にでも届くべきものを」で出す。詳しい家族が近くにいる人だけが詐欺から守られている、という壁を取り払う。作者の本業はこの題材と遠いので、1つ目の「あなたにしかない深さ」では戦わない。

警察庁の確定値では、2025年の特殊詐欺の被害額は1,423.1億円で過去最悪だった。そのうちニセ警察詐欺が1,005.0億円で、特殊詐欺の被害額の70.6%を占める([警察庁 確定値](https://www.npa.go.jp/bureau/safetylife/sos47/new-topics/260605/01.html))。「約7割」と言うときの分母は特殊詐欺の被害額で、件数や SNS 型詐欺を含む総額ではない。確定値には2026年7月2日付の訂正が出ているので、提出前に訂正版で数字を確かめ直す。手口は、電話で「口座が犯罪に使われている」と告げ、SNS のビデオ通話でニセの逮捕状を見せ、インターネットバンキングで送金させるものが目立つ([警察庁 2025年3月末の資料](https://www.npa.go.jp/bureau/safetylife/sos47/new-topics/250428/02.html))。電話と LINE はアプリから自動で見られないので、母がやることを「ボタンを押して話す」1つにし、そのあとの銀行への接続は自動で見る予定だった(DNS が要るので2026年11月7日に提出から外した。「提出から外したもの」の節)。

この筋は2026年11月1日に審査員の立場から見直して決めた。全部の機能が同じ重さで並ぶと、高齢の親向けの便利アプリに見え、上位6には届きにくい。削る案も出たが、検知だけでは既存サービスと差が付かないので、作る範囲は変えず筋を絞った。

提出に必須なのは、通話のあとの声かけ、声の相談、家族への知らせと解決、その実測の結果。これがそろうまで、ほかの機能(Gmail、Safari、朝のアラーム、週ごとのふり返り、電話番号の一覧)には進まない。ほかの機能は間に合わなければ提出から外す。外したものと理由は「提出から外したもの」の節にまとめた。

## 点数の見立てと伸ばし方

2026年11月3日に、審査員の役のサブエージェント(Claude Opus 5.5)に、この設計と実装計画、開発のハーネスを読ませ、審査の4基準で採点させた。動くもの、デモ動画、母の利用の記録が無い段階での点だ。上位6に残れるかの見込みも聞いた。

| 時点 | インパクト(30%) | デモ(25%) | Claude の活用(25%) | 深さと実行力(20%) | 合計 | 上位6の見込み |
|---|---:|---:|---:|---:|---:|---|
| 2026年11月3日、設計、計画、ハーネスだけ | 7.5 | 7 | 7.5 | 6.5 | 71.75 | 中くらい |

採点役は、11月4日のうちに母の iPhone へ届かなければ見込みは「低い」に下がると見ていた。採点役が一番自信がないと答えたのは Claude の活用の点だった。ハーネスは動画にほとんど映らないので、作品の中の使い方だけで見られれば6点台、リポジトリまで読まれれば8点台になりうる、とのことだった。

満点にならない理由として、採点役は次の3つを挙げた。

1. 動くものがまだ無い。動画、実測、母の記録が無く、計画より1日遅れている。デモと深さはここで頭打ちになる
2. 題材から来る天井がある。主役の場面では、犯人に「誰にも話すな」と言われた母が、通話のあとの声かけに答えて話す必要がある。一番大事な場面で「母が何もしなくても」が成り立たない。電話と LINE の中身を見られないのは iPhone の制限で、誰が作っても同じ
3. 作る範囲が1人で6日には広い。拡張機能4つ、Gmail、DNS、アラーム、Managed Agents の3か所が、主役の厚みと時間を削っている

採点役は、周りの機能(Gmail、Safari、電話番号の一覧、週ごとのふり返り、朝のアラーム)を今のうちに外し、Managed Agents を1か所に減らす案も出した。2026年11月3日に作者は、外さずに全部作ると決めた。順番は「主役がそろうまで周りに進まない」条件で守り、外すかどうかは11月7日 12:00 の節目で改めて決める。2026年11月5日の朝に作者はこれを変え、周りの機能は主役の一続きが実機で通り、2台並べて撮れるようになってから残りの時間で入れることにした。入りきらなかった周りを外すかは変わらず11月7日 12:00 に決める、というのはセッションの読みで、問いと答えの原文と読みは [`CONDITIONS.md`](../CONDITIONS.md) にある。

2026年11月5日の夜に作者は、Gmail と Safari を主役の実機の確かめを待たずに今から並行で作り、毎朝の笑顔と合わせて提出から外さないと決めた(問いと答えは [`CONDITIONS.md`](../CONDITIONS.md) にある)。

審査は相対評価で、250チームから上位6チームを選ぶ。満点かどうかより、他より記憶に残るかで決まるので、満点ではなく上位6を狙う。

題材にははっきりした強さもある。被害額は過去最悪で社会的なインパクトが大きく、過去の受賞作に高齢者や詐欺対策のものは無く題材が空いている。母という本物の使い手がいて、11月8日には直接撮れる。なので題材は変えず、記録で勝負する。

ここから点を伸ばすのは、機能を足すことではなく次の3つだ。どれも母へ渡してから11月7日までに取れるので、主役を早く仕上げて母に渡せるかで点が一番大きく変わる。

- 母が誘導なしで相談できた場面を、実際に撮れること
- 最後に1回だけ測る組で、規則だけより Claude 込みのほうが良いと数字で示せること
- 家族が通知を見て、何が起きて危ないかが分かり、母に電話して解決まで動けたと示せること

## この形に決めた理由

応募の案は「母が怪しいと思ったら LINE に転送する」ものだった。でも、怪しいと思えないから詐欺に引っかかる。気づいた人しか守れない作りでは、一番守りたい場面が抜ける。そこで、詐欺のほうは母が何もしなくても気づける仕組みにした。

iPhone では他のアプリが SMS やメールを読めない。母が何もしなくても見られる範囲は、Web より iOS アプリのほうがずっと広い。

| 届く経路 | iOS アプリなら | Web なら |
|---|---|---|
| SMS | 知らない相手からのものは見られる | 見られない |
| メール(Gmail) | サーバーが読める | サーバーが読める |
| 怪しいサイト、広告 | DNS と Safari の拡張機能で見られる見込み | 見られない |
| 電話 | 登録した番号に警告を出せる程度 | 見られない |
| LINE | 見られない | 見られない |

既存の詐欺対策(ドコモの詐欺対策プラス、トレンドマイクロの詐欺バスター)は、母がスクショを送るか、検知の通知を家族に送るところまでだ。母が気づかなくても見る仕組み、スマホ相談、家族への知らせと解決、毎日のつながりを1つにしたものは見つからなかった。守るだけのアプリは何も起きない日に開かれないので、毎朝の笑顔で母が毎日開く場所にする。

過去の受賞作(Built with Opus 4.7 と 4.6)では、現場の本人が作ったもの、役割を分けたエージェント、精度を数字で示したものが上位だった。モバイルアプリと chat bot の入賞は無い。iOS アプリにしたのは、母を守る範囲を優先したから。

2026年11月に、母から電話で相談があった。iPhone に「ストレージがいっぱい」と出たがどうすればいいか、アプリが多すぎて整理できない、広告に出たストレージを空けるアプリを入れていいか、という内容だった。作者は怪しいと思い、入れないよう答えた。詳しい家族がすぐ電話に出られなければ、母は広告のアプリを入れていたかもしれない。同じ形の被害は実際に出ていて、無料ゲームの「容量がいっぱいです」という広告から入れた掃除アプリ3本で、週1,500円の課金が約1か月続き2万円を超えた事例が2026年10月に報じられた([ケータイ Watch](https://k-tai.watch.impress.co.jp/docs/column/minna/2144672.html))。IPA の安心相談窓口では、2026年7月から9月の相談3,369件のうち、偽のセキュリティ警告が1,160件で最も多かった([IPA](https://www.ipa.go.jp/security/anshin/reports/2026q3outline.html))。国民生活センターに寄せられた2024年度の偽警告の相談5,166件では、70歳以上が46.4%で最も多い年代だった([国民生活センター](https://www.kokusen.go.jp/pdf/n-20250806_3.pdf))。

## 決まったこと

- 題材は母の案。スマホ相談と詐欺対策は同じ重さで、検知、家族への知らせと解決、スマホ相談の3つとも作り込む
- 期間中に母に実際に使ってもらい、デモにもやり取りを映してよい(個人情報は伏せる)
- iOS アプリで作る。配るのは TestFlight
- 母の iPhone の初回設定は FaceTime で案内する。デモの母の場面は、提出日の11月8日に直接撮る
- 家族は何人でも招待できる。妹も入れる
- 母は声で話しかけられる
- 裏側は Cloudflare Workers の無料プラン
- Managed Agents は、怪しいものの裏の調べもの、家族への要約、週ごとのふり返りの3か所で使う予定にした。2026年11月7日の時点で作ったのは、SMS、メール、ページの知らせのあとの裏の調べものだけで、家族への要約(#12 の残り)と週ごとのふり返り(#18)はまだ無く、同じ日に提出から外した(「提出から外したもの」の節)。家族への要約にも通知とカードと同じ決まりを当て、母の言葉や届いた文を切り出さず、家族に出す前に `quotes()`([`server/src/summary.ts`](../server/src/summary.ts))を通す
- 実機で確かめていないことは、キックオフ後の初日に試す

## 全体像

iPhone のアプリは1つで、最初に「見守られる人」か「家族」かを選ぶ。家族の誰かが招待のコードを出し、母や他の家族がそれを入れるとつながる。

母の iPhone に入れるもの。

- SMS を仕分ける拡張(IdentityLookup の Message Filter)
- DNS の設定(NEDNSSettingsManager で自前の DoH を指す)(2026年11月7日に提出から外した。「提出から外したもの」の節)
- Safari の拡張機能(開いたページに警告を重ねる)
- 共有の受け口(スクショやメールの文面を渡す)と、背面タップのショートカット
- 笑顔で止めるアラーム(AlarmKit と ARKit の顔トラッキング)(2026年11月7日に提出から外した。「提出から外したもの」の節)
- 詐欺に使われた番号の一覧(CallKit の Call Directory)(2026年11月7日に提出から外した。「提出から外したもの」の節)

Cloudflare Workers が受け持つもの。

- SMS の問い合わせ先。Apple から送り主と本文が届き、決まった規則で即答する
- DNS(DoH、RFC 8484)。上流は 1.1.1.1。危ないドメインを止めて記録する(2026年11月7日に提出から外した。「提出から外したもの」の節)
- ページの判定。Safari の拡張機能からの問い合わせに答える
- 相談の受け口と、相談と解決の記録(D1 を正にする)
- Gmail の見張り。Cron Trigger で5分ごと
- iPhone への通知(APNs)

Claude の使い分け。

- Haiku 5.5(`claude-haiku-5-5`)は、即答のあとに重ねる判定と理由づけ
- Sonnet 5.5(`claude-sonnet-5-5`)は、母との会話とスクショの読み取り(押す場所の座標)
- Managed Agents は、急がない作業。即答と母との会話の1往復には使わない(応答の速さの目安が公式に無く、セッションの記録は削除するまで残るため)

## 母の画面

母の画面は、ChatGPT や Claude のアプリと同じ、ふつうの AI チャットの形にする。上に家族の知らせと通話のあとの声かけ、真ん中に会話、一番下に文字の欄が並ぶ。AI の答えは吹き出しに入れず、幅いっぱいの地の文で出す。吹き出しは右に寄せた母の言葉だけにする。古いものから順に並び、開くと最新が見える。マイクを押して話しても、欄に書いて送っても、同じ会話に並ぶ。欄は細い1本で、マイクは欄の中に送るボタンと同じ大きさで収め、文字を入れると送るボタンに替わる。聞き取り中はマイクが赤い波形になり、聞き取った言葉は母の吹き出しとして伸びていく。文字は大きさを決め打ちせず、iOS の「文字サイズ」に従う(Dynamic Type の標準の本文)。画面の文字は欄の名札(「メッセージ」)だけにし、説明は読み上げ(VoiceOver)に残す。

家族の知らせは、会話の上の細い帯1本にまとめる。知らせは届いていない、返事がまだ、伝えた、の順に並べ、同じ中では新しい順にして、上から3件までを出す。並べてから3件に切るのは、届いていない古い相談が、届いた新しい相談に押し出されて画面から消えないようにするためだ。裏側は相談から24時間を過ぎると最初の知らせを送り直さず([`server/src/cases.ts`](../server/src/cases.ts) の `FIRST_NOTICE_RETRY_MS`)、解決していない相談は3日のあいだ画面に残る。閉じているときは先頭の1件と件数を出し、押すと同じ順で全部が開く。「急ぐなら電話して」で終わる知らせは、どの幅と文字サイズでも「電話して」が切れないよう、閉じていても行数を決めずに折り返す。「家族に伝えました」は2行までにし、アクセシビリティ向けの大きな文字サイズでは折り返す。開いたときは画面の4割までにし、それより多ければその中でずらして見る。スクショを送る入口と、家族から届いた笑顔とひと言もこの画面に足す。

はじめは、家族から届いた笑顔とひと言の下に大きなマイクのボタンが1つあるだけの画面だった。作者が2026年11月4日に、チャットにすると決めた(「大きなマイクボタン一つだけは嫌」「LINE とかメッセージアプリ、Instagram とかを使いこなせる人も対象にしたい。母がまさにそう」)。そのときは LINE と同じく AI の答えも左の吹き出しに入れ、文字とマイクを大きく決め打ちしていた。作者は自分の iPhone で見て「ふつうのAIチャットボットを比較してなんか全然UIUXがよくない」「なんか高齢者とかを意識しすぎ」と言い(#86)、2026年11月5日に、AI の答えも吹き出しにする見本と地の文にする見本を見比べて、地の文のほうを選んだ(#87)。ふつうの AI チャットの見た目で、AI の長めの答えが読みやすいためだ。

危ないものが届いたときは、通知と画面の両方で「開かないで」と出す。「家族に伝えました」も同じ画面に出し、何を伝えたかを母が見られるようにする。知らせが家族のどの端末にも届かなかったときは、相談の答えと画面の知らせの両方で、「家族に伝えました」の代わりに「家族に届いていません。急ぐなら電話して」と出す。30分たっても届いていなければ「家族から返事がまだ」より先にこちらを出し、送り直しが届いたら「家族に伝えました」に戻る(「失敗したとき」の節)。

## 家族の画面

毎朝、母の笑顔が届く。家族は自分の笑顔かひと言で返す。家族同士の笑顔も見える。

知らせはカードで家族全員に届き、全員が同じカードを見る。カードには危なさの段階、困りごとの1行、AI が母に何と答えたか、「まだ解決していない」か「(名前)が解決」が載り、ボタンは「電話する」と「解決」だけにする。判定の理由と裏の調べもので分かった根拠は読み上げ(VoiceOver)で聞ける。根拠は、調べものが挙げた公式のページのサイトごとに「警察庁の注意喚起」のような決まった1行にし、エージェントの書いた文は家族に出さない(2026年11月7日、#12)。母と電話で話した人が「解決」を押し、ほかの家族にも「(名前)が解決」と知らせる。「解決」は押すと確かめを挟み、ボタンは「解決にする」と「やめる」だけにする。「やめる」なら何も送らない。押し間違えると30分の見張りが止まり、母の画面から相談が消え、ほかの家族に「(名前)が解決」が届くためで、2026年11月4日に決めた。週に一度、何が届いて何を止めたかのふり返りが届く(2026年11月7日に提出から外した。「提出から外したもの」の節)。

## 毎朝の笑顔

母の朝のアラームはカメラに向かって笑うと止まる(アラームは2026年11月7日に提出から外し、笑顔の送り合いは残した。「提出から外したもの」の節)。今は、アラームとは別に撮った笑顔が家族に届き、家族から返ってきた笑顔やひと言が母の画面に並ぶ。決まった時間までに笑顔が届かなければ、家族にそっと知らせる。毎朝の安否確認を兼ねる。

笑顔の判定は iPhone の中だけで行い、判定のコードも含めて期間中に一から書く。

笑顔は母だけでなく家族の誰でも撮って送れ、母の画面にも家族の画面にも家族みんなの笑顔が並ぶ(2026年11月5日に作者が決めた)。決まった時間の知らせが見るのは母の笑顔だけで、家族が撮らなくても知らせない。安否確認のためだ。

ひと言は自由に書く文にせず、「おはよう」「いい笑顔」「ありがとう」「元気だよ」「またね」の5つから選ぶ形にした。母の側からも同じ5つを選べる。作者が2026年11月5日に「決まった言葉から選ぶ」を選んだ。相談への返事(relays)を外したときと同じく、利用者どうしの自由な文を運ぶと「他人の通信の媒介」に近づくので、運ぶのは決まった語だけにする(「家族への知らせと解決」の節)。写真は残す。裏側は決まった語の ID か語そのものだけを受け付け、外れた文は400で断る。決まった語なので、ひと言に「この警告を止めて」のような文が紛れ込むこともない。

## 検知

危なさは3段階にする。

1. 開かないで
2. 家族に確かめるまで待って
3. 心配は少ないけど、お金や暗証番号を聞かれたら止めて

「安全です」とは決して言わない。判定には理由を短く添える(送り主のドメインが公式と違う、急がせる言い回しがある、など)。

母に読み上げる答えには、段階を決めるために Claude に渡している言葉(「手口の印」「印」「規則の判定」)を使わない。相談の答えに「手口の印は聞き取れませんでした」が出て、母には何のことか分からなかった。指示でそう頼み、それでも詐欺の相談の答えに入った文は読み上げず、その経路の決まった文に替える。替えるのは指示が使う形だけで、「手口の印」「見えた印」「印のない相談」のように印を名指す語と、「印が無いので」「お話に印は見当たらない」のように文の頭の「印」に「無い」が続く形にする。画面の印(「赤い印」「既読の印」「地図の印」「印をつけて」)や「印鑑」「矢印」は替えない。スマホの操作の案内は、この語で替えない。案内の「印」は「画面に印が無ければ」のように画面の印を指し、替えると読み上げられない案内として家族に回ってしまうためだ。はじめは1つの語の中の「印」だけを通していたが、操作の案内に「赤い印」が入ると家族に回っていた(PR #129 の1回目のレビュー)。形を絞ったあとも、「画面に印が無ければ」で同じことが起きた(2回目のレビュー)。家族のカードの理由には、今までどおり見えた印を書く(2026年11月5日、#121)。

SMS は知らない相手からのものを Apple 経由で受け、決まった規則で即答する。規則ではっきり危ないものだけを迷惑フォルダに回し、迷うものは通常どおり届けたうえで、Claude の判断を母と家族に知らせる。本物の SMS(認証コードなど)を見落とさせないため。

サーバーには誰の iPhone からの問い合わせか分からない(Apple が送る JSON に端末や利用者を識別する項目が無い)。なので、母に配るビルドは問い合わせ先の URL に家族の印を入れる。審査員向けのビルドは体験モードにし、家族に届くはずのカードを同じ iPhone の中で並べて見せる。体験モードは主役の電話の相談から始め、家族が解決を押す場合と、30分たっても解決しない場合の両方を試せるようにする。SMS の判定はそのあとに試せるようにする。家族まで届くという一番の差を、審査員が1台で体験できるようにするため。

対象は連絡先に無い相手からの SMS だけで、iMessage は見られない。

問い合わせ先の URL はビルドごとに1つなので、母には母の家族の URL を入れた版を、母だけの外部テストのグループで配る。審査員の版は `demo` のままにする。2026年11月5日に作者が決めた(#133)。

Gmail では5分ごとに母の受信箱の新しいメールを読む。`gmail.readonly` を Google の審査なしで使える「テスト」の状態で使い、母をテストユーザーにする。読むだけで、母の Gmail には手を加えない。母の許可は7日で切れるので、11月2日以降にもらい、切れる前に取り直す。許可の画面には「未確認のアプリ」と出るので、FaceTime で案内する。許可は母の iPhone からだけ取る。母の画面の上に「Gmail」のボタンを1つ置き、押すと Google の同意の画面がシステムのサインインの画面(`ASWebAuthenticationSession`)で開く。ボタンは許可が無いときと、許可から6日たって切れそうなときだけ出し、それ以外は母に新しい操作を見せない。家族には、6日たったときに「Gmail の許可がもうすぐ切れます」、切れたときに「Gmail の許可の取り直しが要ります」を1回ずつ知らせ、家族が電話で母に取り直しを頼む。2026年11月6日に #15 の実装の中で主のセッションが決め、作者には PR #143 で伝える。

メールの送り元は From の表示名を除いたアドレス(addr-spec)から取る。最後の山括弧が From の終わりにあればその中、山括弧が無ければ From 全体がアドレスのときだけそれを使う。表示名は何でも書けるので、表示名に山括弧つきで公式のアドレスを書いても、送り元はそのあとの本当のアドレスになる(例は [`server/test/gmail.test.ts`](../server/test/gmail.test.ts) の試験にある)。それより前は From の中で最初の山括弧を送り元にしていて、詐欺が表示名で公式を名乗ると、規則の確かさ(`confident`)が外れていた(#170)。山括弧が閉じていない、山括弧のあとに文字が続く、山括弧の中がアドレスでない、引用符の外にカンマがあってアドレスが2つ以上ある From、上限の500字を超えるアドレス、それとドメインが英数字とハイフンのラベルを点でつないだ形でないアドレスとローカル部が ASCII の印字できる文字でないアドレスは、送り元を空にする。ドメインの形は、規則が NFKC と URL の読みを通す前の生の文字で見る。`?`、`/`、`#`、全角の `＠` を入れたドメインは、Gmail から見たドメインと、規則が URL のホストとして読むドメインが食い違い、公式のドメインのあとに詐欺のドメインを続けた形で公式を名乗れたからだ(PR #171 の1回目のレビュー)。送り元が無ければ公式にも数えないので、読み違えたときは確かさを外さない側に倒れる。表示名の符号化(`=?UTF-8?B?...?=`)はアドレスの中には書けない決まりなので、From は符号化を解かずに読む。長すぎるアドレスを切って残さないのは、切った先がちょうど公式のドメインで終わる形を作れるからだ。2026年11月6日に #170 の実装役が決めた。

SPF や DKIM の結果(`Authentication-Results`)は、今は見ない。`users.messages.get` の `format=full` の `payload.headers` は名前で引けるので、届いていればコードからは読める。ただ Google の参照([users.messages](https://developers.google.com/workspace/gmail/api/reference/rest/v1/users.messages) と [Format](https://developers.google.com/workspace/gmail/api/reference/rest/v1/Format)、2026年11月6日に読んだ)には「To、From、Subject のような RFC 2822 の見出し」とあるだけで、`Authentication-Results` が入るとも、見出しが届いた順に並ぶとも書いていない。`Authentication-Results` は送り手が自分で書き足せるので、Gmail が付けたもの(先頭の `mx.google.com` のもの)だけを数える必要があり、その見分けを順番に頼ることになる。母の受信箱の本物のメールで確かめられないまま、読み違えて本物の銀行の知らせから公式を外すと、規則の段階が確かになり、Claude が本物と見ても段階を軽くできなくなる。#170 のあとに公式を名乗るには、From のアドレスのドメインを公式のドメインそのもの(かその下のドメイン)として偽る必要があり、見張りは受信トレイ(`labelId=INBOX`)だけを読むので、Gmail が DMARC で弾いたり迷惑メールに回したりしたメールは規則に届かない(Gmail がどのドメインでどう扱うかは、ここでは確かめていない)。残るのは、DMARC を置いていないか緩くしているドメインを名乗る偽りで、それでも段階は残り、母と家族への知らせと Claude の判定は止まらない。本文に公式のリンクを書けば確かさが外れる引き換えを [`eval/README.md`](../eval/README.md) で受け入れたのと同じ考えで、公式の送り元は確かさを外すだけに使い、段階は下げない。見るようにするなら、Gmail が付けた `Authentication-Results` に `dmarc=pass` が無く、送り元のドメインが公式のときだけ送り元を外す形にする。公式でない送り元は今までどおり残し、似せたドメインの印を落とさない。`JudgePayload` の形は変えない。2026年11月6日に #170 の実装役が決めた。

サイトは2段構え(DNS は2026年11月7日に提出から外した。「提出から外したもの」の節)。DNS では、母の iPhone が行こうとしたドメインを見て、危ないものは止めて記録する。Safari の拡張機能は開いたページの中身まで見て、ページの上に警告を出す(全サイトでの許可を初回に設定する)。Safari 以外のブラウザやアプリ内のブラウザでは拡張機能が動かず、DNS も外したので、今はそこでは何も見ていない。

ニセ警察詐欺は通話のあとの声かけを相談のきっかけにし、3段構えで受ける。声かけは、母が自分で思い立たなくても相談のきっかけがアプリのほうから来るようにするためのもので、通話の終わりの声かけと毎日の声かけの二段にする。2026年11月5日に作者が決めた([#25 のコメント](https://github.com/sagochiko/mimamori/issues/25#issuecomment-6645340403)、#99)。

通話の終わりの声かけでは、アプリが前面にあるあいだ `CXCallObserver` で通話がつながってから終わるまでを測り(電話番号は分からない)、3分以上の通話が終わったら母に「さっきの電話、大丈夫だった？」と通知で聞く。「大丈夫」を押せば何もしない。アプリが止まっているあいだは通話の終わりが分からない。Apple の DTS の担当者が、`CXCallObserver` はアプリが止まっているあいだは通話の変化を知らせず、終わった通話をあとから知る公開の API も無いと答えていて([Apple Developer Forums](https://developer.apple.com/forums/thread/849682))、作者の iPhone 16(iOS 27.2)で3回試しても、前面に開いていたときだけ通話の終わりが届いた(「2026年11月5日に分かったこと」の節)。アプリを開いたときに直近の通話について聞く案も、通話があったこと自体が分からないので成り立たない。ショートカットの「電話が閉じた」のオートメーションは、電話に出て切る流れでは3回とも動かなかったので使わない。

毎日の声かけでは、決まった時刻にローカル通知で「今日、知らない人から電話や連絡はあった？」と聞き、押すと母の相談の画面(チャット)が開く。アプリが通話を知れなかった日にも、相談のきっかけを作るため。通知がうるさいかもしれないので母の側で切れるようにした(作者)。母の画面に設定の画面は足さず、iOS の「設定」の「みまもり」に、オンとオフと、17時から21時までの5つの時刻を置く。既定はオンで18時にした。その日の電話のことを、次の日に送金する前に聞くため。夜22時から朝7時の時刻は選べず、通話のあとの声かけを出した日は、その日の毎日の声かけを出さない。通知は今日から30日分を1日1件ずつ予約し、アプリを前面に開くたびと、役が変わったときに組み直す。繰り返しの通知では、声かけを出した日だけを飛ばせないため。iOS が残す予約は近いものから64件までと [UILocalNotification の文書](https://developer.apple.com/documentation/uikit/uilocalnotification) にあり(今の `UNUserNotificationCenter.add(_:)` の文書には数が無い)、30件はその半分に収まる。「設定」で変えた値も、次にアプリを前面に開いたときに読むので、それまでは予約済みの通知が出る。「設定」は別のプロセスで、別のプロセスが値を変えても `UserDefaults.didChangeNotification` は出ない([Apple の文書](https://developer.apple.com/documentation/foundation/userdefaults/didchangenotification))うえ、止まっているアプリは何もできないため。

1つ目は電話のあとの声の相談で、母が「警察から電話があって、口座が犯罪に使われてるって」と話すと、Claude がニセ警察の決まった筋書き(口座が犯罪に使われている、潔白の証明、ほかの人に話すな、ビデオ通話への誘い、送金や口座の移し替え)を見抜く。母には、見えた根拠と勧める行動を分けて「詐欺で使われる説明と一致しています。送金せず、いったん電話を切って家族に確かめて」と返し、家族に1段階で知らせる。広い言い切りはしない。Claude を待たずに1段階と決める筋書きの部品は、この一覧のまま(逮捕や捜査をほのめかす話を含む)にする。相談だけで読む言い方として、携帯の契約やマイナンバーが犯罪に使われた、事件や捜査に本人の名前が出た、自動音声のあとに警察を名乗る相手につながった、カードや通帳を人が取りに来る、の4つの部品と、元の部品の言い方の幅(逮捕しに行く、身柄を、LINE で令状を見せる、人に言っちゃだめ、警察の名乗りと並んだときだけの犯罪を疑われた話)を足した。これらは元の一覧の部品が1つ並んだときだけ筋書きの部品に数え、単独ではいくつ並んでも2段階までにして Claude に回す。足した部品が暗証番号を求める話のような別の中くらいの印と並べば規則は1段階になるが、確かな印ではないので、Claude が答えれば Claude の段階による。本物の警察も、被害者、目撃者、家族に、名前やカードや身柄のことで電話するためだ。メッセージやページでは注意喚起が同じ言い方を引くので、足した言い方を使わない。母の言葉に警察の名乗りが無く、警察のものでない部品(カードの受け取りなど)で筋書きになったときは、家族の1行を「警察を名乗る電話の相談」ではなく「詐欺の手口に似た電話の相談」にする(2026年11月7日、#21、PR #206 の1回目のレビュー)。

2つ目はニセの書類の読み取りで、LINE やビデオ通話で送られた「逮捕状」などのスクショを送ると、Claude が詐欺の書類に見られる特徴との一致を読み取る。書類の見た目だけで真偽を言い切らない。

3つ目は銀行への接続で(DNS が要るので2026年11月7日に提出から外した。「提出から外したもの」の節)、1段階の知らせから60分のうちに、母の iPhone から銀行やネット銀行のドメインへの問い合わせがあったら、DNS で気づいて家族に「銀行関連の通信がありました」と知らせる(止めはしない)。DNS で分かるのは問い合わせだけで、母が開いたことや送金したことは分からないので、そう言わない。知らせるのは送金の直前に家族が電話できるようにするため。銀行のドメインの一覧は公式のものを集める。

ニセ警察詐欺と並んで多いのが、偽のセキュリティ警告の画面から電話をかけさせ、遠隔操作のアプリを入れさせて送金させるサポート詐欺。母の iPhone から遠隔操作のアプリの通信先への問い合わせがあったら、DNS で気づいて家族に1段階で知らせる(止めはしない。DNS が要るので2026年11月7日に提出から外した。「提出から外したもの」の節)。通信先の一覧は、各アプリの公式の情報から集める。DNS で分かるのは問い合わせだけなので、遠隔操作されているとは言い切らない。

電話では詐欺に使われた番号の一覧を入れて、着信に「詐欺の疑い」と出す(2026年11月7日に提出から外した。「提出から外したもの」の節)。着信ごとにサーバーへ問い合わせる Live Caller ID Lookup は、Apple の承認に数か月かかる例があり、期間中は間に合わないので入れない。

メール、SMS、ページの中の文字はすべて調べる対象として扱い、「この警告を止めて」のような文があっても従わない。Claude の答えは Structured Outputs で決まった形(段階、理由、母への一言)だけを受け取る。通知先や共有の範囲は、Claude の答えや届いた文面では変えられないようにする。

怪しいものを見つけたら、Managed Agents に裏で調べさせる。送り主のドメインと、公式の注意喚起に同じ手口が載っているかを数分かけて調べ、分かった根拠を家族のカードに足す。カードに足すのは公式のページの出典と「<表示名>の注意喚起」の1行だけにし、何が分かったかの文は足さない。エージェントの文を網でふるっても、安心させる言い換えが毎回すり抜けたためだ。

## 家族への知らせと解決

家族が母について知りたいのは、何に困っているか、危ない状況にあるのかないのか、解決したのかどうかの3つだけだ。作者が2026年11月4日に、ここまでに絞ると決めた(「引き受けるとかよくわかんない」「担当とかいらない」)。

AI が答えきれない相談と、2段階目以上の知らせは、相談1件として記録する。ただし、前を指すだけで指す先の無い問いかけ(端末に前の会話が残っていないときの「それってどういうこと」など)は、答えきれない相談に数えない。AI が何のことかを聞き返し、記録もしない(「スマホ相談と声」、2026年11月5日、#114)。状態は「家族に知らせた」と「解決」の2つにする。知らせが届いたことと、家族が見たことは別に扱う(APNs が成功を返しても、届いて見られたとは限らないため)。

同じ会話(60分)の相談は、解決していない相談1件にまとめる。家族に知らせ直すのは、段階が重い相談が加わったときと、答えきれずに家族に回した2段階の相談(詐欺の印は無い)に詐欺の印のある2段階の相談が加わったときで、カードの困りごとの1行と理由もそちらに替える。答えきれない問いのあとにニセ警察の相談が続いても、家族に警察の相談として届くようにするためだ。それ以外の相談が加わっても、知らせ直さない(2026年11月5日、#114)。前を指す問いかけに前の日の会話が付いて届いても、まとめるのは60分の中の相談だけで、前の日の相談には足さない(2026年11月5日、#118)。

知らせは家族全員に届き、全員が同じカードを見る。受け持ちは決めない。母と電話で話した人が「解決」を押し、ほかの家族に「(名前)が解決」と知らせる。解決は家族の誰でも押せ、ほぼ同時に押されても知らせは1回だけにする。解決した相談は母の画面から消える。30分たっても解決しなければ、母には「家族から返事がまだ。急ぐなら電話して」と出し、家族全員にもう一度「まだ解決していません」と知らせる。

AI はいつも母に答える。家族が見ているあいだも案内を止めない。家族はアプリの中で母に返事を送らず、話したいときは電話する。詐欺の電話の最中に家族が本当にするのは母への電話で、アプリの中の1通の返事は電話より弱い。

家族への通知とカードには、母の言葉や届いた文をそのまま切り出して載せない。困りごとの1行は、ニセ警察の筋書きなら決まった1行(「警察を名乗る電話の相談」)にする。前の母の言葉で筋書きを話したあとの「それってどういうこと」のような前を指すだけの問いで、指す先(前の母の言葉のうち、何かを言っている最後の1件)が筋書きの部品を含むときも、Claude に回して段階は Claude と規則で決めるが、1行は同じ決まった1行にする。規則は今の言葉しか見ず、Claude の行は母の言葉を写すと使えないので、警察の話の答えなのに「スマホの相談」と届いていた(2026年11月6日、#128)。ほかは、Claude に聞いた相談なら Claude が自分の言葉で書いた20字以内の1行、SMS などなら経路と判定の理由とドメイン(「SMS 銀行を名乗る example.com」)から作る。Claude の書いた行が母の言葉や届いた文を8字続けて写していたら(読点、中黒、空白、全角と半角の違いは数えない)使わず、決まった1行(「スマホの相談」)に替える。読み上げで聞ける理由も同じようにふるい、残らなければ規則の理由か「家族に確かめるまで待って」にする。カードの AI の答えが母の言葉を写していたら、カードには「答えました」とだけ出し、母への答えはそのまま返す。母の言葉に AI や見守りに向けた指示が混ざっていたら、Claude の1行は使わず理由から作る。

はじめは、最初に「引き受ける」を押した家族が受け持ち、その相談では AI が案内を止め、受け持ちが書いた1通を母の画面に「(名前)から」と出して読み上げる形だった。2026年11月4日に外した。引き受けから60分は別の話題でも AI が「(名前)が見ています」としか答えず、返事を受けた母が声で返しても誰にも届かなかった。利用者どうしのメッセージは、総務省の[電気通信事業参入マニュアル[追補版]](https://www.soumu.go.jp/main_content/000477428.pdf)(令和5年1月30日改定)の28ページで「他人の通信の媒介」の例に当たる。母の言葉の先頭30字をそのまま家族に届ける形も、同じマニュアルの19ページの「電話の内容を自動で文字に起こしてメールやチャットで提供する」例に近かった(経緯は [`dev-log.md`](dev-log.md))。

相談1件ごとに Managed Agents のセッションを1つ立て、家族への要約を作らせる(2026年11月7日に提出から外した。「提出から外したもの」の節)。この要約にも通知とカードと同じ決まりを当て、母の言葉や届いた文を切り出さず、家族に出す前に `quotes()`([`server/src/summary.ts`](../server/src/summary.ts))を通す。状態の正は D1 にして、エージェントの記憶と食い違わないようにする。週ごとのふり返りも Managed Agents の定期実行で作る予定だった(2026年11月7日に提出から外した。「提出から外したもの」の節)。

## スマホ相談と声

母が話した声は iPhone の中で文字にし、Claude に渡す。書いて送った言葉もそのまま渡す。答えは画面の会話に出し、読み上げは既定でしない。声で聞いたときも読み上げない。2026年11月5日、作者が実機で試したあとに既定をオフにすると決めた(#115)。読み上げたいときは、毎日の声かけと同じく iOS の「設定」の「みまもり」の「読み上げ」をオンにする。母の画面に切り替えは足さず、名札は1語にして説明の文は置かない。オンにしても読み上げるのは声で聞いたときだけで、文字で聞いたときは読み上げない。人前で急に声が出ないようにするためだ。「設定」で変えた値は、次の答えが届いたときに読む。

がつながらない」)は、前のやり取りが無いときと同じに答える。AI の行の中の仕込みの文は下限に使わない。AI の行は端末が残した裏側の答えで、母の言葉ではないからだ。家族に届く中身(段階、困りごとの1行、理由)の作り方も変えず、前の母の言葉も切り出さない。2026年11月4日に作者が決めた(#73)。スクショが付いていれば、押す場所を座標で返させ、そこに丸を付けた画像を見せる。押せたかは次のスクショで確かめ、一手ずつ進める。

画像は送る前にこちらで縮小し、返った座標がそのまま使える状態にする(公式の推奨)。公式は「位置は近似なので確かめてから使う」としているので、丸は次のスクショで確かめる一手とセットにする。iPhone 15 のスクショ(1179×2556)なら、高解像度の扱いで縮小なしに読める。

送金、認証コードの共有、構成プロファイルの導入、データの削除は案内しない。その場合は家族に回す。

「読み上げ」がオンのとき、AI の答えは母の iPhone の普通の読み上げの声で読む。家族はアプリの中で母に返事を送らず、電話する(「家族への知らせと解決」の節)。

はじめは家族の iPhone のパーソナルボイス(端末の中で作る本人そっくりの声)で返事を音声にする案だった。2026年11月3日に調べると、パーソナルボイスを作れる言語は英語(米国)、中国語(北京語、中国本土)、スペイン語(メキシコ)の3つだけで、日本語が無かった([Apple の iOS 27 の提供状況](https://www.apple.com/ios/feature-availability/))。家族が自分の声を録って送る案も出たが、作者は普通の声にすると決めた。その家族の返事も、2026年11月4日に外した。

## アプリからの声かけ

困っても誰にも相談しない高齢者は37.4%いて、その理由の約半分は「自分で解決できると思った」だった([トビラシステムズ](https://tobila.com/news/report/p2525/))。母に「困ったら相談して」と頼むだけでは足りない。通話のあとの声かけと同じく、アプリのほうから気づいて「一緒にやろう」と声をかける点検を置く。点検はアプリを開いたときと、バックグラウンドの更新のときに端末の中で回し、声かけは通知と母の画面の両方に出す。

| 点検 | 何で気づくか | 声かけと引き継ぎ |
|---|---|---|
| 空き容量 | OS から空きの量を読む | 少なくなったら、設定の「iPhone ストレージ」から一緒に空けようと声をかけ、スクショで一手ずつ案内する。広告の掃除アプリは入れなくていいと伝える。空き容量とそこから判断したことは端末の外へ送れない(Apple の[理由の申告が要る API](https://developer.apple.com/documentation/bundleresources/describing-use-of-required-reason-api))ので、家族には知らせない |
| iOS の更新 | 今の版をアプリで読み、最新の版は裏側が Apple の[開発者向けリリース情報](https://developer.apple.com/news/releases/rss/releases.rss)から取る | 古いままなら「夜に充電しながら更新しよう」と声をかける。公式の API は無いので、取れないときは声をかけない |
| 迷惑なカレンダーの予定 | カレンダーの許可をもらい、購読しているカレンダーを見分ける | 「ウイルスに感染」のような予定が並ぶ購読カレンダーを見つけたら、消し方を案内する。アプリから消せるかは公式に書かれていないので、実機で確かめる |
| サブスクの見直し | 気づけない(ほかのアプリの課金は見えない) | 月に1回、設定のサブスクリプションの画面まで一緒にたどる。アプリを消しても解約にならないことも伝える([国民生活センター 見守り新鮮情報 第545号](https://www.kokusen.go.jp/mimamori/pdf/shinsen545.pdf)) |
| 見守りの自己点検 | 通知の許可とバックグラウンドの更新の状態を読み、毎日裏側へ生存の知らせを送る | 母が通知を切ったりアプリを閉じたりすると、ほかの点検が黙って止まる。生存の知らせが48時間途切れたら、家族に「見守りが止まっている」と知らせる |
| iCloud のサインアウト | iCloud のサインインの印が消えたことを読む | 母に確かめ、心当たりがなければ家族に回す。乗っ取りや操作の迷いのきっかけになるため |

ほかのアプリの一覧、iCloud の残り容量、端末全体の画面の使い方は、アプリからは読めない。「アプリが多すぎて整理できない」は気づく側ではなく、声の相談とスクショの案内で受ける。

## データの扱い

- 笑顔の写真は家族の間だけで共有し、Claude にも Managed Agents にも渡さない
- スクショはその場で処理して残さない。残すのは要約と危なさの段階だけ
- Managed Agents に渡すのは怪しいメッセージの中身だけで、母との会話は渡さない
- 鍵(Claude、APNs、Google)は Workers の秘密の置き場に置き、公開リポジトリには入れない
- リポジトリに実際の相談やメールは入れず、試験用の例文だけを置く

残す期間は30日。知らせ、相談、笑顔の写真は30日たったら自動で消す。家族を抜けた人の端末の鍵はその場で無効にし、以後は何も見られない。母か家族の誰かが「すべて消す」を押すと、その家族のデータを裏側からすべて消し、Gmail の許可を取り消し、Managed Agents のセッションも削除する。

「すべて消す」は2026年11月1日の設計で入ったが、そのときの理由は残っていなかった。2026年11月3日に、確かめた次の3つの事実を理由として作者と決め直した。

1. Apple の審査の決まりの 5.1.1(v) に「If your app supports account creation, you must also offer account deletion within the app.」とあり、2.2 で TestFlight のベータ版もこの決まりに従うとしている([App Review Guidelines](https://developer.apple.com/app-store/review/guidelines/))。審査員向けのビルドは外部テストの審査を通る。この決まりだけなら「家族を抜ける」で足りる見込み
2. 裏の調べものには、母に届いた怪しいメッセージの本文を渡す。Anthropic は「Claude Managed Agents is a stateful resource; session transcripts persist until you delete them.」としている([API and data retention](https://platform.claude.com/docs/en/manage-claude/api-and-data-retention))
3. 知らせ、相談、笑顔は家族のもので、「家族を抜ける」は抜けた本人の行しか消さない。母が抜けても、家族の誰かが残っていれば母の相談は残る

30日の自動削除と違うのは、すぐに消せることと、Gmail の許可の取り消し、家族と端末の鍵の削除。Anthropic か Google が消す依頼を断ったとき(調べものが動いている最中など)は、家族のデータと鍵を消さずに失敗を返す。押し直すと、外の分の続きから消す。外の分だけを残して自動で試し直す案もあったが、表が1つ増えて M1 に響くので採らなかった。

SMS、メール、Safari のページで3段階になったもの(規則が印を付けず Claude も答えなかったものを含む)は、知らせの行を残さない。この3つの経路は母が受け取ったものや開いたものの多くを Claude に見せるので、行を残すと母の受信箱と閲覧の記録になってしまうためだ。残すのは1段階と2段階と、相談だけにする(2026年11月6日、#137)。

知らせが多すぎると家族が反応しなくなる。家族に通知を送るのは1段階と2段階の知らせと、家族に回した相談、その解決だけにする。3段階は通知を送らない。同じ送り主やドメインの知らせは、1時間に1回にまとめる。例外として、誰かが家族に入ったときは、先にいる家族全員に「(名前)が入りました」と知らせる。6桁の招待のコードを総当たりで当てて入り込まれても気づけるようにするためで、2026年11月3日に #4 のレビューを受けて作者が決めた。入るときは接続元ごとに回数も絞る。

母には使い始めに「家族に伝えることがある。伝えたら必ずあなたにも言う」と一度示す。使うことへの同意と、動画に映すことへの同意は分けてもらい、公開前に映す範囲を母と確かめる。

## 失敗したとき

一番怖いのは DNS が止まって母の iPhone がネットにつながらなくなることだ(DNS はこれを確かめられないまま2026年11月7日に提出から外した。「提出から外したもの」の節)。Workers の無料プランは1日10万リクエストまでで、1回の処理の CPU 時間は10ミリ秒。上限に近づいたら家族に知らせる。DNS のサーバーにつながらないときに iPhone が普通の DNS に戻るかはタスク8で確かめ、戻らないなら有料プランにするか DNS を外す。

Claude の呼び出しが失敗したり遅れたりしたときは、決まった規則の判定だけで知らせ、母には「確かめ中」と出す。SMS、メール、ページで規則も段階を決めなかったものは、誰にも知らせない。この3つの経路は規則が印を付けないものも Claude に見せるので、ふつうのお知らせや記事が Claude の失敗で家族に届かないようにするためだ(2026年11月6日、#137)。数十秒かかる処理は、Workers の waitUntil(レスポンス後30秒まで)では足りないので Queues に回す。母の声の相談だけは、母が画面で待つ1往復なのでリクエストの中で Claude を待ち、15秒で打ち切って規則だけで答える。母の言葉が規則でニセ警察の筋書きと決まったときは、Claude を待たずにすぐ答え、答えを返す前に家族に知らせる。通知が届かなかったときに、母に解決済みと思わせない。予算が足りない、APNs が家族の全部の端末で失敗した、家族に通知を受けられる端末が無い、のどれかで家族のどの端末にも届かなかった相談では、母への答えを「家族に伝えました」ではなく「家族に届いていません。急ぐなら電話して」にする。1台にでも届けば「家族に伝えました」のままにする。同じ会話の相談で危なさが重くなり、その知らせが届かなかったときも、届いていない側に入れる。届かなかった相談は5分ごとに送り直し、家族があとで端末を登録したときも届く。30分たっても解決しないときの母への知らせも、家族に一度も届いていなければ「家族から返事がまだ」ではなく同じ「家族に届いていません。急ぐなら電話して」にする。2026年11月4日に決めた(#60)。

APNs への送信はデプロイした Workers からなら動く見込み(Workers の fetch は HTTP/2 に直接対応していないが、本番では Cloudflare が HTTP/2 に上げる)。手元の `wrangler dev` では失敗しうるので、デプロイしてから確かめる。

## 精度の測り方

公開されている詐欺の例文(フィッシング対策協議会や警察庁の注意喚起)と、本物の通知(Amazon、ドコモ、銀行)を集めて試験用の一式を作る。「この警告を止めて」のような仕込みの例も入れる。高齢者が狙われやすいスマホまわりの手口として、サポート詐欺の偽警告(電話番号つき)、「容量がいっぱいです」の広告、「3日間無料、その後毎週1,500円」の課金画面、Apple をかたる iCloud 満杯の SMS、使っているアプリの名前をかたる支払い確認のメール、構成プロファイルへ誘う SMS、迷惑なカレンダーの予定、遠隔操作のアプリを入れさせる指示も入れる。何でも危ないと言ってしまう失敗を確かめるため、本物のストレージの警告、iCloud の通知、Apple の領収書、携帯会社の正規のお知らせも入れる。

測る前に、件数、分母、許容する失敗を決めておく。最後に測る組は、経路(SMS、メール、ページ、声の相談、書類の画像)ごとに詐欺15件と本物15件を初期値にし、本物を1段階にするのは0件を目標にする。声の相談は、文字にしたものだけでなく実際に話した声から家族の端末にカードが出るまでの時間も測る。相談は、あいまいな話し方、本物に近い連絡、書類の画像に分けて出す。DNS の銀行の知らせは実機で知らせ漏れと要らない知らせの件数を数える。

例文は直すときに使う組と、最後に1回だけ測る組に分ける。同じ手口の文面違いが両方に混ざらないよう、手口ごとに分ける。最後に測る組は提出の前まで中身を見ない。

規則だけと、規則と Claude の組み合わせを同じ条件で比べる。出すのは、見逃しの件数と率、本物を危ないとした件数と率、家族に送った要らない通知の数、届いてから家族に知らせるまでの時間。数字は README とデモに載せる。母1人の利用で、高齢者全体への効果は言わない。

## 作った過程の残し方

審査の「Claude の活用」は、Claude Code を開発の中心に置いたかを見る。なので、期間中に実際にぶつかった問題ごとに、何が起きたか、Claude Code が何を提案したか、採るかどうか決めた理由、直した結果を記録する。わざと失敗を作って見せることはしない。

家族通知は既存サービスにもあるので、差は「母は話すだけでよく、電話のあとにアプリが声をかけ、ニセ警察の筋書きを見抜いて、家族に何が起きてどうなったかが届く」で示す。同じ試験用の電話の相談を母、妹、作者で試し、母が迷わず話せたか、家族が通知の1行で何が起きたかを分かって電話できたか、話したあと解決を押せたかを記録する。少人数の観察として示し、効果は言い切らない。2026年11月4日までは、通知だけと引き受けありを比べる予定だった。引き受けを外したので、この比べ方はやめた。毎日の笑顔が危ないときの対応につながる、という因果も主張しない。

母に使ってもらって直したことも、少なくとも1件残す。11月3日に FaceTime で設定してから11月7日まで、母が止まったところと、どう直したか、直したあと手助けなしでできたかを記録する。

結果しだいで設計を直す。

### 2026年11月3日に分かったこと

パーソナルボイスは日本語で作れない([Apple の iOS 27 の提供状況](https://www.apple.com/ios/feature-availability/))。家族の返事は文字で送り、母の iPhone の普通の声で読む形に変えた(「スマホ相談と声」の節)。その返事は2026年11月4日に外した(「家族への知らせと解決」の節)。

通話の終わりは、アプリが止まっているあいだは分からない。Apple の DTS の担当者がフォーラムで「It is specifically NOT expected to work while apps are suspended」と答え、止まっているあいだの通話を知る公開の API、拡張、バックグラウンドの仕組みも無いと書いている([Apple Developer Forums](https://developer.apple.com/forums/thread/849682))。アプリが前面にあるとき、バックグラウンドにあるとき、強制終了したときの3通りで実際に何が届くかを、確かめ用のアプリで作者の iPhone 16 に入れて測ることにした。ショートカットの「電話を閉じたとき」のオートメーションが代わりのきっかけになるかも、作者が試すことにした。結果は「2026年11月5日に分かったこと」に書いた。

内部テスターは、App Store Connect のユーザーで、そのアプリを見られる人に限られる([App Store Connect のヘルプ](https://developer.apple.com/help/app-store-connect/test-a-beta-version/add-internal-testers))。母を役割つきのユーザーとして招待する。どの役割なら足りるか、母に何が要るかは、作者が画面で確かめる。

端末の中で日本語を文字にできるかは、Apple に対応言語の一覧が無い。`SFSpeechRecognizer` の `supportsOnDeviceRecognition` は端末ごとに返る値で決まり([Apple](https://developer.apple.com/documentation/speech/sfspeechrecognizer/supportsondevicerecognition))、iOS 26 の `SpeechTranscriber` も `supportedLocales` で確かめる作り([Apple](https://developer.apple.com/documentation/speech/speechtranscriber))なので、確かめ用のアプリで両方を実機で試した。2026年11月3日 22:02〜22:04 に作者の iPhone 16(iOS 27.2)で、同じ日本語の文を3つの方式で文字にした。機内モードで Wi-Fi も切った状態(`NWPathMonitor` が unsatisfied)でも、3つとも文字になり、エラーは出なかった。録音を止めてから最後の文字が出るまでは、`SFSpeechRecognizer`(`requiresOnDeviceRecognition` を true)が0.04秒、`SpeechAnalyzer` と `DictationTranscriber` が0.05秒、`SpeechAnalyzer` と `SpeechTranscriber` が0.22秒だった。`SpeechTranscriber` だけ句読点がほとんど付かなかった。母の相談には、句読点が付き、iOS 26 より前でも動く `SFSpeechRecognizer` を使う。母の iPhone でも同じかは、機種が分かってから確かめる。

Safari の拡張機能、DNS のサーバーが止まったとき、SMS の待ち時間、DNS の外部テストの審査と1日の件数は、裏側のデプロイが要り、M1 の主役には要らないので、それぞれタスク9、8、5、8で確かめる。背面タップはタスク12のスクショの部分で、Managed Agents の応答の速さはタスク11で測る。2026年11月3日に作者と決めた。

### 2026年11月5日に分かったこと

2026年11月5日の朝に、作者の iPhone 16(iOS 27.2)で3回の通話を試した([#25 のコメント](https://github.com/sagochiko/mimamori/issues/25#issuecomment-6645207853))。確かめ用のアプリを前面に開いたままの1回目は、`CXCallObserver` の `callChanged` が `hasConnected=true` のあと23秒で `hasEnded=true` を届け、どちらもアプリが前面(`active`)のときだった。開いてからホームに戻して30秒待った2回目と、アプリの一覧から上にはじいて閉じた3回目は、通話の終わりが届かなかった。止まっていたアプリがあとで前面に戻ったときに遅れて届くかは、ログが消えていて確かめられていない。ショートカットの「電話」が「閉じた」ときのオートメーションは、3回とも動かなかった。電話に出て切る流れでは「電話」のアプリが開いて閉じたことにならないからだと読んでいる(推測)。見立てどおり、通話の終わりが分かるのはアプリが前面にあるときだけだったので、声かけを二段にした(「検知」の節)。

## 提出から外したもの

2026年11月7日の節目([`CONDITIONS.md`](../CONDITIONS.md) の `feature_freeze`)で、次の5つを提出から外した。理由は2つに分かれる。DNS(#11)、朝のアラーム(#17)、週ごとのふり返りと電話番号の一覧(#18)、#20 のうち迷惑なカレンダー、サブスクの見直し、iCloud のサインアウトは、同じ日の終わりにコードを止めるまでに、実機か日にちの経過が無いと動くかを確かめられず、作者の手を借りずに確かめる道も無い。#20 のうち iOS の更新と、Managed Agents の家族への要約と引き継ぎ(#12 の残り)は、裏側の試験やシミュレータで確かめられる。こちらは、コードを止めるまでの時間が足りず、主役の直しと提出の準備を先にしたので外した。どちらも、確かめていないものをデモや README で動くものとして見せないためだ。

案は Claude が [#187](https://github.com/sagochiko/mimamori/issues/187) のコメントに書き、返事が無ければこの案で進めると添えた。作者は寝ていて返事は無かった。作者は同じ日の深夜、寝る前に主の会話で「ねるのでぜんぶやって」「どうするって寝る間にきかないでね」と言っていたので、案のとおりに外した。#187 の案に挙げたのは #11、#17、#18、#20 の4つだけで、#12 の残りは、案のあとで主のセッションが同じ日に足した。Gmail、毎朝の笑顔、Safari は、2026年11月5日の夜の作者の決定どおり外さない(「点数の見立てと伸ばし方」の節)。アプリからの声かけ(#19)のうち空き容量と見守りの自己点検は、シミュレータで確かめられたので入れた(PR #199)。

### DNS(#11)

自前の DoH を `NEDNSSettingsManager` で指し、危ないドメインを止め、1段階の知らせのあとの銀行や遠隔操作のアプリへの接続を家族に知らせる予定だった(「検知」の節)。DNS の設定はシミュレータで確かめられない([`CLAUDE.md`](../CLAUDE.md) の「検証」)。DoH のサーバーが止まったときに iPhone が普通の DNS に戻るのか、ネットにつながらなくなるのかも、実機でしか分からない(#11 の「タスク1から移した確認」)。つながらなくなれば母の iPhone 全体が使えなくなるので、確かめないまま入れない。アプリの DNS の設定、`server/src/doh.ts`、`/dns-query/` の受け口は作っていない。裏側には経路の名前 `dns` を受け付ける型だけが残り、そこへ届く道は無い。

### 朝のアラーム(#17)

笑うと止まる朝のアラーム(AlarmKit)の予定だった。顔トラッキングはシミュレータでは使えず(`ARFaceTrackingConfiguration.isSupported`、[`ios/App/SmileCamera.swift`](../ios/App/SmileCamera.swift))、朝に鳴って笑顔で止まるかは、実機で次の朝を待たないと確かめられない。アラームの設定と止める画面は作っていない。笑顔を撮って家族に送る部分(#14)は、アラームとは別に、家族の誰でもいつでも撮れる形で入っている。アプリの最低の版は、AlarmKit のために iOS 26.0 にしたまま変えていない([`ios/project.yml`](../ios/project.yml))。

### 週ごとのふり返りと電話番号の一覧(#18)

ふり返りは、Managed Agents の定期実行で1週間の知らせをまとめ、家族に送る予定だった。1週間分の知らせがたまり、定期実行が回るのを待たないと、中身を確かめられない。電話番号の一覧は、詐欺に使われた番号からの着信に「詐欺の疑い」と出すもので、着信の表示は実機でしか確かめられない。Call Directory の拡張は中身の無い作りのままアプリに入っていて([`ios/CallDirectory/CallDirectoryHandler.swift`](../ios/CallDirectory/CallDirectoryHandler.swift))、番号を1つも登録しないので、着信には何も出ない。

### iOS の更新などの声かけ(#20)

iOS の更新、迷惑なカレンダーの予定、月に1回のサブスクの見直し、iCloud のサインアウトの4つの点検の予定だった(「アプリからの声かけ」の節)。迷惑なカレンダーを購読した端末、1か月の経過、iCloud からのサインアウトは、実機か日にちの経過が要る。購読カレンダーをアプリから消せるかも公式に書かれておらず、実機で確かめる予定だった。iOS の更新は、古い版のシミュレータ(iOS 26.5 の母役の端末)と裏側の試験で確かめられるが、コードを止めるまでの時間が足りず、主役の直しと提出の準備を先にした。最新の iOS の版を取る `server/src/osversion.ts` と `GET /os/latest` は作っていない。

### Managed Agents の家族への要約と引き継ぎ(#12 の残り)

相談1件に1つセッションを立て、家族への要約を作らせる予定だった(「家族への知らせと解決」の節)。作ったのは、SMS、メール、ページの知らせのあとの裏の調べものだけだ。家族への要約は裏側で閉じるので、Vitest と本物の API で確かめられる。外したのは、コードを止めるまでの時間が足りず、主役の直しと提出の準備を先にしたからだ。2026年11月7日の時点で、本番の D1 には調べもののセッションが付いた知らせがまだ1件も無く、本物の API が根拠を書いたことも無い(README の「Built, not yet tried on a real iPhone」)ので、1つ目の使い方の確かめを先にした。#12 の、最小のセッションで `session.status_idle` までの時間を測る確かめもしていない。

### デモから届かないこと

2026年11月7日に `ios/App`、拡張機能、`server/src` を、テストを除いて grep で調べた。`NEDNSSettingsManager`、`import AlarmKit`、`EKEventStore`、`ubiquityIdentityToken`、`startCaseSession`、`osversion`、`os/latest` は0件だった。`dns-query` は [`server/src/auth.ts`](../server/src/auth.ts) のコメントの1件だけで、[`server/src/index.ts`](../server/src/index.ts) の受け口の一覧に DNS の道は無い。[`ios/App/Views`](../ios/App/Views) の `Button`、`Label`、`Text` の文字を grep で全部見たが、外したものへの入口は無かった。設定アプリに出るみまもりの欄([`ios/App/Settings.bundle/Root.plist`](../ios/App/Settings.bundle/Root.plist))も、毎日の声かけ、その時刻、読み上げだけだ。体験モード([`ios/App/Views/DemoView.swift`](../ios/App/Views/DemoView.swift))が見せるのは、ニセ警察の相談、家族のカード、SMS の判定だけだ。Call Directory の拡張だけは、アプリからではなく iPhone の設定の電話の欄に名前が出うるが、オンにしても何も登録しない。README の「Not built yet」と、[`README.ja.md`](../README.ja.md) の「まだ作っていないもの」にも、同じ5つを作っていないと書いてある。
