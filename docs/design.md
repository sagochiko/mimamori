# 設計

2026年11月1日に、キックオフ前の構想の検討として決めた設計。主催者の FAQ に従ってキックオフ前はリポジトリの外に置き、開発スタート後の2026年11月3日にこのリポジトリへ写した(運営はキックオフで、事前に作った仕様文書や構想は使ってよいと説明している)。写すときに、家族の個人的な情報を伏せ、作者の手元にしかないファイルへのリンクを外した。コードはすべて開発スタート後に書く。

前提は応募時の構想と、主催者が示したテーマ、ルール、審査基準。実装の順番とつなぎ目は [`plan.md`](plan.md) にある。

## 何を作るか

離れて住む母の iPhone を、母が何もしなくても詐欺から守り、スマホの困りごとには声で答え、毎朝の笑顔で家族とつなぐ iOS アプリ。家族(作者、妹など)は同じアプリで母の笑顔を受け取り、危ない知らせや答えきれない相談を引き受ける。

## 作品の筋

「毎日つながっている家族だから、母が気づけないときに、家族が代わりに気づいて引き受けられる」。機能は全部作るが、デモと説明はこの1本の筋で通す。主役は一番被害の大きいニセ警察詐欺の場面。長い電話が終わるとアプリが「さっきの電話、大丈夫だった？」と母に聞き、母がそのまま「警察から電話があった」と話すだけで、AI が筋書きを見抜いて電話を切るよう伝え、家族に知らせが届く。家族が引き受けると母の画面が切り替わる。そのあと母の iPhone が銀行のサイトにつながれば、母が何もしなくても家族に知らせる。SMS の自動検知は2つ目の場面にし、毎朝の笑顔は「毎日つながっている」を見せる脇役にする。

テーマは2つ目の「本来、誰にでも届くべきものを」で出す。詳しい家族が近くにいる人だけが詐欺から守られている、という壁を取り払う。作者の本業はこの題材と遠いので、1つ目の「あなたにしかない深さ」では戦わない。

警察庁の確定値では、2025年の特殊詐欺の被害額は1,423.1億円で過去最悪だった。そのうちニセ警察詐欺が1,005.0億円で、特殊詐欺の被害額の70.6%を占める([警察庁 確定値](https://www.npa.go.jp/bureau/safetylife/sos47/new-topics/260605/01.html))。「約7割」と言うときの分母は特殊詐欺の被害額で、件数や SNS 型詐欺を含む総額ではない。確定値には2026年7月2日付の訂正が出ているので、提出前に訂正版で数字を確かめ直す。手口は、電話で「口座が犯罪に使われている」と告げ、SNS のビデオ通話でニセの逮捕状を見せ、インターネットバンキングで送金させるものが目立つ([警察庁 2025年3月末の資料](https://www.npa.go.jp/bureau/safetylife/sos47/new-topics/250428/02.html))。電話と LINE はアプリから自動で見られないので、母がやることを「ボタンを押して話す」1つにし、そのあとの銀行への接続は自動で見る。

この筋は2026年11月1日に審査員の立場から見直して決めた。全部の機能が同じ重さで並ぶと、高齢の親向けの便利アプリに見え、上位6には届きにくい。削る案も出たが、検知だけでは既存サービスと差が付かないので、作る範囲は変えず筋を絞った。

提出に必須なのは、通話のあとの声かけ、声の相談、家族の引き受け、母への返事、その実測の結果。これがそろうまで、ほかの機能(Gmail、Safari、朝のアラーム、週ごとのふり返り、電話番号の一覧)には進まない。ほかの機能は間に合わなければ提出から外す。

## 点数の見立てと伸ばし方

2026年11月3日に、審査員の役のサブエージェント(Claude Opus 5.5)に、この設計と実装計画、開発のハーネスを読ませ、審査の4基準で採点させた。動くもの、デモ動画、母の利用の記録が無い段階での点だ。上位6に残れるかの見込みも聞いた。

| 時点 | インパクト(30%) | デモ(25%) | Claude の活用(25%) | 深さと実行力(20%) | 合計 | 上位6の見込み |
|---|---:|---:|---:|---:|---:|---|
| 2026年11月3日、設計、計画、ハーネスだけ | 7.5 | 7 | 7.5 | 6.5 | 71.75 | 中くらい |

採点役は、11月4日のうちに母の iPhone へ届かなければ見込みは「低い」に下がると見ていた。採点役が一番自信がないと答えたのは Claude の活用の点だった。ハーネスは動画にほとんど映らないので、作品の中の使い方だけで見られれば6点台、リポジトリまで読まれれば8点台になりうる、とのことだった。

満点にならない理由として、採点役は次の3つを挙げた。

1. 動くものがまだ無い。動画、実測、母の記録が無く、計画より1日遅れている。デモと深さはここで頭打ちになる
2. 題材から来る天井がある。主役の場面では、犯人に「誰にも話すな」と言われた母が、通話のあとの声かけに答えて話す必要がある。一番大事な場面で「母が何もしなくても」が成り立たない。電話と LINE の中身を見られないのは iPhone の制限で、誰が作っても同じ
3. 作る範囲が1人で6日には広い。拡張機能4つ、Gmail、DNS、アラーム、Managed Agents の3か所が、主役の厚みと時間を削っている

採点役は、周りの機能(Gmail、Safari、電話番号の一覧、週ごとのふり返り、朝のアラーム)を今のうちに外し、Managed Agents を1か所に減らす案も出した。2026年11月3日に作者は、外さずに全部作ると決めた。順番は「主役がそろうまで周りに進まない」条件で守り、外すかどうかは11月7日 12:00 の節目で改めて決める。

審査は相対評価で、250チームから上位6チームを選ぶ。満点かどうかより、他より記憶に残るかで決まるので、満点ではなく上位6を狙う。

題材にははっきりした強さもある。被害額は過去最悪で社会的なインパクトが大きく、過去の受賞作に高齢者や詐欺対策のものは無く題材が空いている。母という本物の使い手がいて、11月8日には直接撮れる。なので題材は変えず、記録で勝負する。

ここから点を伸ばすのは、機能を足すことではなく次の3つだ。どれも母へ渡してから11月7日までに取れるので、主役を早く仕上げて母に渡せるかで点が一番大きく変わる。

- 母が誘導なしで相談できた場面を、実際に撮れること
- 最後に1回だけ測る組で、規則だけより Claude 込みのほうが良いと数字で示せること
- 通知だけより、家族が引き受ける形のほうが、母が迷わなかったと示せること

## この形に決めた理由

応募の案は「母が怪しいと思ったら LINE に転送する」ものだった。でも、怪しいと思えないから詐欺に引っかかる。気づいた人しか守れない作りでは、一番守りたい場面が抜ける。そこで、詐欺のほうは母が何もしなくても気づける仕組みにした。

iPhone では他のアプリが SMS やメールを読めない。母が何もしなくても見られる範囲は、Web より iOS アプリのほうがずっと広い。

| 届く経路 | iOS アプリなら | Web なら |
|---|---|---|
| SMS | 知らない相手からのものは見られる | 見られない |
| メール(Gmail) | サーバーが読める | サーバーが読める |
| 怪しいサイト、広告 | DNS と Safari の拡張機能で見られる見込み | 見られない |
| 電話 | 登録した番号に警告を出せる程度 | 見られない |
| LINE | 見られない | 見られない |

既存の詐欺対策(ドコモの詐欺対策プラス、トレンドマイクロの詐欺バスター)は、母がスクショを送るか、検知の通知を家族に送るところまでだ。母が気づかなくても見る仕組み、スマホ相談、家族への引き継ぎ、毎日のつながりを1つにしたものは見つからなかった。守るだけのアプリは何も起きない日に開かれないので、毎朝の笑顔で母が毎日開く場所にする。

過去の受賞作(Built with Opus 4.7 と 4.6)では、現場の本人が作ったもの、役割を分けたエージェント、精度を数字で示したものが上位だった。モバイルアプリと chat bot の入賞は無い。iOS アプリにしたのは、母を守る範囲を優先したから。

## 決まったこと

- 題材は母の案。スマホ相談と詐欺対策は同じ重さで、検知、引き継ぎ、スマホ相談の3つとも作り込む
- 期間中に母に実際に使ってもらい、デモにもやり取りを映してよい(個人情報は伏せる)
- iOS アプリで作る。配るのは TestFlight
- 母の iPhone の初回設定は FaceTime で案内する。デモの母の場面は、提出日の11月8日に直接撮る
- 家族は何人でも招待できる。妹も入れる
- 母は声で話しかけられる
- 裏側は Cloudflare Workers の無料プラン
- Managed Agents は、怪しいものの裏の調べもの、家族への引き継ぎ、週ごとのふり返りの3か所で使う
- 実機で確かめていないことは、キックオフ後の初日に試す

## 全体像

iPhone のアプリは1つで、最初に「見守られる人」か「家族」かを選ぶ。家族の誰かが招待のコードを出し、母や他の家族がそれを入れるとつながる。

母の iPhone に入れるもの。

- SMS を仕分ける拡張(IdentityLookup の Message Filter)
- DNS の設定(NEDNSSettingsManager で自前の DoH を指す)
- Safari の拡張機能(開いたページに警告を重ねる)
- 共有の受け口(スクショやメールの文面を渡す)と、背面タップのショートカット
- 笑顔で止めるアラーム(AlarmKit と ARKit の顔トラッキング)
- 詐欺に使われた番号の一覧(CallKit の Call Directory)

Cloudflare Workers が受け持つもの。

- SMS の問い合わせ先。Apple から送り主と本文が届き、決まった規則で即答する
- DNS(DoH、RFC 8484)。上流は 1.1.1.1。危ないドメインを止めて記録する
- ページの判定。Safari の拡張機能からの問い合わせに答える
- 相談の受け口と、相談と引き継ぎの記録(D1 を正にする)
- Gmail の見張り。Cron Trigger で5分ごと
- iPhone への通知(APNs)

Claude の使い分け。

- Haiku 5.5(`claude-haiku-5-5`)は、即答のあとに重ねる判定と理由づけ
- Sonnet 5.5(`claude-sonnet-5-5`)は、母との会話とスクショの読み取り(押す場所の座標)
- Managed Agents は、急がない作業。即答と母との会話の1往復には使わない(応答の速さの目安が公式に無く、セッションの記録は削除するまで残るため)

## 母の画面

開くと、家族から届いた笑顔とひと言が並び、その下に大きなマイクのボタンが1つある。押して話すか、スクショを送る。最近の知らせも同じ画面に出て、止めたものと気をつけるものが短い言葉で並ぶ。画面の説明文は置かず、読み上げ(VoiceOver)には残す。

危ないものが届いたときは、通知と画面の両方で「開かないで」と出す。「家族に伝えました」も同じ画面に出し、何を伝えたかを母が見られるようにする。

## 家族の画面

毎朝、母の笑顔が届く。家族は自分の笑顔かひと言で返す。家族同士の笑顔も見える。

知らせはカードで家族全員に届く。カードには危なさの段階、何が届いたかの要約、AI が母に何と答えたか、裏の調べもので分かった根拠が載る。ボタンは「引き受ける」「母に返事する」「電話する」「解決」。最初に「引き受ける」を押した人が受け持ち、ほかの家族には「(名前)が対応中」のように出る。「母に返事する」を押したあとに書いた1通だけが母に届き、母の画面には「(名前)から」のように名前が出る。週に一度、何が届いて何を止めたかのふり返りが届く。

## 毎朝の笑顔

母の朝のアラームはカメラに向かって笑うと止まる。止めたときの笑顔が家族に届き、家族から返ってきた笑顔やひと言が母の画面に並ぶ。決まった時間までに笑顔が届かなければ、家族にそっと知らせる。毎朝の安否確認を兼ねる。

笑顔の判定は iPhone の中だけで行い、判定のコードも含めて期間中に一から書く。

## 検知

危なさは3段階にする。

1. 開かないで
2. 家族に確かめるまで待って
3. 心配は少ないけど、お金や暗証番号を聞かれたら止めて

「安全です」とは決して言わない。判定には理由を短く添える(送り主のドメインが公式と違う、急がせる言い回しがある、など)。

SMS は知らない相手からのものを Apple 経由で受け、決まった規則で即答する。規則ではっきり危ないものだけを迷惑フォルダに回し、迷うものは通常どおり届けたうえで、Claude の判断を母と家族に知らせる。本物の SMS(認証コードなど)を見落とさせないため。

サーバーには誰の iPhone からの問い合わせか分からない(Apple が送る JSON に端末や利用者を識別する項目が無い)。なので、母に配るビルドは問い合わせ先の URL に家族の印を入れる。審査員向けのビルドは体験モードにし、家族に届くはずのカードを同じ iPhone の中で並べて見せる。体験モードは主役の電話の相談から始め、家族が引き受ける場合と誰も応じない場合の両方を試せるようにする。SMS の判定はそのあとに試せるようにする。家族まで届くという一番の差を、審査員が1台で体験できるようにするため。

対象は連絡先に無い相手からの SMS だけで、iMessage は見られない。

Gmail では5分ごとに母の受信箱の新しいメールを読む。`gmail.readonly` を Google の審査なしで使える「テスト」の状態で使い、母をテストユーザーにする。読むだけで、母の Gmail には手を加えない。母の許可は7日で切れるので、11月2日以降にもらい、切れる前に取り直す。許可の画面には「未確認のアプリ」と出るので、FaceTime で案内する。

サイトは2段構え。DNS では、母の iPhone が行こうとしたドメインを見て、危ないものは止めて記録する。Safari の拡張機能は開いたページの中身まで見て、ページの上に警告を出す(全サイトでの許可を初回に設定する)。Safari 以外のブラウザやアプリ内のブラウザでは、拡張機能が動かず DNS だけになる。

ニセ警察詐欺は通話のあとの声かけを相談のきっかけにし、3段構えで受ける。声かけでは、アプリが通話の始まりと終わりを CXCallObserver で知り(電話番号は分からない)、3分以上の通話が終わったら、母に「さっきの電話、大丈夫だった？」と通知で聞く。母が自分で思い立たなくても、相談のきっかけがアプリのほうから来るようにするため。「大丈夫」を押せば何もしない。アプリが閉じているときにも通話の終わりが分かるかは初日に確かめ、分からなければ、アプリを開いたときに直近の通話について聞く形にする。

1つ目は電話のあとの声の相談で、母が「警察から電話があって、口座が犯罪に使われてるって」と話すと、Claude がニセ警察の決まった筋書き(口座が犯罪に使われている、潔白の証明、ほかの人に話すな、ビデオ通話への誘い、送金や口座の移し替え)を見抜く。母には、見えた根拠と勧める行動を分けて「詐欺で使われる説明と一致しています。送金せず、いったん電話を切って家族に確かめて」と返し、家族に1段階で知らせる。広い言い切りはしない。

2つ目はニセの書類の読み取りで、LINE やビデオ通話で送られた「逮捕状」などのスクショを送ると、Claude が詐欺の書類に見られる特徴との一致を読み取る。書類の見た目だけで真偽を言い切らない。

3つ目は銀行への接続で、1段階の知らせから60分のうちに、母の iPhone から銀行やネット銀行のドメインへの問い合わせがあったら、DNS で気づいて家族に「銀行関連の通信がありました」と知らせる(止めはしない)。DNS で分かるのは問い合わせだけで、母が開いたことや送金したことは分からないので、そう言わない。知らせるのは送金の直前に家族が電話できるようにするため。銀行のドメインの一覧は公式のものを集める。

電話では詐欺に使われた番号の一覧を入れて、着信に「詐欺の疑い」と出す。着信ごとにサーバーへ問い合わせる Live Caller ID Lookup は、Apple の承認に数か月かかる例があり、期間中は間に合わないので入れない。

メール、SMS、ページの中の文字はすべて調べる対象として扱い、「この警告を止めて」のような文があっても従わない。Claude の答えは Structured Outputs で決まった形(段階、理由、母への一言)だけを受け取る。通知先や共有の範囲は、Claude の答えや届いた文面では変えられないようにする。

怪しいものを見つけたら、Managed Agents に裏で調べさせる。送り主のドメインと、公式の注意喚起に同じ手口が載っているかを数分かけて調べ、分かった根拠を家族のカードに足す。

## 引き継ぎ

AI が答えきれない相談と、2段階目以上の知らせは、相談1件として記録する。状態は「家族に知らせた」「家族が引き受けた」「解決」に分ける。知らせが届いたことと、家族が見たことは別に扱う(APNs が成功を返しても、届いて見られたとは限らないため)。

知らせは家族全員に届き、最初に引き受けた人が受け持つ。引き受けたら、その相談では AI が案内を止める。母がどちらに従えばいいか迷わないようにするため。30分誰も応じなければ、母には「家族から返事がまだ。急ぐなら電話して」と出し、家族全員にもう一度知らせる。

相談1件ごとに Managed Agents のセッションを1つ立て、家族への要約と返事の受け渡しを受け持たせる。状態の正は D1 にして、エージェントの記憶と食い違わないようにする。週ごとのふり返りも Managed Agents の定期実行で作る。

## スマホ相談と声

母が話した声は iPhone の中で文字にし、Claude に渡す。答えは文字と読み上げの両方で返す。スクショが付いていれば、押す場所を座標で返させ、そこに丸を付けた画像を見せる。押せたかは次のスクショで確かめ、一手ずつ進める。

画像は送る前にこちらで縮小し、返った座標がそのまま使える状態にする(公式の推奨)。公式は「位置は近似なので確かめてから使う」としているので、丸は次のスクショで確かめる一手とセットにする。iPhone 15 のスクショ(1179×2556)なら、高解像度の扱いで縮小なしに読める。

送金、認証コードの共有、構成プロファイルの導入、データの削除は案内しない。その場合は家族に回す。

家族本人が書いた返事は、その人の声で母に届ける。家族の iPhone のパーソナルボイス(端末の中で作る本人そっくりの声)で返事を音声にし、母の iPhone で再生する。AI の答えは普通の読み上げの声のままにする。AI の答えまで家族の声にすると、母が「家族の声なら信じていい」と覚え、家族の声を真似る詐欺にかかりやすくなるため。パーソナルボイスで音声ファイルに書き出せるかは初日に確かめ、できなければ家族の返事も普通の声にする。

## データの扱い

- 笑顔の写真は家族の間だけで共有し、Claude にも Managed Agents にも渡さない
- スクショはその場で処理して残さない。残すのは要約と危なさの段階だけ
- Managed Agents に渡すのは怪しいメッセージの中身だけで、母との会話は渡さない
- 鍵(Claude、APNs、Google)は Workers の秘密の置き場に置き、公開リポジトリには入れない
- リポジトリに実際の相談やメールは入れず、試験用の例文だけを置く

残す期間は30日。知らせ、相談、笑顔の写真は30日たったら自動で消す。家族を抜けた人の端末の鍵はその場で無効にし、以後は何も見られない。母か家族の誰かが「すべて消す」を押すと、その家族のデータを裏側からすべて消し、Gmail の許可を取り消し、Managed Agents のセッションも削除する。

知らせが多すぎると家族が反応しなくなる。家族に通知を送るのは1段階と2段階の知らせと、引き継ぎの相談だけにする。3段階はアプリの中に並べるだけで、通知は送らない。同じ送り主やドメインの知らせは、1時間に1回にまとめる。

母には使い始めに「家族に伝えることがある。伝えたら必ずあなたにも言う」と一度示す。使うことへの同意と、動画に映すことへの同意は分けてもらい、公開前に映す範囲を母と確かめる。

## 失敗したとき

一番怖いのは DNS が止まって母の iPhone がネットにつながらなくなることだ。Workers の無料プランは1日10万リクエストまでで、1回の処理の CPU 時間は10ミリ秒。上限に近づいたら家族に知らせる。DNS のサーバーにつながらないときに iPhone が普通の DNS に戻るかは初日に確かめ、戻らないなら有料プランにするか DNS を外す。

Claude の呼び出しが失敗したり遅れたりしたときは、決まった規則の判定だけで知らせ、母には「確かめ中」と出す。数十秒かかる処理は、Workers の waitUntil(レスポンス後30秒まで)では足りないので Queues に回す。通知が届かなかったときに、母に解決済みと思わせない。

APNs への送信はデプロイした Workers からなら動く見込み(Workers の fetch は HTTP/2 に直接対応していないが、本番では Cloudflare が HTTP/2 に上げる)。手元の `wrangler dev` では失敗しうるので、デプロイしてから確かめる。

## 精度の測り方

公開されている詐欺の例文(フィッシング対策協議会や警察庁の注意喚起)と、本物の通知(Amazon、ドコモ、銀行)を集めて試験用の一式を作る。「この警告を止めて」のような仕込みの例も入れる。

測る前に、件数、分母、許容する失敗を決めておく。最後に測る組は、経路(SMS、メール、ページ、声の相談、書類の画像)ごとに詐欺15件と本物15件を初期値にし、本物を1段階にするのは0件を目標にする。声の相談は、文字にしたものだけでなく実際に話した声から家族の端末にカードが出るまでの時間も測る。相談は、あいまいな話し方、本物に近い連絡、書類の画像に分けて出す。DNS の銀行の知らせは実機で知らせ漏れと要らない知らせの件数を数える。

例文は直すときに使う組と、最後に1回だけ測る組に分ける。同じ手口の文面違いが両方に混ざらないよう、手口ごとに分ける。最後に測る組は提出の前まで中身を見ない。

規則だけと、規則と Claude の組み合わせを同じ条件で比べる。出すのは、見逃しの件数と率、本物を危ないとした件数と率、家族に送った要らない通知の数、届いてから家族に知らせるまでの時間。数字は README とデモに載せる。母1人の利用で、高齢者全体への効果は言わない。

## 作った過程の残し方

審査の「Claude の活用」は、Claude Code を開発の中心に置いたかを見る。なので、期間中に実際にぶつかった問題ごとに、何が起きたか、Claude Code が何を提案したか、採るかどうか決めた理由、直した結果を記録する。わざと失敗を作って見せることはしない。

家族通知は既存サービスにもあるので、差は「引き受けがあることで、母の迷いと家族の対応漏れが減るか」で示す。同じ試験用の電話の相談で「家族に通知が届くだけ」と「誰が対応中かと返事が母にも見える」を母、妹、作者で試し、母が誰の返事を待てばいいか分かったか、家族が二重に動いたり誰も動かなかったりしなかったかを記録する。少人数の観察として示し、効果は言い切らない。毎日の笑顔が危ないときの対応につながる、という因果も主張しない。

母に使ってもらって直したことも、少なくとも1件残す。11月3日に FaceTime で設定してから11月7日まで、母が止まったところと、どう直したか、直したあと手助けなしでできたかを記録する。

## デモの流れ(3分)

母の iPhone と家族の iPhone を並べて撮る。母の場面は提出日の11月8日の午前から昼に直接撮る。撮れなかった場面は、期間中の FaceTime の画面か、母に撮ってもらった画面で補う。

| 時間 | 場面 |
|---|---|
| 0〜15秒 | 「2025年の特殊詐欺の被害額の約7割がニセ警察詐欺」という数字(出典つき)と、母の困りごとを母本人の言葉で |
| 15〜60秒 | 試験用のニセ警察の電話が終わると、アプリが「さっきの電話、大丈夫だった？」と聞き、母がそのまま話す。AI が筋書きを見抜いて「電話を切って」と返し、家族に知らせが届く |
| 60〜85秒 | 妹が「引き受ける」を押すと、母の画面に「家族が見ています」と出て AI の案内が止まり、妹の声で返事が届く。母が銀行のサイトを開くと、家族に知らせが届く |
| 85〜110秒 | 母が何もしていないのに、詐欺の SMS で家族にカードが届く。本文の「家族には知らせないで」に従わず、逆に危なさを上げる |
| 110〜125秒 | 毎朝の笑顔が家族に届き、家族が返す |
| 125〜150秒 | 最後に測る組での数字(規則だけと Claude 込みの比較)と、母の利用から直した1点、通知だけと引き受けありの比較 |
| 150〜180秒 | Claude Code での開発の記録と、守れる範囲の限界(電話と LINE の中身は見られず、母が話す必要がある) |

試験用の SMS と実際の相談は区別して見せる。母が本物の詐欺に遭うことをデモの条件にしない。

最終日(11月8日)は動画づくりに残す。

## 初日に実機で確かめること

結果しだいで設計を直す。

- Safari の拡張機能が全サイトでページを読み、サーバーに問い合わせられるか
- 背面タップで撮った画面を、そのまま送れるか
- DNS のサーバーにつながらないとき、iPhone がどうなるか
- SMS の問い合わせに、Apple がどれだけ返事を待つか
- 日本語の声を、iPhone の中だけで文字にできるか
- DNS を設定するアプリが、TestFlight の外部テストの審査で何を問われるか
- Managed Agents の応答の速さ(最小のセッションで測る)
- Workers で受ける DNS が、母1人で1日何件になるか

## 確かめたこと(出典)

- SMS の拡張は [SMS and MMS Message Filtering](https://developer.apple.com/documentation/identitylookup/sms-and-mms-message-filtering) と [deferQueryRequestToNetwork](https://developer.apple.com/documentation/identitylookup/ilmessagefilterextensioncontext/deferqueryrequesttonetwork(completion:))
- Live Caller ID Lookup の承認待ちの例は [Apple Developer Forums](https://developer.apple.com/forums/thread/775877)
- DNS の設定は [NEDNSSettingsManager](https://developer.apple.com/documentation/networkextension/nednssettingsmanager)。NEDNSProxyProvider は監視対象の端末でしか使えない([Apple Developer Forums](https://developer.apple.com/forums/thread/820849))
- Safari の拡張機能の許可は [Managing Safari web extension permissions](https://developer.apple.com/documentation/safariservices/managing-safari-web-extension-permissions)
- Gmail のテストの状態の制限は [Google Cloud のヘルプ](https://support.google.com/cloud/answer/15549945) と [OAuth 2.0](https://developers.google.com/identity/protocols/oauth2)
- Managed Agents は [概要](https://platform.claude.com/docs/ja/managed-agents/overview)。料金は [料金のページ](https://platform.claude.com/docs/ja/about-claude/pricing)
- 座標は [vision-coordinates](https://platform.claude.com/docs/ja/build-with-claude/vision-coordinates)
- Workers の制限は [Limits](https://developers.cloudflare.com/workers/platform/limits/)。HTTP/2 の件は [workerd の issue 4841](https://github.com/cloudflare/workerd/issues/4841)
