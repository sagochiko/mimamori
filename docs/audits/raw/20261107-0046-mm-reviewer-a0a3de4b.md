## 指摘

### 1. 画像だけの相談では、送金やリンクや認証コードの画面の案内が、裏側の壁を通らずに母へ返る(重い、確度は高い)

`server/src/consult-judge.ts` の `decidePlan`(行 857 から 943)は、案内しない話題(`SENSITIVE`)とメッセージや電話の話(`CONTACT`)を、どちらも母の言葉(`topicWords(said)`)だけで見分けている。共有の拡張は `text` を付けずに送る(`ios/ShareExtension/ShareViewController.swift` の `client.consult(image:)`、`APIClient.consult(image:text: = "")`)。そのため画像だけの相談では、どちらの見分けも空の文字列を見ることになり、効かない。Claude の `action` を `SENSITIVE` で確かめる `guided`(行 862 から 866)も、前の言葉に案内しない話題があるとき(`askedEarlier`)に限られている。

結果として、Claude が `kind: "help"`、`level: 3`、`handoff: false` と答えれば、どんな画面でも行 942 から 943 に落ちる。`action` がそのまま読み上げの答えになり、`tap` の丸が付き、`toFamily: false` で `record: false` になる。純粋な関数の `judgeConsult` を `tsx` で直接呼んで確かめた。

```text
{"t":"","level":3,"toFamily":false,"record":false,"reply":"画面の「送金する」を押して金額を入れて","tap":{"x":10,"y":10}}
{"t":"","level":3,"toFamily":false,"record":false,"reply":"このメッセージのリンクを押して、ログインして","tap":{"x":10,"y":10}}
{"t":"","level":3,"toFamily":false,"record":false,"reply":"届いた認証コードを相手に伝えてください","tap":{"x":10,"y":10}}
```

具体的な場面は2つある。1つ目は、SMS や LINE の詐欺のスクショを Claude が操作の相談と読んだ場合で、「リンクを押して」が丸付きで母に出て、家族には何も届かず、記録も残らない。2つ目は、ネットバンキングの振込画面や認証コードの画面の場合で、`docs/plan.md` タスク12の「送金、認証コード、構成プロファイル、データの削除に関わる相談は、案内せず `handoff: true` にして相談を開く」が、Claude のプロンプトの1文(`IMAGE_NOTE` の「詐欺かもしれない画面のときは tap を空」と既存の段落)だけに任されている。文字の相談では言葉の規則が決まった形で止めていたので、画像の経路だけ壁が1枚減ったことになる。`docs/design.md` 行 209 の「案内しない話題…とメッセージや電話の話かどうかは、今の言葉で決める」は、言葉がある前提で書かれている。画像だけの相談で何を見るかは、設計にも計画にも書かれていない。

直し方の案は、画像があるときは `SENSITIVE` と `CONTACT` を Claude の書いた文(`action`、`reasons`、`topic`)にも、`askedEarlier` を問わず当てることだ。当たれば、`SENSITIVE` は家族に回し、`CONTACT` は今の行 934 と同じ決まった3段階の1行にして丸を付けない。もっと固くするなら、画像だけの相談の `help` の答えは常に `record: true` にして、家族が後から見られるようにする手もある。どちらにするかは設計の判断なので、`docs/design.md` に1文足すのがよい。

### 2. 画像に「これ何」が付き、Claude が `handoff: true` と答えると、家族に回らず聞き返しになる(中くらい、確度は高い)

`POST /consult` の約束では `text` と `image` を一緒に送れる(`docs/plan.md` の表)。「これ何」「これどうするの」は `pointsBack` が真になり、共有からは `history` が付かないので、`pointsAtNothing(said)` も真になる。すると行 881 から 889 の条件(`claude.handoff || claude.kind === "scam"`、`level === 3`、`rule.level === null`)に当たり、画像を見て Claude が「家族の手が要る」と返しても `ASK_AGAIN_REPLY` になり、家族に回らない。画像はあるので「何のことか、もう一度くわしく教えて」は筋も違う。

```text
{"t":"これ何","level":3,"toFamily":false,"record":false,"reply":"何のことか、もう一度くわしく教えて"}
{"t":"これどうするの","level":3,"toFamily":false,"record":false,"reply":"何のことか、もう一度くわしく教えて"}
```

今の共有の拡張は `text` を送らないので、今日の利用者の経路には出ない。ただ、計画の次の手順(母の画面からスクショを送り、声で添える)ではそのまま踏む。直し方は、画像があるときは `pointsAtNothing` の聞き返しを飛ばすことだ。画像が「指す先」になっている。テストには、`text` 付きで Claude が `{}` を返す例(`takes her words with the image`)しかなく、この形は試されていない。

### 3. base64 の文字の検査だけで、無料プランの CPU の10ミリ秒をほぼ使い切る(中くらい、確度は中くらい)

`server/src/consult.ts` の `parseImage` は、300万字までの `data` 全体に `BASE64 = /^[A-Za-z0-9+/]+={0,2}$/` を当てている。手元の Node で、300万字の base64 を測った結果は次のとおり。

```text
parse 1.1 regex 9.5 stringify 1.8
parse 1.4 regex 9.5 stringify 1.7
```

正規表現だけで約9.5ミリ秒かかる。`JSON.parse`、Claude に送る `JSON.stringify`、`request.text()` を足すと、上限近くの画像では `.claude/rules/server.md` の「1回の CPU 時間10ミリ秒」を超えうる。Workers の実機の CPU では測っていないので、確度は中くらいとした。JPEG の q0.85 のふつうのスクショなら、50万から130万字ほどで済む見込みだ。直し方の案は、正規表現の検査をやめるか、先頭と末尾の数百字だけにすることだ。壊れた base64 は Anthropic 側が400で返し、`requestClaudeConsult` は null から「答えきれない」へ倒れる。上限を下げる手もある。

### 4. テストが上の経路を試していない(中くらい、確度は高い)

`server/test/consult-image.test.ts` の偽の Claude は、設定画面の `help`、逮捕状の `scam`、Claude が自分で印を付けた注入の3種類だけだ。足りないのは、画像だけで Claude が `help` と答え、`action` が送金、リンク、認証コード、構成プロファイルに触れる場合(指摘1)と、画像に「これ何」を付けて `handoff: true` が返る場合(指摘2)だ。注入のテストは、Claude が `injection_suspected: true` を返した場合しかない。画像の中の「家族に知らせないで」に Claude が従い、印も付けずに `help` で返す場合の振る舞いは、指摘1の直し方で決まるので、その形も1件足すべきだ。

## 確かめて問題なかったこと

- 文字だけの相談の経路は前と同じだった。`buildConsultRequest` は画像が無ければ文字列の `content`、`CONSULT_SCHEMA`、`tap` の無い `required`、前と同じシステムプロンプトを返す。テスト `asks a text-only consultation as before` と、既存の `server/test/consult.test.ts` を含む571件が通った(`npx vitest run test/consult-image.test.ts test/consult.test.ts`)。`consultRoute` も、`text` が無ければ今までどおり400 `consult_text_invalid` になる。
- 画像はどこにも残らない。`alerts` と `cases` に `data` が入らないことをテストが全列で見ている。`console.` の出力は `index.ts` の `error.name` だけで、本文も画像も出さない。`recordAiReply` と `openCase` には画像を渡していない。
- 注入で段階が下がらない。Claude が `injection_suspected` を返せば `decide()` が1段重くし、`steered` によって Claude の `topic` と `reasons` はカードに載らない。知らせる先は `openCase` が家族の表から決め、Claude の答えは使わない。画像の中の文字は `IMAGE_NOTE` でデータとして扱うよう書かれ、画像の大きさの行は `<untrusted>` の外にある。
- 警告や家族に回す答えには `tap` が付かない。`tap` は行 942 の Claude の案内の経路だけで付き、裏側の `tapOn` が画像の外を捨てる。逮捕状の答えは `MATCH`/`basis` を通り、言い切りの語は `usable`/`readable` が止める。
- Structured Outputs の形。`tap` は `anyOf` を使わない整数の配列で、空なら押す場所なしになる。`parseTap` は長さ2、整数、負でないことを確かめ、壊れていても答えの残りは捨てない。
- `CoordinateMapper.sentSize` は、claude-docs の `/docs/en/build-with-claude/vision-coordinates` の `resized_size` を正しく写している。28の切り上げ、トークン数、縦長の回転、二分探索、偶数への丸めが同じだ。戻すときはパディングでなく送った寸法で割り、画面の外は nil にする。裏側の `fitsUnresized` も同じ式で、それ以外の寸法は400で断る。`UIImage(data:)` は scale が1なので、`size` はピクセルになる。Core のテスト11件が通った。参考までに、公式には `"transformations": { "oversized_image": "error" }` で縮小を誤りにする方法があり、足せば寸法のずれが黙って起きなくなる(指摘ではない)。
- `POST /consult` の約束を広げた点は、`docs/plan.md` の表とタスク12のつなぎ目の両方に書かれていて、413と400の誤りの名前もコードと合っている。
- 共有の拡張は、`App/KeychainDeviceKeyStore.swift` を一緒にコンパイルし、App Group `group.com.sagochiko.mimamori` を鍵の置き場として読む。Safari の拡張と同じ形で、entitlements にもその group がある。受けるのは画像1枚だけになり、文字や URL の受け口は外した(送れないのに出てしまう問題をなくすため)。母以外の端末では403が返り、「送れませんでした」が出る。
- `ios/Core` の新しいファイル(`CoordinateMapper.swift`、`ShareConsult.swift`)は `Foundation` だけを読み込み、iOS 専用の枠組みを使っていない。差分に秘密の値や家族の情報は無かった。
