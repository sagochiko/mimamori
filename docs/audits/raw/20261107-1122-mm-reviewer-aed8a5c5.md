## 指摘

直すべき重い指摘は無い。軽いものを3つ、重い順に挙げる。どれもマージを止める理由にはしていない。

1. 読み込み中に聞き始めると、書いた言葉が消える(軽い。確度は中)
   場所は `ios/App/Views/ProtectedHomeView.swift` の `onChange(of: pickedPhoto)`、350行目あたり。`loadTransferable` を待つあいだは phase が idle のままで、待っている印も出ない。iCloud にしか無い写真だと、読み込みに数秒かかることがある。そのあいだに母がマイクを押して listening に入ると、先に `if draft == text { draft = "" }` が走って欄が空になる。そのあと `AppModel.sendPicture` が `guard voice.acceptsText else { return }` で何も言わずに戻る。結果、画像は送られず、書いた言葉も消える。直し方は、`sendPicture` が受け付けたかを `Bool` で返し、欄を空にするのはその後にする。または、読み込みのあいだボタンを止める。

2. 丸を付けた画像が、アプリの切り替え画面のスナップショットに写る(軽い。確度は中。OS の動き)
   場所は `AppModel.shownPicture`。この画像は次の相談まで画面に出ている。そのまま裏に回すと、iOS が切り替え画面のスナップショットをアプリの入れ物に保存し、そこに画像が写る。アプリのコードが書くものではない。会話の文も同じように写る。それでも design の「画像はファイルにも…残さない」を文字どおり読むと、これは外れる。裏に回るとき(`scenePhase` が `.inactive` か `.background`)に画像を伏せるか、design に OS の切り替え画面は対象外と書くか、どちらかで足りる。

3. 落ちようのない試験と、App 側のつなぎの試験が無いこと(軽い)
   - `ios/Core/Tests/MimamoriCoreTests/PictureConsultTests.swift` の `lineIsFixed` は、決め打ちの文字列に数字が無いことを見ているだけで、落ちようがない。
   - `keepsLineAndAnswerOnly` は、`ChatKeeper.pictured` が文字列しか受け取らないので、画像が入らないことを確かめたことにはならない。
   - `AppModel` の `.sendPicture` の効果のつなぎにも試験が無い。たとえば、`chat` に1行だけ入ること、`shownPicture` が次の `sendTyped` か `micTapped` で消えること、通信が落ちたとき `voice.sendFailed()` になること。このつなぎはコードを読んで確かめ、正しかった。試験で守られていないだけだ。

## 確かめて問題なかったこと

- 画像は残らない
  - `ChatKeeper.pictured` が保存するのは、`pictureLine` と書いた言葉の1行だけ。答えは `ShareConsult.reply` の文だけ(`ios/Core/Sources/MimamoriCore/Chat.swift`)。
  - `ConsultPicture` と `ShownPicture` は、メモリに置くだけでファイルに書かない。`shownPicture` は、ログアウト(401)の処理、次の文字の相談、次の声の相談で消える。
  - 裏側では `server/src/consult.ts` の `consult` が、画像を `askClaude` に渡すだけで保存しない。共有の拡張と同じ道を通る。
- 共有の拡張の動きは変わっていない
  - `ShareViewController` から移した縮め方を、前の差分と1行ずつ見比べた。`UIImage(data:)`、`UIGraphicsImageRenderer` を scale 1 と opaque で使うこと、JPEG の品質 0.85、0.6、0.4、base64 で300万字の上限、`circle` の計算が同じだ。`CircledImage` も中身は同じまま移っている。
  - 増えたのは、幅か高さが0の画像を弾く guard だけ。前は送ってから失敗していたもので、今は手前で失敗になる。
  - `ios/project.yml` で `App/ConsultPicture.swift` を ShareExtension に足してある。pbxproj は生成の差分の形をしている。
- 母の安全の決まりは写真の道でも同じに効く
  - 写真のボタンは `Session.consult(image:text:)` から、共有の拡張と同じ `POST /consult` の `image` に届く。文字は `text`、前のやり取りは付けない。
  - 詐欺の答えを決まった文にすること(PR #191 の `decidePlan`)、案内しない話題を家族に回すこと、`IMAGE_NOTE` の注入への構え、`notReachedReply`、カードに母の言葉を写さない `repeats` の判定は、どれも裏側で画像のありなしに関係なく働く。
  - 画像に言葉を添えた相談(`text` と `image` の両方)は、もともと `consult.ts` が受けていた形だ。
  - 家族に回った答えでは、`answered` の `if answer.handoff { await loadCases() }` が写真の道でも走る。
- 読み上げない
  - `pictured` が `byVoice = false` にするので、「読み上げ」がオンでも画像の答えは読まれない。声で聞いたあとに画像を見せても同じで、その試験がある。
- 待つあいだと落ちたときの状態
  - thinking のあいだは `acceptsText` が false なので、写真のボタンも欄も止まる。
  - 通信が落ちると `.failed(.offline)` になる。母の1行と画像は残り、答えは付かない。文字の相談で落ちたときと同じ形だ。
  - 読めない画像では `.failed(.unreadableImage)` になる。会話には何も入らず、欄の言葉も残る。
- 衝突の解き方
  - `origin/main...HEAD` の差分は、この PR の3つのコミットの中身だけだった。ひと言(`SmileNote` と「ひと言」)の名残りは `ProtectedHomeView.swift` にも `AppModel.swift` にも無い。
