1. 照らす段に入った時点でボタンの位置が無いと、吹き出しが見えないまま残る(固まりはしない)。確度は中(コードを読んで組み立てた。再現はしていない)
   [`ios/App/Views/OnboardingGuide.swift`](ios/App/Views/OnboardingGuide.swift) の `lose` は、消えた部品がその時の段(`tour?.current == step`)のときだけ `skip` する。起きる場面はこうなる。家族 A が招待や笑顔の段を読んでいるあいだに、家族 B が唯一の未解決のカードを解決する。`keepCasesFresh` がカードを読み直すと「電話する」と「解決」が消え、`frames[.call]` は nil になる。このとき今の段は `.invite` なので `skip` しない。A が「次へ」を押して `.call` に進むと、`CoachMarkOverlay` は `if let frame = guide.frames[step]` を満たさず何も描かない。`FamilyHomeView` の `scrollTo` も、`guidedCardID` が nil なので何もしない。暗い面も「次へ」も無いので画面はふつうに使えるが、`tour` は `.call` のまま残る。あとで同じ起動中に新しい未解決のカードが届き、その行が画面に出ると、ボタンの位置が入った瞬間に暗い面と「心配なときはここから母に電話してね」が突然かぶさる。もう1つの経路もある。`guidedCardID` が別のカードへ移ると、古いボタンの `onDisappear` が新しいカードの記録した `frames[.call]` を後から消すことがある。こちらで起きるのは、ツアーが早く終わるだけ。
   直し方の案。「次へ」で `next()` したあとに `tour?.skip { ($0 == .call || $0 == .resolve) && model.guidedCardID == nil }` のように、カードの有無で飛ばす。`frames` で判断すると、List がまだ作っていない行まで飛ばしてしまうので、`frames` ではなくカードの有無で見る。急がない。

## 確かめて問題なかったこと

- 1回目の指摘1(画面の外で固まる)は閉じた。吹き出しの余白は `clamp` で上60pt、下40pt以上に収まる。上限の `height - 240` は、穴が縦に長いときだけ効く(below が偽なのに `minY < 253` になるのは、高さが画面の半分近い穴に限られる)。カードのボタンでは起きない。穴が画面の外にあるとき、縁と吹き出しの先は `onScreen` で隠れ、吹き出しと「次へ」は画面の中に残る。`.call` と `.resolve` に入ると `scrollTo(id, anchor: .bottom)` でカードの下の端を画面へ入れる。`CaseCardView` のボタンはカードの一番下(`if !actions.isEmpty { buttons }`)にあるので、カードが画面より高くても見える
