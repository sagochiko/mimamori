## 指摘(重い順)

### 1. 中の下。`gh auth status -t` の直後に区切り記号が来る形が guard-secrets をすり抜ける

場所は `~/develop/mimamori/.claude/hooks/guard-secrets.sh` の11行目の `pat` に足した枝。

```text
gh[[:space:]]+auth[[:space:]]+status[^;&|]*(--show-token|[[:space:]]-[[:alpha:]]*t[[:alpha:]]*([[:space:]]|$))
```

短いフラグの束の終端が `([[:space:]]|$)` なので、`-t` のすぐあとに `;`、`|`、`>`、`&`、`)` が来ると当たらない(`--show-token` の枝には終端の条件が無いので当たる)。入力を `jq --arg` で2つの部品から組み立ててフックに流した結果。

```text
exit=0 : <gh auth status> -t;true        (通る。トークンが出る)
exit=0 : <gh auth status> -t|pbcopy      (通る)
exit=0 : <gh auth status> -t>/tmp/x      (通る)
exit=0 : <gh auth status> -t&&true       (通る)
exit=0 : <gh auth status> -t)            (通る)
exit=2 : <gh auth status> -t 2>/dev/null (止まる)
exit=2 : <gh auth status> --show-token;true (止まる)
```

`Bash(gh auth status*)` が allow のままなので、`-t|pbcopy` のような形は聞かれもせずにトークンを文脈に出す。終端を `([^[:alnum:]]|$)` にする(あるいは `;&|><)` を足す)のと、`scripts/test-hooks.sh` の27〜31行目の並びに `-t;true` のような `expect 2` を1行足すのが直し方。確からしさは高い(再現した)。


閉じる側に倒れていて理由も表示されるので、重さは低い。`pat` は単引用符の中なので、span の除外に改行を入れるには `$'\n'` をつないで組み立てる必要がある。指摘1の終端を直すときに一緒に見ればよいが、これだけでは止めない。
