## 指摘

### 1. ページの関門が、母の公式サイトのログイン画面や、ふつうの記事まで Claude に回す(確かめ方: 再現した)

`~/develop/mimamori/.claude/worktrees/issue-137-unmarked-to-claude/server/src/page-gate.ts` の 64〜67行目。

```ts
if (rule.level !== null || rule.reasons.length > 0) return true;
return page.hasSecretField === true || speaksAsOtherBrand(page) || callsForSupport(page);
```

`officialBrandOf(host)` を見るのは `speaksAsOtherBrand` だけで、`hasSecretField` と `callsForSupport` はホストを見ない。`SPEAKS_AS_BRAND`(33行目)と `BRAND_WORDS` も「本文のどこかにある」で当てるので、ナビに「ログイン」がある記事サイトで会社の名が出ると当たる。使い捨ての Vitest で `pageWorthAsking` に次の3つを渡すと、3つとも `true` が返った(規則は `{ level: null, reasons: [] }`)。

- `https://www.amazon.co.jp/ap/signin`、本文「Amazon サインイン」、`hasSecretField: true`(母が Amazon に入るたび)
- `https://www.bk.mufg.jp/`、本文「不正利用にご注意ください。お問い合わせ 0120-860-777」(銀行の公式の注意ページ)
- `https://www.nikkei.com/article/1`、本文「ログイン 会員登録 楽天グループの決算を発表」(ヘッダに「ログイン」がある記事)

起きること。母が開く銀行や通販のログイン画面、公式のサポートページ、「ログイン」のナビつきの記事で会社の名が出るもの(日経、Yahoo のたぐい)の本文が、毎回 Claude に送られる。`content.js` は最初と本文が伸びたときの2回送るので(157〜159行目)、1ページで2回の Claude 呼び出しになりうる。行は残らず知らせも出ないので誤報にはならないが、作者が「Safari はうまいことやれないか」と言った「閲覧をそのまま Claude に見せない」の狙いからは外れる。`docs/plan.md` はこの実装のとおりに書かれているので、計画との食い違いではなく設計の狙いとのずれ。

直し方の案。`officialBrandOf(host(page)) !== null` のときは `hasSecretField` と `callsForSupport` を見ない(公式のドメインの一覧は厳密一致と末尾一致なので、似せたドメインは除外されない)。`speaksAsOtherBrand` は、会社の名と客に話す語の距離を限る(同じ文、または前後 N 字)。

あわせて、`~/develop/mimamori/.claude/worktrees/issue-137-unmarked-to-claude/server/test/page.test.ts` の 128〜137行目「the brand's own sign-in page」は `hasSecretField: false` で呼んでいるので、公式のログイン画面(欄がある)が回らないことを確かめていない。`true` にすると落ちる。確かさは高い(再現した)。

### 2. 規則が印だけ付けた SMS、メール、ページは、Claude が落ちると誰にも伝わらなくなった(確かめ方: コードで見た)

`~/develop/mimamori/.claude/worktrees/issue-137-unmarked-to-claude/server/src/claude.ts` の 210〜216行目。`decideFor` が3段階にする条件は `claude === null && rule.level === null` で、`rule.reasons` の有無を見ない。

この PR の前は、印はあるが段階は無い SMS(`UNSURE_WEAK` のような弱い印1つ、海外の番号つきの見慣れないリンクなど)やページは、Claude が落ちると2段階「確かめ中」で母と家族に届いていた(`decide()` の `UNDECIDED_LEVEL`)。今は同じものが3段階になり、行も書かれず、誰にも届かない。Issue の完了の条件は「印の無い本物の SMS で知らせが出ない」で、印のあるものまで黙らせるとは書いていない。`docs/design.md` の「Claude の呼び出しが失敗したり遅れたりしたときは、決まった規則の判定だけで知らせ」とも少しずれる。

ただし PR の説明と `docs/plan.md` の直しは「規則も Claude も段階を決めなかったもの」と書いていて実装と合っているので、主のセッションがこれを意図して選んだなら指摘2は採らなくてよい。意図していないなら、`rule.reasons` が `FOREIGN_SENDER_REASON` だけか空のときに限って3段階にすると、前の動きを保てる。確かさは中(どちらを意図したかは文書から読めない)。

## 確かめて問題なかったこと

- `decideFor` の条件は `sms`、`gmail`、`page` の3経路と「規則 null かつ Claude 無し」だけで、`consult`、`call`、`dns` は `decide()` そのまま(`server/test/claude.test.ts` 230〜256行目で3経路と相談の両方を確かめている)。Claude が答えたときは `decide()` と同じで、`injection_suspected` で1段重くする動きも変わらない。`INJECTION` の規則は strong なので、注入の文があるものは段階が付き、3段階の黙る経路には入らない
- `judge.ts` の早い `return "done"`(385行目)は Claude の呼び出しの後、`INSERT` の前にある。1段階と2段階は今までどおり行を書いて知らせる。1時間のまとめの SQL は `notified = 1 AND level <= ?` で、3段階の行はもともと当たらない。届き直しで二重の知らせは出ない(行が無いので Claude をもう一度呼び、知らせは1回)。30日の削除(`retention.ts`)と「すべて消す」は行が無いぶん減るだけ。`GET /alerts` の実装は `server/src/index.ts` に無く、iOS 側にも3段階の行を読む所は無かった(`grep` で確かめた)
- 相談の3段階は行を書き続ける(`judge.test.ts` 286〜293行目)
- `worthAsking` が外すのは `level === null` かつ `CODE_ONLY_REASON` だけ。`CODE_ONLY_REASON` は規則が SMS にしか付けない(`rules/index.ts` 315、333行目)ので、メールの認証コードは Claude に回る。SMS の `junk` の判定(`rule.level === 1 && rule.confident`)は変わっていない
- `POST /page` の `hasSecretField` は真偽でなければ 400、キューの `payload` には乗らない(`page.test.ts` 149〜156行目)。`content.js` は `type`、`autocomplete`、`name`、`id` だけを見て `.value` は読まない。家族の端末と家の中のアドレスは関門の前で外れる。どの経路も「安全です」は返さず、関門は段階も理由も付けない
- `ios/Core` の `PageCheck.swift` は `Foundation` だけで、iOS だけの枠組みは足していない。`as? Bool` 以外は `false` に落とす
- 予算。Cloudflare の料金の文書(developers.cloudflare.com/queues/platform/pricing)では無料プランの Queues は1日1万操作で、1通あたり書く、読む、消すの3操作なので、1日およそ3,300通まで。1家族の SMS、メール、ページなら足りるが、指摘1のとおりページの回りすぎが積み上がる経路になる。Claude の呼び出しは `ExternalBudget` が1回の処理ごとに絞っていて、足りなければ `retry`。Haiku の料金は確かめていない
- eval の `rules+claude` は `worthAsking` と `pageWorthAsking` と `decideFor` を本番と同じ関数で通す。`eval/README.md` と `eval/RESULTS.md` に、前の行が本番より見逃しを少なく出していた理由と、例文に入力欄が無いことが書いてある。`eval/test` の2件は Claude を呼んだ例文を `seen` で確かめていて、関門を外すと落ちる
- 秘密、家族の実データ、外から写したものは差分に無い。テストの電話番号は `+819000000001` と `050-0000-0000` のような空の番号
