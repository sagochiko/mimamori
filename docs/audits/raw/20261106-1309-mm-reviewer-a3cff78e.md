## 指摘

1. `graphql` を道筋や URL で書くと、マージと削除の mutation が聞かずに通る(確かさは高め、8割程度)
   - 場所は [`.claude/hooks/guard-prod.sh`](.claude/hooks/guard-prod.sh) の225行目。`[[ "$endpoint" == graphql ]]` は文字が完全に一致したときだけ graphql の扱いになる。
   - `gh api /graphql -f query='mutation{mergePullRequest(input:{pullRequestId:"x"}){clientMutationId}}'` や `gh api https://api.github.com/graphql -f query='mutation{deleteRef(...)}'` は REST の枝に入る。field() が立てる `merges` と `deletes` は REST の枝では見ないので、POST として何も聞かずに通る。
   - gh は REST の道筋の頭の `/` を落として `https://api.github.com/graphql` に `{"query": ...}` を POST する。これは GraphQL の要求として受け付けられるので、マージの関門を飛ばしてマージできる。完全な URL の形は確実に通る。`/graphql` は gh の道筋の組み立て方からの推測で、流していない。
   - 直し方の案は、`${endpoint##*/}` が `graphql` なら graphql の扱いにすること。または REST の枝でも `merges` と `deletes` を見る。
