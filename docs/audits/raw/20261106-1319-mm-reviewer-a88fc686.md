## 指摘

1. help の経路で、読点をまたぐ認証コードの手順が3段階のまま母に返る。main より弱まる道で、確度は高い(再現した)。
   場所は [`server/src/consult-judge.ts`](~/develop/mimamori/.claude/worktrees/issue-84-consult-overflow/server/src/consult-judge.ts) の `guidedIn`(565〜587行目)。`ALWAYS_GUARDED` は注意の形の除外をやめたが、型を当てる先は読点で切ったあとの部分のままになっている。認証コードの型 `(sms|ショートメール|メッセージ|メール)で(届い|来)た.{0,6}(番号|数字|コード)` は、main では行全体に当てるので `.{0,6}` が読点をまたいで当たる。本ブランチでは「〜た」で部分が切れるので当たらない。
   前に「振込のやり方を教えて」か「認証コードってどこに入れるの」と聞いたあと、「次は何を押すの?」に Claude が help で返した場面で確かめた(`probe6.mts`)。

   | Claude の手順 | 本ブランチ | main |
   |---|---|---|
   | `メールで届いた、番号を入れて` | `L3 fam=false`(読み上げる) | `L2 fam=true` |
   | `smsで来た、数字を入れて` | `L3 fam=false` | `L2 fam=true` |

   8958f87 のコミットメッセージと `docs/design.md` の新しい文は「送金と認証コードは main と同じく語があれば注意の形でも手順と数える」と書いている。実装はそうなっていない。送金と認証コードはもう注意の形で外さないので、部分に切る理由が無い。直し方は、`ALWAYS_GUARDED` の型だけ main と同じく `normalize(line)` の全体に当てること。部分で当てた結果との和を取れば、注意の形で外すほかの話題の動きは変わらない。上の2例を「money or a code」の表に足すとよい。

2. 前に聞いた話題(データの削除、構成プロファイル)の手順も、読点をまたぐと読み上げられる。main より弱まる道で、確度は高い(再現した)。重さは1より一段下。
   原因は1と同じで、`guidedIn` が部分に切ってから型を当てている。削除の型 `(データ|写真|連絡先|トーク|…).{0,8}(消|削除)` と、プロファイルの型 `プロファイル.{0,10}(インストール|…)` が読点をまたげない。
   前に「写真を全部消したい」と聞いたあとの help の答えで確かめた(`probe5.mts`、`probe6.mts`)。

   | Claude の手順 | 本ブランチ | main |
   |---|---|---|
   | `写真、まとめて消すには選択を押して` | `L3`(読み上げる) | `L2 fam=true` |
   | `写真はまとめて、消して` | `L3` | `L2 fam=true` |
   | `連絡先、削除して` | `L3` | `L2 fam=true` |
   | `トーク、消すなら設定から` | `L3` | `L2 fam=true` |
   | `プロファイル、インストールを押して`(前にプロファイルを聞いたあと) | `L3` | `L2 fam=true` |

   設計の文は「確かめるのは、前に聞いた話題と、送金と認証コードだけ」で、前に聞いた話題の手順は家族に回すと読める。PR の1回目から `guidedIn` にあった切り方で、この直しで入った穴ではない。ただ「main より弱まる道」なので挙げる。直し方は、文全体で型が当たるのにどの部分にも当たらない文を手順と数えること。または、注意の形かどうかだけを部分の終わりで見て、話題の有無は文で見ること。

3. `asksFamilyOnly` の例外は1文に限らず、`!`、`?`、改行のあとの手順を読み上げる。確度は高い(再現した)。main も同じものを読み上げるので後退ではない。ただ、依頼の「例外で手順が読み上げられる道」に当たり、設計の「家族に確かめることだけを言う1文は読む」とも合わない。
   場所は同じファイルの `asksFamilyOnly`(625〜629行目)の `^[^、。,て]*`。この文字の並びが `!`、`?`、`！`、`？`、`\n` を通す。銀行を名乗るメッセージの相談への scam の答え(2段階)で確かめた(`probe5.mts`)。
   - `暗証番号を入れる!そのあと振込先に問題ないか家族に確かめて` は、そのまま `詐欺の手口と似ているところがあります。暗証番号を入れる!そのあと…` と読み上げる
   - `暗証番号を入力\n問題ないか家族に確かめて` と `暗証番号を入れろ?問題ないか家族に確認して` も同じ
   - 3段階では `lowConcernReply` が「暗証番号」を含む行を落とすので出ない。ただ `振込を押すか家族に確かめて` は3段階でも読む。これは1文で家族に確かめる形なので設計どおりと読んだ

   注入された文が Claude の action をこの形に寄せると、そのまま母に届く。直し方は、文字の並びに `!?！？\n` を足して除くこと(`[^、。,て!?！？\n]`)。1行で済む。
