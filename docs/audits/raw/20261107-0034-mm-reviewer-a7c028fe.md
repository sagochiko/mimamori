## 指摘

1. 候補が1つしか見つからないときは、追跡済みかどうかを見ないまま使う。そのため、前の回の原文を今回の回として黙って投稿する道が残っている。場所は `scripts/review-record.sh` の36行目と43〜52行目。確かさは高い(コードで見た。再現はしていない)。
   直しで足したのは `if [[ "$count" -ge 2 ]]` の中の追跡済みを外す分岐だけで、`count` が1のときはこの分岐を通らない。たとえば次の流れになる。1回目の原文 `20261107-0010-mm-reviewer-55556666.md` はブランチにコミット済み。2回目は別の id のレビュー役で走った(Sonnet で始めた役は続きを頼まず新しく起動するので、id が変わるのは CLAUDE.md の決まりどおりの流れ)。ここで主が1回目の id `55556666` と `2` を渡すと、見つかるのは追跡済みの1回目だけで、`count=1` のまま `name` に入る。61行目の `mv` は動かず、70行目で「2回目、<HEAD> を読んだもの。保存した原文は `...-0010-...`」という本文が1回目の中身で書かれる。73行目は `already committed` を出すだけで、終了コードは0になる。その本文を `gh pr comment` で流すと、1回目の「直すべき指摘あり」が2回目として PR に載る。2回目の保存に失敗したとき(`save-report.sh` は失敗をログに書くだけで止めない)も同じ形になる。
   3回目も同じ形になる。1回目と2回目がどちらも追跡済みで3回目がまだ保存されていないと、40行目の `tail -n 1` が2回目を選び、3回目として出す。コメントの「すべて追跡済みなら流し直し」という前提は、渡された `round` と原文の回が合っているかを確かめていない。
   直し方の案はこうだ。選んだ原文が追跡済みなら、その原文を入れたコミットの件名(`docs(harness): N回目のレビューの原文を残す`)の N を `git log -1 --format=%s -- "$raw"` で読み、`$round` と違えば名前を並べて止める。`count` が1のときもこの確かめを通す。試験には、`count` が1で追跡済みの1回目だけがある状態で `2` を渡すと止まる形と、1回目と2回目が追跡済みの状態で `3` を渡すと止まる形を足す。

2. SKILL の手順6.1の書き方は、指摘1の場合を伝えていない。場所は `.claude/skills/mm-task/SKILL.md` の66行目。確かさは中くらい。
   「none, or more than one not yet on the branch, stops it」とあるので、読んだ主は「止まらなければ今回の原文が選ばれた」と受け取る。実際には、追跡済みのものが1つだけ残ったときは止まらずに使われる。指摘1をスクリプトで直せば、この文はそのままで合う。直さないなら、出力に `already committed:` が出たときは流し直しのときだけ正しい、という注意が要る。

## 確かめて問題なかったこと

- 主の場面は正しく動く。1回目が追跡済みで、2回目が本体の木にまだ追跡されずにある場面だ。このとき `fresh` には2回目だけが残り、本体の木から作業の木へ `mv` されてコミットされる。2回目の流し直し(どちらも追跡済み)では `tail -n 1` が2回目を選ぶ。66〜68行目は HEAD が2回目の原文のコミットのときに親を指すので、「読んだコミット」も正しい。
- 名前は `YYYYMMDD-HHMM` で始まるので、`sort -u` の後の `tail -n 1` は時刻の一番新しいものになる。
- 2つとも追跡されていない場合は止まる。1回目の実行がコミットの前に落ちて作業の木に残り、2回目も保存された場面がこれにあたる。既存の試験 `33334444` がこれを確かめている。
- PR が本体の木にある場合(`main_tree` が `.` と同じ)も、`sort -u` で重複が消え、追跡されていない2回目だけが残る。
- 試験は直しを外すと落ちる。直しの前は、1回目(`rw` に追跡済み)と2回目(本体の木)で `count=2` になって `exit 1` し、新しい2つの試験はどちらも失敗する。`tail` を `head` に替えると、流し直しの試験の `grep -q '^2回目$'` が落ちる。「追跡済みを外さず、いつも一番新しいものを使う」に替えると、既存の `33334444` の試験が落ちる。
- `bash scripts/test-hooks.sh` は手元で `exit=0` だった。
- 直しの外の話で、今回の指摘にはしないものがある。`save-report.sh` は同じ分に同じ名前の原文が本体の木にあると `...-<id>-2.md` で保存し、これは `*-mm-reviewer-<id>.md` に当たらない。ただ、1回目は作業の木へ移ったあとなので、ふつうの流れではこの名前にならない。
