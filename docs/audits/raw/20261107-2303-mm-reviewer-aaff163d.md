## 指摘

直すべき指摘はない。気づいたことを、重い順に3つ挙げる。どれもマージを止める理由にはならないと見ている。

1. 「すべて消す」と家族の作り直しを繰り返すと、1つの接続元が使える額は家族の上限の120倍になる(確度は高い。ただ設計の範囲の中の話)
   - [`server/src/family-limit.ts`](server/src/family-limit.ts) の上限は1時間に5家族なので、1日に120家族まで作れる。[`server/src/claude-limit.ts`](server/src/claude-limit.ts) の上限は家族ごとに Claude 200回と調べもの20回で、1家族あたり1日約20ドルになる。1つの接続元で1日に約2,400ドルまで届き、接続元を替えれば上限はない。
   - [`docs/design.md`](docs/design.md) の「1家族で1日に…収まる」という書き方自体は正しい。ただ、実際に額を止めているのは Anthropic Console の月50ドルの上限で、そこまでは1日もかからずに使い切れる。使い切った後は Claude がエラーを返し、どの経路も規則だけで答える既存の道に入る。母を危なくはしないが、本物の家族の Claude の判定も月末まで止まる。
   - 直すなら、design の文に「本当の歯止めは組織の上限で、そこまで行くと全家族が規則だけになる」と一言足す程度で足りる。

2. iOS の `POST /families` は429を特に扱わない(確度は高い。影響は小さい)
   - [`ios/Core/Sources/MimamoriCore/APIClient.swift`](ios/Core/Sources/MimamoriCore/APIClient.swift) の45行目が `POST families` を呼ぶ。`ios/` に429や回数超えを扱う箇所はなく、ふつうの失敗と同じ表示になる。
   - 1つの回線の後ろで審査員が続けて6回作ると、6回目は理由の分からない失敗に見える。会場の Wi-Fi を共有するような場面でだけ起きうる。

3. 相談で Claude を呼ぶ前に回数を引くので、`ExternalBudget` が尽きたときは1回ぶん余計に数える(確度は高い。実害はほぼない)
   - [`server/src/consult.ts`](server/src/consult.ts) の308行目と326行目は `takeClaudeCall` を `budget.take()` より先に呼ぶ。チケットが無くて Claude を呼ばなかったときも、日の回数は1つ増える。上限を厳しめに使う側なので、安全側に倒れている。

## 確かめて問題なかったこと

- 母に「家族に伝えました」と返しながら知らせが届かない道(#64 と同じ種類)は無かった。上限や D1 の失敗のとき、相談の1回目の呼び出しは `null` を返す。その後は既存の「Claude が答えなかった」道を通り、`familyWasTold` が `cases.family_notified_at` を読んで `notReachedReply` を選ぶ([`server/src/consult.ts`](server/src/consult.ts) の378行目)。試験は両方の場合を確かめている。上限のときに家族のカードと2件の push が出ること、家族の端末トークンを消すと「うまく答えられませんでした。家族に届いていません。急ぐなら電話して」になること(`server/test/consult.test.ts` の末尾)。
- 詐欺を見逃す道は無かった。判定のキューでは、上限で `claude` が `null` のまま `decideFor` に入るので、規則の1段階と2段階はそのまま知らせになる。試験は、規則の2段階の SMS が上限のときに母へ「確かめ中」、家族へ2件届き、「安全」と言わないことを確かめている。メールで規則が確かでないものは、`MAIL_CLAUDE_DELIVERIES` の回数まで待ってから規則の段階で知らせるので、遅れるだけで落ちはしない([`server/src/judge.ts`](server/src/judge.ts) の439行目から446行目)。規則が3段階で Claude だけが拾えたものは上限で落ちる。ただし design に書かれた「Claude が答えなかったとき」と同じ扱いで、上限を使えるのはその家族の鍵を持つ人だけなので、他人が本物の家族の上限を使い切ることはできない。
- 調べものの上限は、バッチのすべての知らせの後に `takeResearchStart` で判定され、超えたときは `continue` するだけになっている。知らせは3件出ていることを試験で見た。
- Claude を呼ぶ箇所は全部数えている。`api.anthropic.com` を呼ぶのは [`server/src/claude.ts`](server/src/claude.ts)、[`server/src/consult-judge.ts`](server/src/consult-judge.ts)、[`server/src/agents.ts`](server/src/agents.ts) だけで、Claude を呼ぶ経路は `judge.ts` の `askClaude`、`consult.ts` の `askClaude` と `searchAnswer`、`startInvestigation` の4つしかない。どれも上限を通る。`agents.ts` の残りは削除、回収、webhook で、新しい会話は始めない。
- ニセ警察の筋書きは上限のときも Claude を呼ばず、すぐ答えて家族に2件届く(試験あり)。体験モードは決まった答えを流すので、裏側を通らない。
- 審査員が家族を作る流れも壊れていない。アプリが `POST /families` を呼ぶのは最初の1回だけで、別の接続元なら6回目の後でも201になることを試験で見た。
- SQL に要求の値は入らない。`claude-limit.ts` で文字列に埋めているのは型 `Column` の2つの固定の名前だけで、値はすべて bind している。「すべて消す」の表の一覧も固定。`family_attempts` の鍵は HKDF で導いた別の鍵の HMAC で、アドレスそのものは残さない。
- 同時に呼ばれたときも上限を越えない。`claude_daily` は `ON CONFLICT ... DO UPDATE ... WHERE col < cap RETURNING` で増やし、断るときは行を返さず何も書かない。`family_attempts` は先に SELECT するが、upsert の `RETURNING count` で数え直すので、同時の試行も5回で止まる(10回同時の試験がそれぞれにある)。D1 が失敗したとき、`take` は `false` を返して例外を投げない。`takeFamilyCreate` は例外のまま500になり、家族を作らない側に倒れる。
- マイグレーション `0010` の2つの表は、plan.md の表と合っている。日次の掃除は日本時間の今日と昨日の行を残し、`family_attempts` は1日より古い行を消す(午前4時の掃除の試験あり)。「すべて消す」は `claude_daily` も消し、別の家族の行は残る(`server/test/data.test.ts`)。
- [`server/test/helpers.ts`](server/test/helpers.ts) の `createFamily` を毎回違うアドレスにした変更は、試験を弱めていない。これまで `POST /families` には上限が無く、ヘッダが無いと全部 `unknown` の1つの枠に入るので、この変更が無いと既存の試験が6家族目から落ちる。上限そのものは `claude-limit.test.ts` が同じアドレスで直接確かめている。`ip` を付けずに `/families` を直に呼ぶ試験はほかに無い。
- 試験は上限を本当に確かめている。上限の1つ手前では Claude を呼び、上限ちょうどでは呼ばない、の両側があり、家族ごとに分かれること、日本時間の0時で戻ること、既定値の200と20と5も確かめている。手元で流した結果は次のとおり。`claude-limit`、`judge`、`consult-search`、`data` の4つのファイルで `Tests 213 passed (213)`、`consult.test.ts` で `Tests 782 passed (782)`。
- 秘密、家族の実データ、外から写したものは無く、`ios/Core` にも変更は無い。届いた文面や Claude の答えで、上限、通知先、段階が変わる道も無い。

レビューは `origin/main...limit-claude-per-member` の差分で行った。PR のデプロイの手順(`0010` を先に流す)は、表が無いときの挙動とも合っている。表が無いと `take` が失敗して規則だけになり、`POST /families` は500になる。
