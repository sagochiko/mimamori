## 指摘

### 1. `REASSURES` が公式の注意喚起のよくある言い回しを落とす(この直しが作った退行、確度は高い)

[`server/src/agents.ts`](~/develop/mimamori/.claude/worktrees/issue-12-managed-agents/server/src/agents.ts) の336行目で、`正規|本物|実在` を前後の条件なしに部分一致で落としている。注意喚起のページは「本物そっくりの偽サイト」「正規のサイトを装う」「実在する企業をかたる」とよく書くので、エージェントが日本郵便や警察庁のページを正しく要約した行がそのまま消える。`WARNS` と `REASSURES` を写した小さなスクリプトに通して確かめた。

```text
DROP 実在する宅配業者を装った偽 SMS に注意を呼びかけている
DROP 本物そっくりの偽サイトへ誘導する手口を警告している
DROP 正規のサイトを装うフィッシングに注意を呼びかけている
PASS 警察庁が同じ手口の詐欺を注意喚起している
```

起きる場面はこうなる。宅配の偽 SMS についてエージェントが日本郵便の注意喚起を読み、「実在する宅配業者を装った偽 SMS に注意を呼びかけている」と報告する。`parseEvidence` がこの行を落とすので `evidence` は `[]` になり、家族の読み上げには何も足されない。安全の側には倒れているが、調べものという機能がいちばん多い形の根拠で空振りする。

直し方は2つある。1つは、`正規|本物|実在` のすぐあとに `を?装|そっくり|に似せ|をかた|を騙|になりすま` が続くときは落とさないこと。もう1つは、この3語を「(と|に)(一致|同じ)」「からの(もの|連絡)」「である」のような安心させる述語と組になったときだけ落とすこと。`server/test/agents.test.ts` の `keeps only lines that warn, and drops lines that would reassure` には、こういう行が1つも入っていない。上の DROP の3行を `warn` 側に足せば、この退行を捕まえられる。

### 2. 注意喚起の語を含む安心の行は網を抜ける(確度は高い、重さは中くらい)

網羅は求めないという指示なので、いちばん重い1件だけ挙げる。「フィッシングの注意喚起はあるが今回の連絡は公式からのもの」は `WARNS`(`注意`、`フィッシング`)に当たり、`REASSURES` にも `soundsSafe` にも当たらないので通る。今回届いた連絡を公式のものだと言い切る行が家族の読み上げに載り、「安全と言わない」の決まりを根拠の欄から破る。本文に仕込んだ文でこの形を書かせることもできる。`今回の(連絡|メール|SMS|メッセージ)は` や `公式から(の|届)` のように、届いたものそのものを評価する形を落とす1本を足すのが安く済む。

### 3. `POST /sessions` を10秒で打ち切ると、誰も消せないセッションが残り得る(この直しで広がった、確度は中くらい、起きるのはまれ)

231行目の `AbortSignal.timeout(AGENTS_TIMEOUT_MS)` は `postJson` のすべての呼び出しに付く。API がセッションを作ったあと、返事が10秒を過ぎると、Worker の側では中止になって `session.id` を受け取れない。D1 には何も書かれないので、`dropSession` も見張りも `purgeExpiredResearch` もそのセッションを知らない。届いた本文の入ったセッションが30日を過ぎても残り、30日で消すという約束から外れる。打ち切りが無かったころは返事を待っていたので、この道はほぼ無かった。

`/agents` と `/environments` には本文が入らないので関係ない。直すなら、`/sessions` の作成だけ打ち切りを長くする(30秒など)。または、作る前に印を D1 に書いておき、あとで一覧から拾って消せるかを claude-docs の `session-operations` で確かめる。

同じ種類の小さな穴がもう1つある。310行目の `if (budget.take()) await deleteAgentSession(...)` は、競り合いに負けたセッションを消す直しだ。調べものは今ではバッチの最後に残りの予算で走るので、作成の1枚で `remaining` が0になったあとにこの道に入ると、消さずに終わる。窓は狭いので、予算に関係なく1回は消しにいく形にすれば足りる。

### 4. `data.test.ts` は外した期待の代わりを書いていない(確度は高い、重さは低い)

[`server/test/data.test.ts`](~/develop/mimamori/.claude/worktrees/issue-12-managed-agents/server/test/data.test.ts) の469行目のあたりで `not.toContain("sesn_research_new")` を外したのは妥当だ。`alertWithSession` は `investigated_at` を埋めるので、新しい `watchInvestigations` の最初のループがこのセッションを消す。それが今の正しい動きになる。ただ、外したあとに置いたのはコメントだけで、そのコメントの言う「見張りが新しいほうも消す」を確かめる期待が無い。`expect(deleted).toContain("sesn_research_new")` を足すとよい。
