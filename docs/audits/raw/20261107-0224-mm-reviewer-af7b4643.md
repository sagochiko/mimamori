## 指摘

直すべき指摘は無い。軽い所見が2つあるが、どちらもマージは止めない。

1. 低電力モードのあいだに母が自分でバックグラウンド更新を切っても、家族には知らせない(軽い。仕様として受け入れてよい)
   [`ios/Core/Sources/MimamoriCore/Checkup.swift`](~/develop/mimamori/.claude/worktrees/issue-19-checkup/ios/Core/Sources/MimamoriCore/Checkup.swift) の `backgroundRefresh != .denied || lowPowerMode` では、低電力モードの間の `.denied` を、母が切ったのか OS が止めたのか区別できない。そのため誤って伝えない側に倒している。低電力モードが終われば次の知らせで `.denied` のまま偽になり、家族に届く。遅れるだけで、知らせが失われはしない。

2. `giveBack` 自体が投げたときは、元のエラーが消えて印が残る(軽い。起きる頻度は低い)
   [`server/src/heartbeat.ts`](~/develop/mimamori/.claude/worktrees/issue-19-checkup/server/src/heartbeat.ts) の `catch` の中の `await giveBack()` が D1 の障害でまた失敗すると、印は1のまま残る。D1 全体が落ちているときだけ起き、今の枠の見積もりでは上限に当たって落ちる道はふさがったので、直さなくてよい。

## 確かめて問題なかったこと

- `watchHeartbeats` の抜ける位置。関数の頭で `budget.d1Remaining < 1 + LAPSE_D1` なら戻り、各メンバーの印の UPDATE より前に `d1Remaining < LAPSE_D1` で `break` する。印を取ったあとに枠で途中が切れる道は無い。`LAPSE_D1 = 4` は、印、`familyOf`、`sendPush` の SELECT、印の戻しで、1回目に数えた回数と合う。`sendPush` の中の、APNs に断られた端末を消す UPDATE は見積もりに入らないが、[`server/src/budget.ts`](~/develop/mimamori/.claude/worktrees/issue-19-checkup/server/src/budget.ts) の `D1_CALLS_PER_TICK = 40` の注にある、10回の余白で吸う決まりどおりだ。`no_budget` で印を戻したあとは `break` するので、同じ tick で D1 を無駄に使わない
- `reportSetting` と `watchHeartbeats` の両方で、`tellFamily` が投げたら `giveBack` で印を NULL に戻してから投げ直す。`sendPush` は1台ごとの送信の失敗を中で受けるので、投げるのは送る前の SELECT だけだ。届いたあとに印を戻して二重に送る道は無い
- `HeartbeatReport.init(notifications:backgroundRefresh:lowPowerMode:)` を見た。通知は `.denied` のときだけ偽で、`.notDetermined`、`.authorized`、`.provisional`、`.ephemeral` は真になる。1回目の1つ目の指摘(参加の直後の誤報)はこれで起きない。バックグラウンド更新は、`.denied` で低電力モードでないときだけ偽になる。`@unknown default` は通知で `.notDetermined`、更新で `.available` に倒していて、どちらも誤報の側には行かない。`NotificationPermission` と `BackgroundRefresh` は Core に置いた自前の enum で、`ios/Core` は UserNotifications も UIKit も import していない
- Apple の文書の引用。`https://developer.apple.com/tutorials/data/documentation/uikit/uiapplication/backgroundrefreshstatus.json` を読んだ。Discussion に「Don’t warn the user if the value of this property is set to restricted. A restricted user, such as one who is managed under parental controls, can’t enable Background App Refresh.」と「Background App Refresh is disabled automatically when a device is operating in low-power mode.」がある。コードの注と [`docs/plan.md`](~/develop/mimamori/.claude/worktrees/issue-19-checkup/docs/plan.md) の引用は、アポストロフィの字形を除いて原文と合う。なお、文書は低電力モードのときにこの値が `.denied` になるとまでは書いていない。`isLowPowerModeEnabled` を別に見る今の実装なら、どちらの値でも誤報にならない
- `-mimamori-now-hour` が Release に入らないこと。[`ios/App/Debug/DebugLaunch.swift`](~/develop/mimamori/.claude/worktrees/issue-19-checkup/ios/App/Debug/DebugLaunch.swift) はファイル全体が `#if DEBUG` に入っている。[`ios/App/AppModel.swift`](~/develop/mimamori/.claude/worktrees/issue-19-checkup/ios/App/AppModel.swift) の `checkupNow` も、`DebugLaunch.nowHour` を読む所を `#if DEBUG` で囲み、Release では `.now` を返す。Release で `DEBUG` の条件を足す設定は見当たらなかった
- 足した試験が落ちうる形か、1つずつ確かめた
  - 枠が4の試験は、頭の判定を消すと印を取って2件送るので落ちる。枠が5の試験は、`LAPSE_D1` を実際より大きくすると送らないので落ちる
  - 押しの枠が0の試験は、`d1Remaining` が `100 - 5` になるかを見ている。`break` を消すと2人目の分の D1 も使うので落ちる
  - `failingOn` の2つの試験は、`catch` の `giveBack` を消すと印が残って `toBeNull()` が落ちる。前方一致の `SELECT id FROM members WHERE family_id` は `familyOf` にだけ当たり、`sendPush` の `SELECT id, apns_token` には当たらない
