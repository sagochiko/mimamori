## 指摘

直すべき指摘はない。小さいものが1つだけある。

1. (軽い、確度は中) 設定の画面を開いたまま iOS の「設定」で値を変えて戻ると、画面に古い値が残る。[`ios/App/Views/SettingsView.swift`](ios/App/Views/SettingsView.swift) の45〜47行目は `onAppear` でしか読み直さないためだ。
   起きる流れはこうなる。シートを開いたままホームへ戻り、「設定」の「みまもり」で時刻を20時にしてアプリへ戻る。`cameToFront` が20時で組み直すが、シートには18時のまま出る。ここで「毎日の声かけ」をオフにしてオンに戻すと、`onChange(of: daily)` が `stored` で2つの鍵をまとめて書くので、古い18時で上書きされる。Issue の「どちらで変えても同じになる」から少し外れる。
   ただ、シートを開いたまま「設定」へ行く人はまずいないので、マージは止めない。直すなら `scenePhase` が `.active` になったときに `daily` と `readAloud` を読み直せば足りる。

## 確かめて問題なかったこと

- 型
  - アプリの中の画面は `UserDefaults.set` に `Bool` と `Int` を入れ、どちらも `NSNumber` で残る。
  - 「設定」側の `Root.plist` は `DefaultValue` が `<true/>`、`<integer>18</integer>`、`<false/>` で、`Values` も整数なので同じ型になる。
  - 読む側の `DailyCheckInSettings(reading:)` は `Bool`、`NSNumber`、`String` のどれでも受ける。5つの時刻の外の値は18時に戻る。
- 既定値
  - `register(defaults:)` はどこにも無い。鍵が無いときは Core の `standard`(オン、18時、読み上げはオフ)が既定になる。
  - plist の `DefaultValue` と Core の既定値が揃っていることは、既にある `DailyCheckInTests.swift` の165行目と169行目、`ReadAloudTests.swift` の60〜61行目のテストが見ている。
  - 画面を開いただけでは `onChange` が走らないので、何も書かれない。
- 時刻を変えたときの組み直し
  - `settingsChanged()` は `scheduleDailyCheckIns()` を呼ぶ。この関数は前の組み直しを待ってから値と役を読む([`ios/App/AppModel.swift`](ios/App/AppModel.swift) の464行目から)。
  - `DailyCheckInNotifier.replace` は、接頭辞 `daily-check-in-` の付いた予約を全部消してから足す。古い時刻の通知は残らない。
  - 時刻を続けて何度か変えても、最後の値で組み直される。オフにすると空の一覧で全部消える。
- 家族の画面に出ないこと
  - 「設定」のボタンは `model.route == .protectedHome` のときだけ出る([`ios/App/Views/RootView.swift`](ios/App/Views/RootView.swift) の98行目)。
  - Debug の起動の引数で開く道も、同じ条件と `#if DEBUG` の中にある。
  - 家族の画面の `FamilyHomeView` の `WipeMenu` には出ない。
  - 母の画面のボタンは増えていない。「その他」のメニューに1つ足しただけだ。
- 画面の文言
  - 画面に出る文字は「毎日の声かけ」「時刻」「読み上げ」「設定」「閉じる」と時刻の名札だけで、説明は `accessibilityHint` にだけ置いている。
  - 名札が `Root.plist` の `Title` や `Titles` と同じであることをテストで照らしている。
  - テストが読む `Root.plist` の道筋(`#filePath` から4つ上がって `App/Settings.bundle/Root.plist`)が正しいことも確かめた。
- テスト
  - `swift test --filter MotherSettingsTests` を流し、5件とも通った(`Test run with 5 tests in 1 suite passed`)。
  - 書いて読み直すテストは、本物の `init(reading:)` を通すので、鍵の名前か型がずれれば落ちる。
- Release のビルド
  - `xcodebuild -configuration Release -sdk iphonesimulator CODE_SIGNING_ALLOWED=NO build` を流し、`** BUILD SUCCEEDED **` だった。
  - `ScreenshotStubTransport.settingsOpen` を使う所は `#if DEBUG` の中にある。`SettingsView.swift` は pbxproj の Sources に入っている。
  - 生成物は消した。
- 文書の書きぶり
