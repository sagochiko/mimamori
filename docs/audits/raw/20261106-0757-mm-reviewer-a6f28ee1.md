## 確かめて問題なかったこと

- 両側の正規表現の文字列は `^` と `$` の位置も含めて同じ。Swift 側は `.unicodeScalar`、JS 側は `u` で、どちらもコードポイント単位。`\p{Script=Han}` と `\p{Script=Hiragana}` は両方とも Script(scx ではない)で、swiftc(`-enable-bare-slash-regex`)で動かした結果が JS と全件一致した。「々」(U+3005)は両側で Han、「ー」は両側で Common なので「このー方」は両側で false。

```text
T そう / F そうじ / T その消し方 / T この使い方 / T この両方 / T あの夕方 / T その々方 / F このー方 / F 大丈夫そう / F うんそれ / T ねぇそれ / T その送り方
```

- `$` は Swift では既定で入力の終わり(複数行の意味にしていない)。両側とも先に改行を落とす(`ignored` に 0x0A、JS は `\s`)ので、末尾の改行で答えが割れる道は無い。
- `npx vitest run test/consult.test.ts` は479件通過、`swift test --filter PointsBackTests` は通過(手元で流した)。
- 元の27件は消されても答えを変えられてもいない。
- `NEW_TOPIC` は変えておらず、「それと」「それから」「別の」「ほかの」は引き続き false。
- 締めた方向は、前の日の会話を端末の外へ出す回数が減る側で、「振込のやり方を教えて」「そうじのアプリを入れたい」「おそれがある」「だれそれ」が false になるのは Issue の1に沿う。
- 通知先と共有の範囲は `pointsBack` で変わらない。変わるのは段階の下限(指摘1の2つ目)と題だけ。
- `eval/RESULTS.md` と `eval/results.jsonl` の1行は数字と備考だけで、個人の情報や時刻は無い。`docs/dev-log.md` の追記は日付だけ。
