**1. ラッパーを前に付けた git push と gh api を、フックが見ずに通す。permissions もそれを allow に落とす(重い。確からしさ高い)**

場所は `.claude/hooks/guard-prod.sh` 57〜59行目と128行目。git の節は `starts` の先頭の語が `git` のときだけ読み、gh の節は `gh_calls`(`lib.sh` 299〜304行目)の先頭の語が `gh` のときだけ読む。`command_starts` が読み飛ばす語は `time` と予約語、`VAR=` だけになっている。

permissions の文書(https://code.claude.com/docs/en/permissions の「Wrappers」の節)には次の文がある。
> Before matching Bash rules, Claude Code strips a fixed set of wrappers, so a rule like `Bash(npm test *)` also matches `timeout 30 npm test`. The stripped wrappers are `timeout`, `time`, `nice`, `nohup`, and `stdbuf`, plus the shell builtins `command` and `builtin`, and zsh's `noglob`.

> Bare `xargs` is also stripped

なので `timeout 60 git push -fu origin main` は `git push -fu origin main` として照らされる。deny の `git push* -f`、`git push* -f *`、`git push*--force*`、`git push* +*` はどれも当たらず、allow の `Bash(git push*)` に落ちる。フックに JSON を流した答えは次のとおりで、全部終了コード0、出力なしだった。
```text
quiet  timeout 60 git push -fu origin main
quiet  timeout 60 git push --mirror
quiet  nohup git push -fu origin main
quiet  command git push -fu origin main
quiet  nice git push origin :main
quiet  stdbuf -o0 git push origin --delete main
quiet  noglob git push -f origin x
quiet  echo origin | xargs git push --mirror
quiet  timeout 30 gh api -X PATCH repos/sagochiko/mimamori -f visibility=public
quiet  command gh api -X PUT repos/o/r/pulls/3/merge
BLOCK  time git push -f origin x        (time だけは読み飛ばしている)
```
起こりうる場面はこう。push が non-fast-forward で弾かれたあと、Claude がネットワークの待ちを嫌って `timeout 60 git push -fu origin main` と書く。それが確認なしで main を書き換える。main には保護の規則が無い。Claude はネットワークのコマンドに `timeout` をよく付けるので、わざと崩した書き方とは言えない。
