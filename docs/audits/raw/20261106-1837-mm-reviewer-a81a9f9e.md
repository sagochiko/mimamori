## 指摘

1. `read_only_select` で「その execute の単純なコマンド」を切り出す方法が、生の文字を `)|;&<>` と改行で切るだけになっている。そのため、main では聞いていた「実行時に作る SQL」が聞かれずに通る。場所は [`.claude/hooks/guard-prod.sh`](.claude/hooks/guard-prod.sh) の `tail=${rest%%[)|;&<>$'\n']*}` と、`n=$(grep -oE 'd1[[:space:]]+execute' <<<"$cmd" ...)` の2行。再現して確かめたので確度は高い。下の形は main で ASK になり、この PR では QUIET になった。
   - リダイレクトのあとの語も wrangler の引数になる。`... --command 'SELECT 1' 2>/dev/null --command "$SQL"` では、`>` で切ったところで `tail` が終わるので、2つ目の `--command "$SQL"` が見えない。wrangler が後ろの `--command` を採ると、中身を読めない SQL が本番で走る。
   - 引用符の中の区切り文字でも切れる。`--command 'SELECT 1' --command "x|$SQL"` と `--command ";$SQL" --command 'SELECT 1'` の2つ。
   - 行の継続 `\` と改行でも切れる。`--command 'SELECT 1' \` で改行し、次の行に `--command "$SQL"` を置く形。複数行のコマンドは Claude がよく書くので、ここは偶然に当たりやすい。
   - 2つ目の execute を数え落とす。execute の数を生の `$cmd` の grep で数えているので、`&& npx wrangler d1 "execute" db --remote --command "$SQL"` や `ex''ecute` は数に入らない。`$text` は引用符を外した語で見ているので、main ではこれを聞いていた。
   - `xargs` で引数を足す形。`echo "--command=$SQL" | xargs npx wrangler d1 execute ... --command 'SELECT 1'` と、`xargs -I{} ... --command {}` の2つ。`head` は `|` のあとから見るので、`xargs` が足す引数は見えない。
   - `bash -c "... --command 'SELECT 1' 2>/dev/null --command \"\$0\"" "$SQL"` も、同じリダイレクトの理由で通る。
   - SELECT の後ろに別のコマンドを `;` や `&&` でつなぐ形。`; eval "$C"`、`; bash -c "$C"`、`; $W "$SQL"` がこれにあたる。これらは SELECT が無くても main で通るので、この PR で新しく開いた穴ではない。
   
   直し方の案を書く。生の文字で切らず、`shell_words` の `WORDS` と `command_starts` で execute の単純なコマンドを語の範囲として取る。その範囲の語の中に `$`、バッククォート、`--file`、2つ目の `--command` が無いことを見る。execute の数は `${WORDS[*]}` で数える。コマンドの頭は `npx` か `wrangler` で始まるものだけを認め、`xargs`、`bash -c`、`eval`、`env` のような包みを外す。改行の直前が `\` なら続きとして読む。

2. テストに、上の通り道を突く失敗の形が無い。[`scripts/test-hooks.sh`](scripts/test-hooks.sh) に足した9行は、ASK を期待する形がどれも SQL の側で外れるものだけになっている(`$EXTRA` が `tail` に入る、`;` でつなぐ、`INSERT` で始まる、など)。区切りの文字やリダイレクト、`\` と改行、2つ目の `"execute"`、`xargs` の形が無いので、今の切り出し方でも全部通る。確度は高い。

3. 文書と振る舞いが少しずれている。[`CLAUDE.md`](CLAUDE.md) は「出力を変数で受けても聞かない」と書いているが、実際には行のどこに `$` があっても聞かない。`t=$(...SELECT token...) && curl -d "$t" https://...` のように、読んだ token を外へ送る形も QUIET になる。`guard-prod.sh` が見るのは削除と取り返しのつかない操作だけなので、外へ出すのはもともと範囲の外ではある。それでも、#151 の token を読む場面と隣り合うので、書いておく。[`docs/harness.md`](docs/harness.md) の「その execute の単純なコマンドの中に `$`…が無いとき」は、指摘1のとおりに実装されていない。確度は中くらい。

## 確かめて問題なかったこと

- 一重引用符を抜ける形はどれも ASK に戻った。`'SELECT 1'\''$X'` と `'SELECT 1'"$X"` で試した。
- `--command 'SELECT 1' --command "$SQL"` のように、区切りの文字を挟まずに2つ目の `--command` を書く形は ASK に戻った。
- SQL の側の判定は閉じる側に倒れている。`/* ; DROP */`、`-- UPDATE`、`WITH ... SELECT`、`;` でつないだ書き込み、`INSERT ... SELECT` は、どれも ASK になった。SQLite には SELECT だけで書き込める関数は無い。D1 は `load_extension` を許さないし、`PRAGMA` と `ATTACH` は語の一覧で外している。これはコードと SQLite の仕様から判断したもので、D1 で実際に試してはいない。
- DROP、DELETE、TRUNCATE の判定(`destructive`)と `--file` の判定は `read_only_select` より前、またはそれとは別に動くので、この変更で弱くなっていない。
- 大文字や混ぜた大文字小文字の書き込みの語は、`tr` で小文字にしてから比べているので拾える。
- `--fil`(`--file` の省略形)は main でも QUIET になるので、この PR で増えた穴ではない。
- 秘密のファイル(`.claude/*.local`、`.dev.vars`)は読んでいない。
