### 指摘(重い順)

**1. force push の別の書き方と、遠隔のブランチの削除が確認なしで通る(重い。確からしさ高い)**
`.claude/settings.json` の allow 45行目 `Bash(git push*)` と、deny 86〜93行目。

permissions の文書には「Bash rules match the whole command text」とあり、`*` はどの文字にも当たる。直す前は `git push` が allow に無かったので、deny から漏れた形も毎回確認になっていた。今は deny に当たらなければ allow に落ちて黙って走る。`perm` を同じ設定で流した結果はこうなった。
```text
git push -fu origin x            => allow <- Bash(git push*)
git push -uf origin x            => allow <- Bash(git push*)
git push --mirror                => allow <- Bash(git push*)
git push origin --delete main    => allow <- Bash(git push*)
git push origin :main            => allow <- Bash(git push*)
git push origin HEAD:main        => allow <- Bash(git push*)
```
main にはブランチ保護が無い(dev-log の記録どおり `"protected":false`)。なので `git push -fu origin main` か `--mirror` を1回打てば、main の履歴が確認なしで書き換わる。`--mirror` は遠隔にしか無い ref も消す。`grep -iE "force|mirror|--delete"` を `.claude/hooks/` と `.githooks/` にかけても0件だった。CLAUDE.md 28行目の「force push、`git reset --hard` はフックと permissions で止めている」も事実と違う。止めているのは permissions だけだ。

逆向きの誤りもある。`git push -u origin fix-f` と `git push origin harness-f` は `Bash(git push*-f)` に当たって deny になり、`c++fix` のように `+` を含むブランチ名も deny になる。困るのは名前を変えるくらいで、軽い。

最小の手当ては `guard-prod.sh` に push の判定を足すこと。`git` のあとの `-c`、`-C` を読み飛ばし、`push` の引数を語に分ける。`lib.sh` の `shell_words` が使える。止めるのは次のもの。
- block にするもの: `f` を含む短いフラグの束、`--force*`、`--mirror`、`+` で始まる refspec
- ask にするもの: `--delete`、`-d`、`:` で始まる refspec、宛先が main の push

テストには `-fu`、`-uf`、`--mirror`、`--delete`、`:main`、`HEAD:main`、`git -C . push -f` を足す。

**3. allow の `git -c credential.helper= * push*` は、push 以外の git のコマンドや任意のプログラムの実行も黙って通す(中くらい。確からしさ高い)**
`.claude/settings.json` 46行目。

`*` が引数の手前にあるので、その位置に別のサブコマンドが入る。文書は `Bash(git * main)` を例に、この形を「startup warning」の対象としている。照らした結果はこうなった。
```text

git -c credential.helper= rm -rf . push                    => allow
git -c credential.helper= -c core.sshCommand=evil push     => allow
```
`core.sshCommand` を使えば任意のプログラムが走る。`core.hooksPath` だけは `guard-private.sh` が止める。リポジトリの中でこの形を使っている所は、テスト(`scripts/test-hooks.sh` 135〜141行目)と文書しか無かった。消すか、実際に使う1つの形をそのまま書いた規則にするのがよい。例は `Bash(git -c credential.helper= -c "credential.helper=!gh auth git-credential" push *)`。テストの `rule allow 'git -c credential.helper= -c credential.helper=x push ...'` は、この広い allow をそのまま正しいものとして固めてしまっている。

### 確かめて問題なかったこと
- 文書(permissions)の照らし方との対応。deny、ask、allow の順で最初に当たったものが決まり、規則の細かさで順は変わらない。複合コマンドは分けてから照らし、deny と ask はどれか1つのサブコマンドに当たれば効く。`*` は空白を含むどの文字にも当たり、末尾の ` *` は引数なしの形にも当たる(`*` がそれ1つのときだけ)。`perm` は、複合コマンドの分割、ラッパーの除去、`:*` をまねていない。それでもテストは単純なコマンドしか使っていないので、結果は変わらない。
- ask の `gh api *-X DELETE*` などの4行は、allow の `gh api *` より先に当たる。フックは `-X "DELETE"`、`--method Delete`、`--method=DELETE`、`-XDELETE`、`-X 'delete'` を ask にした。
- `wrangler secret delete`(空白が2つの形も)と `versions secret delete` は ask になる。wrangler の削除系と time-travel restore は block のまま。
- `deleted_at` を DELETE と数えない。`--command`、`--file=`、`--file '...'`、相対の道筋、`cd` の先の相対ファイルも読む。
