## 指摘

1. 設定を読めなかったときに切り替えると、切ったはずの知らせが勝手にオンに戻る(軽い、確からしさは高い)
   場所は [`ios/App/Views/FamilySettingsView.swift`](ios/App/Views/FamilySettingsView.swift) の `update`(263〜267行)と、[`ios/App/AppModel.swift`](ios/App/AppModel.swift) 295〜311行の `loadMemberSettings` と `setMemberSettings`。
   たとえば姉が前に「笑顔が届いたとき」をオフにしていたとする。そのアプリを起動して最初に設定を開いたとき `GET /members/me/settings` が通信の失敗で落ちると、`try?` で何も言わずに既定の「両方オン」が画面に残る。その状態で「笑顔が届かないとき」だけを切ると、`PUT` は2つとも送る(`{smileNotify:true, smileMissedNotify:false}`)ので、裏側の `smile_notify` が1に戻る。
   危ないカードには関係せず、知らせが増える向きなので安全の面の害はない。直すなら、裏側はもともと片方だけの本文を受けるので、変えたキーだけを送るのが手軽だ。同じ理由で、2つを素早く続けて切り替え、答えが逆の順に戻ったときも、画面が古い答えに戻ることがある。

2. マイグレーションの番号 `0012` が PR #284 の `server/migrations/0012_case_hidden.sql` と重なる(軽い、確からしさは高い)
   今の `origin/main` は `0011_consult_summary.sql` までだ。wrangler の D1 マイグレーションは名前の全体で当てたかどうかを覚え、Vitest の `readD1Migrations` も全部のファイルを読む。なので、2つともマージされても動かなくなるわけではない(2本の試験で 836 件が通ることを確かめた)。ただ、同じ番号が2つあると適用の順が名前の並びで決まり、次の番号を選ぶときにも迷う。後からマージする側を `0013` に付け替えるのがよい。どちらの列も互いに依存しないので、順番で壊れることはない。

3. [`docs/plan.md`](docs/plan.md) の `POST /smiles` の行(161行)が「送ると本人のほかの家族全員に」のまま残っている(軽い)
   切った人を除くことは `GET、PUT /members/me/settings` の行に書いてあるので、約束として食い違っているわけではない。ただ、`POST /smiles` の行だけを読む人には分からない。`PUT /families/me/smile-deadline` の行と同じように一言足すと揃う。

## 確かめて問題なかったこと

- 危ないカードと自己点検と参加の知らせは、この設定で切れない。送り先を選ぶ問い合わせを `grep` で全部見た。新しい列を見るのは `server/src/smiles.ts` の `tellOthers`(156行)と `notifyMissedSmiles`(310行)だけだ。`judge.ts:313`、`gmail.ts:282`、`heartbeat.ts:57` と `138`、`families.ts:121`、`cases.ts:198` は変わっていない。相談のカードについては `server/test/consult.test.ts` の新しい試験が、2人とも両方切っても2人に「危ない」が届くことを確かめている。参加の知らせと通知の許可が切られた知らせは `smiles.test.ts` で確かめている。
- 母の端末は `GET` も `PUT` も403 `family_only` になる。試験もある。`tellOthers` では母にも `smile_notify = 1` が要るが、母は列を変えられず、既定が1なので、母への笑顔の通知はこれまでどおり届く。
- マイグレーションの既定値は `NOT NULL DEFAULT 1 CHECK (... IN (0, 1))` だ。すでにいる家族は2つともオンのまま始まるので、今の知らせは止まらない。
- 締めの時刻は家族で1つのまま(`families.smile_deadline_hour`)。日付の確保(claim)は送り先を絞る前に行うので、全員がオフでも1日1回の決まりは崩れない。
- オフの人は時刻を変えられない(Picker を `.disabled`)。この判断は妥当だと考える。家族で1つの時刻を、知らせを受けない人が動かすと、受ける人の知らせだけが変わる。全員がオフなら時刻を変えられないが、そのときは知らせを受ける人もいない。
- `PUT` の本文は検査されている。空の本文、真偽でない値、`null`、配列は400 `settings_invalid` になる。`COALESCE` で、名指ししたキーだけが変わる。デバイスキーが無ければ401になる。
- docs/plan.md の D1 の表と API の表、docs/design.md の家族の画面の段落は、実装と合っている。
- 画面の文言は名札と切り替えだけだ(「設定」「笑顔が届いたとき」「笑顔が届かないとき」「時刻」「◯時」「閉じる」)。説明は `accessibilityHint` に移した。
- 公開の記録に個人の情報は無い。dev-log の見出しは日付だけで時刻は無い。試験の名前の「母」「弟」は役の名前だ。
- 注入の経路は見当たらない。設定は本人のデバイスキーの行だけを変え、送り先と段階はメッセージの本文から決まらない。
- 自分で走らせた確かめは3つで、どれも通った。`npx tsc --noEmit` はエラーなし。`npx vitest run test/smiles.test.ts test/consult.test.ts` は 836 件。`swift test --filter SmileAPITests` は 14 件。
