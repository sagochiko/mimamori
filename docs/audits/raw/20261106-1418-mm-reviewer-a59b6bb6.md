## 確かめて問題なかったこと

- 固定の時刻と締切の範囲は合っている。`notifyMissedSmiles`(`server/src/smiles.ts` 231行目から)が対象にするのは、`midnight + smile_deadline_hour*3600000 <= now` を満たし、しかも守られる人の `created_at` がその締切より前の家族だけだ。このファイルの家族は、止めた時計の15:00 JST に作られる。締切は最大でも12:00 なので、tick の `now` が15:00でも15:10でも、作成が締切より前という条件を満たさない。どの家族も対象に入らない。
- 再現と修正の効き目を自分で確かめた。HEAD の `server/` を `git archive` でスクラッチに取り出し、作業の木の `node_modules` をリンクして、固定の時刻だけを書き換えて `npx vitest run test/cases.test.ts` を流した。作業の木のファイルは変えていない。結果は次のとおり。
  - 15:00(PR のまま)では `Tests  40 passed (40)` だった。
  - 08:56(既定の9時の締切の直前)では2件落ちた。1件は Issue と同じ `after 30 minutes without '解決' ... once` で、`expected [...] to have a length of +0 but got 52` が出た。もう1件は `tells the family about a case the queue gave up on, at the next tick, once` で、`... but got 10` が出た。PR の本文には「40件中1件が落ちた」とあるが、私の再現では2件だった。どちらも同じ原因(笑顔の届かない知らせが `sent` にたまる)で落ちており、この修正で両方とも通る。PR の本文の件数は直しておくとよい。
  - 12:00(締切の上限ちょうど)では40件通った。`created_at < 締切` が厳密な不等号なので通る。
  - 23:55(tick の+10分が JST の日付をまたぐ)では40件通った。翌日の00:05はどの締切より前なので、対象に入らない。
- 試験は今も落ちうる形のままだ。上の08:56の実行で、見張りの「2回目は送らない」という確かめ(`expect(sent).toHaveLength(0)`)が実際に落ちた。`sent` を数える確かめは、余計な送信があれば今も捕まえる。
- Date だけを止めても、ほかの試験は意味を失っていない。
  - claim の期限の試験(404行目)は `recent = Date.now() - CLAIM_TTL_MS + 60_000` と `Date.now() - CLAIM_TTL_MS - 1000` を明示の値で作り、`tick(Date.now())` に渡す。時計が止まっていても差は同じで、TTL の内側と外側を両方とも確かめている。
  - 30分の見張り、1日を過ぎた案件、31日前のセッションの片付けの試験は、どれも `backdate` や `Date.now() - N` で時刻の差を明示している。時刻が進むことには頼っていない。
  - `toFake: ["Date"]` なので setTimeout などのタイマーは本物のままで、待ちで止まる心配はない。`afterEach` の `vi.useRealTimers()` で戻しているので、ほかのファイルにも漏れない。
  - 時計を止めると同じ時刻の行が並び、順番がぶれうる。そこで `ORDER BY c.notified_at` が出てくる箇所(`src/cases.ts` 130、378、445行目)と試験の確かめ方を見た。一覧の試験は `find`、`toContain`、家族が1件だけの `toEqual([mine])` で確かめていて、同じ時刻の並び順には頼っていない。家族の端末が無い25件の試験は、`now - 60_000 + i` と10分前の backdate で時刻を分けている。
- 計画と設計の約束(段階、「安全」と言わない、だれに知らせるか、母への答え、本文を家族に出さない、30日の削除)に触れる変更はない。秘密、実在の家族の情報、外から写したものも入っていない。`ios/Core` にも変更はない。
- tick を流すほかの試験も見た。`test/data.test.ts` は固定の `cleanupTick` を渡し、送信の数を数えていない。`test/smiles.test.ts` は笑顔の知らせそのものを試す側だ。どちらもこの PR の範囲外で、同じ落ち方が出る形には見えなかった。
