## 指摘

### 1. 声で聞いた「大丈夫」「大丈夫よね」が挨拶として扱われ、確かめたいという問いが前の話から切り離される(重い。コードの道は実測で確かめた。Claude の答え方は推測)

[`server/src/consult-judge.ts`](server/src/consult-judge.ts) の1018行目の `NOTHING_WORD` には `大丈夫|だいじょうぶ` が入っていて、語尾に `ね` と `よ` を許す。問いかどうかは1022行目の `/[?]/` だけで見ている。ところが、母の主な入力の声は [`ios/App/VoiceListener.swift`](ios/App/VoiceListener.swift) の `SFSpeechAudioBufferRecognitionRequest` で文字にしていて、`addsPunctuation` を設定していない(`grep` で1件も無い)。Apple の既定ではこれは偽なので、声で聞いた「大丈夫?」は `?` の付かない「大丈夫」として届く。

ブランチの上で `npx tsx -e` から `saysNothing` を呼んだ結果がこれだ。

```text
"大丈夫" true
"大丈夫ね" true
"大丈夫ですね" true
"大丈夫よね" true
"うん大丈夫" true
"はい大丈夫です" true
"大丈夫？" false
```

起きる場面はこうだ。警察の筋書きか息子を名乗る電話のあとで、母がマイクに向かって上がり調子で「大丈夫よね」と聞く。これは、言われたとおりにしていいかを確かめる問いだ。それが `saysNothing` に当たるので、Claude には前のやり取りが渡らず、「大丈夫よね」という言葉だけで答えることになる。直す前なら前の詐欺の話を踏まえて「家族に確かめるまで待って」と返せたが、今は3段階の一般の返事になりうる。前の相談が解決済みなら、家族にも知らせが届かない。`soundsSafe`(165行目)が「大丈夫です」を言い換えるので「安全です」とは返らない。それでも、いちばん止めたい瞬間にもう一度注意する機会が消える。

試験はこの穴を正しいものとして固めている。[`server/test/consult.test.ts`](server/test/consult.test.ts) の表は `["大丈夫", true]` と `["大丈夫です", true]` を通し、`["大丈夫?", false]` で問いを分けた気になっている。けれど声の道では `?` は来ない。

直し方は、`大丈夫` と `だいじょうぶ` を `NOTHING_WORD` から外すことだ(`ok` と `おっけ` も、確かめの返事として同じ形で使われうる)。合わせて、語尾の `ね` と `よ` は確かめの問いになりうるので、少なくとも相づちの語には付けない。試験には、筋書きのあとの「大丈夫よね」で前のやり取りが Claude に渡ることを足す。[`docs/design.md`](docs/design.md) の209行目の例示「大丈夫」と、同じ行の「失うのは、挨拶やお礼の言葉で Claude が前の話を踏まえた返事をしなくなることだけだ」も、直したあとの形に合わせる。

## 確かめて問題なかったこと

- 向きを逆にした直し。1084行目の `ask(rule, saysNothing(text) ? [] : history)` で、`saysNothing` に当たらない言葉は直す前と同じく前のやり取りが渡る。1回目に挙げた「上司の人が取りに来るらしい」「キャッシュカードを預けてって」などの9件は、`seen` が `[son]` であることと、家族に1段階が届くことを見ている。偽の Claude は前を見せられたときだけ1段階と答えるので、1回目の形(`goesOn` が偽なら `[]`)では落ちる。試験はモック自身を確かめるだけのものになっていない。
- 中身のある言葉の取り違え。`はい、お願いします`、`わかった、振り込む`、`大丈夫だよね`、`ほんとに大丈夫`、`ええっ`、`はい100` は偽だった。ほかの語が1つでも入れば外れる。`\p{M}` は `NFKC` のあとに消すので、`は` に結合の濁点が付いた形は `ばい` に合成されて偽になり、別の語を挨拶にする穴にはならない。`\p{S}` で `¥` などの記号が消えても、数字(`\p{N}`)は残るので金額は外れる。ゼロ幅の文字(`\p{Cf}`)を挟んだ `はい` が真になるのは、意味が変わらないので害は無い。
- 「はい」「うん」「わかった」「了解」「うーん」「はーい」だけの言葉が真になるのは、前の答えへの返事として読んで差し支えない。
- #219 の場面。筋書きのあとの「おはよう」「ありがとう」は今も `[]` で聞き、家族に2枚目のカードが届かない試験が通る。
- 下限と注入。`earlierKeepsOut` は `goesOn` の条件のままで変わらない。`plan()` の `earlierSteers` は全部の `history` を見る。
- eval。eval/lib/score.ts は `history` に `[]` を渡すので、測る経路は変わらない。
- [`docs/plan.md`](docs/plan.md) の153行目には、挨拶、お礼、相づちだけのときに渡さないという条件が入った。design.md に残っていた「#219 のあとは、メッセージや電話の話か…」の古い文は、今の版には無い(`grep` で確かめた)。dev-log の追記は、1回目の形を捨てた理由と9件の試験を書いていて、事実と合う。
- `npx tsc --noEmit` は通った。`npx vitest run test/consult.test.ts test/rules.test.ts` は `Tests 1008 passed (1008)` だった。
