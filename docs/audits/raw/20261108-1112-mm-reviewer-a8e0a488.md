## 指摘

1. 家族のカードのボタンが画面の下の外にあると、「次へ」が画面の外に出て、家族の画面が動かせなくなる。確度は中(コードから計算した。シミュレータでは再現していない)
   [`ios/App/Views/OnboardingGuide.swift`](ios/App/Views/OnboardingGuide.swift) の `CoachMarkOverlay` は、照らす部品の位置を `frame(in: .global)` で測り、`below = hole.midY < proxy.size.height / 2` が偽なら吹き出しを穴の上に置く。下の余白は `.padding(.bottom, proxy.size.height - hole.minY + 13)` で決まる。`hole.minY` が画面の高さより大きいと、この値は負になる。暗い面は `.contentShape(Rectangle())` と `.onTapGesture {}` で画面のすべての触れ方を吸うので、`ScrollView` を動かしてボタンを画面に入れることもできない。
   起きる場面。家族のホーム([`ios/App/Views/FamilyHomeView.swift`](ios/App/Views/FamilyHomeView.swift) の `JoinedSection`)は、上に最大280pt の今日の笑顔と名前、その下にカードが新しい順に並ぶ `ScrollView` になっている。照らすのは解決していない一番上のカード(`guidedCardID`)なので、それより新しい解決済みのカードが上にあると、照らすボタンはさらに下へずれる。iPhone SE の高さ(667pt)、文字を大きくした設定、AI の答えが長いカードのどれかが重なると、「電話する」の段で吹き出しの上の端(穴の上の端から約143pt 上)まで画面の外に出る。閉じるボタンが無いので、アプリを終わらせるまで何もできない。記録は出し始めたときに付いているので、次に開けば出ないものの、初めての1回が固まる。
   直し方の案。その段に入る前に `ScrollViewReader` で照らす部品を画面の中へ動かす。あるいは、吹き出しの置き場を画面の中に収め、穴が画面の外なら上に寄せる。

2. 起動したときの道筋が一瞬でも `.chooseRole` だと、見た記録が消える。確度は低から中
   [`ios/App/Views/RootView.swift`](ios/App/Views/RootView.swift) の `.task(id: GuideKey(...))` は、最初に出たときも `guide.start(for: model.route, ...)` を呼ぶ。`OnboardingGuide.start` は `.chooseRole` を受けると、そのたびに `record.forget()` で UserDefaults の記録を消す。`Session.init` のコメントにあるとおり、再起動のあと最初のロックを解く前は Keychain が空に見え、道筋は `.chooseRole` になる。`AppModel` はこれを見越して、道筋が実際に変わったときにしか忘れない(`onRouteChange`)。会話を消す処理も `isProtectedDataAvailable` で守っている。吹き出しの記録だけはこの守りが無いので、ロックの解ける前に画面ができると母の記録が消え、次に開いたときに吹き出しがもう一度出る。害はもう一度出るだけで、母が困るほどではない。それでも、ほかの「忘れる」処理と同じ守り(道筋が変わったときだけ忘れる、または `isProtectedDataAvailable` を見る)にそろえるほうがよい。

3. 照らしていた部品が消えても `frames` に古い位置が残る。確度は中、影響は小さい
   `frames` は足すだけで消さない。家族が「電話する」の段にいるあいだに、別の家族がそのカードを解決するとボタンは消える。それでも穴と吹き出しは古い位置を指したまま残る。「次へ」は押せるので、固まりはしない。
