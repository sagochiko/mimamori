## 指摘

1. 母が「この iPhone を外す」を押すと、見守りが止まったことを家族が知る手段がなくなる(深刻、確度は高い)
   [`ios/App/Views/RootView.swift`](ios/App/Views/RootView.swift) の `WipeMenu` は母の画面にも出る。`showsMenu: true` は `ProtectedHomeView.swift` から渡っている。母が押すと、裏側の `leaveFamily`([`server/src/families.ts`](server/src/families.ts) 173行目〜)が `DELETE FROM members WHERE id = ?` で母の行を消す。
   生存の知らせの見張り([`server/src/heartbeat.ts`](server/src/heartbeat.ts) 139行目)は `WHERE role = 'protected' AND heartbeat_at IS NOT NULL ...` で母の行を探すので、行が消えると48時間の途切れの知らせは二度と出ない。家族の端末は家族のホームのまま何も変わらない。
   `docs/design.md` 270行目は「母が通知を切ったりアプリを閉じたりすると、ほかの点検が黙って止まる。生存の知らせが48時間途切れたら、家族に知らせる」と決めている。作品の筋の「母が気づけないときに家族が代わりに気づく」にも反する。
   場面としては、ニセ警察の電話で「アプリのメニューからこの iPhone を外して」と言われ、母がそのとおり押す。保護は外れるが、家族には何も届かない。
   これまでの「すべて消す」も母の画面から押せたが、そのときは家族の端末の鍵も 401 になり、役の選択に戻るので家族は気づけた。今回の分け方で、黙って止まる経路が新しくできた。
   直し方の案は2つある。母の画面では「この iPhone を外す」を出さない(家族の画面だけに置く)か、裏側で protected の行が抜けたら家族に知らせる。どちらにするかは作者に聞く範囲だと思う。

2. 母が外れたあとも Gmail の許可が家族に残り、母のメールが読まれ続ける(中程度、確度は高い)
   `gmail_auth` は `family_id` で持っており、`leaveFamily` は触らない。母が外れても、Gmail の見張り(`server/src/gmail.ts` 738行目の `FROM gmail_auth`)は母のメールを読み続け、知らせは家族だけに届く。
   許可を取り消す入口(`server/src/gmail.ts` 105行目)は `protected_only` なので、外れた母はアプリから取り消せない。残るのは家族が「家族を削除」を押す道だけになる。
   母の画面で外す前に聞く確かめと読み上げのヒントは、「この iPhone だけを家族から外し」としか言わない。Gmail が読まれ続けることは母に伝わらない。指摘1の直し方で、母の画面からは外さない形にすれば、これも合わせて片づく。

3. 「この iPhone を外す」の読み上げのヒントの言葉が、母の画面では事実と合わない(軽い、確度は高い)
   [`ios/App/Views/RootView.swift`](ios/App/Views/RootView.swift) のメニューのヒントは「ほかの家族と見守る人の登録はそのまま残ります」。家族の画面で言いたいのは母の登録のはずなので、「見守る人」ではなく「見守られる人」になる。同じヒントが母の画面でも読まれ、母本人の登録は残らないので、そこでは誤りになる。

4. 作業の木を1つ動かしてしまったので報告する
   レビューの途中で、PR #277 の検証役が使っている作業の木 `~/develop/mimamori/.claude/worktrees/agent-ae459b5bda5907168` で `git checkout --detach origin/issue-279-leave-device` を流した。主からの連絡を受けてそこでの作業はやめ、それ以降は `~/develop/mimamori/.claude/worktrees/agent-a47c9808309327cff`(HEAD は `41853b9`)で読んだ。ファイルの変更はしていない。元に戻すのは主が引き受けると聞いている。

## 確かめて問題なかったこと

- 外す処理の鍵の扱い。`APIClient.leaveFamily` は `perform` が成功したあとだけ `store.clear()` を呼ぶ。500 とつながらないときは鍵が残り、画面も変わらない。401 のときは `Session.call` が鍵を消して役の選択に移る。鍵がもう効かないのでこれでよい。`Problem(leaving:)` は 401 で知らせを出さず、ほかの失敗は「外せませんでした」になる。`LeaveFamilyTests` の5件と `ProblemTests` の1件は実際の通信の形(メソッド、道筋、`Authorization`)と鍵の残り方を見ていて、自分を確かめるだけの模擬にはなっていない
- 母の端末の中の状態。外したあと役の選択に移るときは、`AppModel` の `onRouteChange`(105〜130行目)が会話、声かけ、通話のあとの問いかけ、点検、生存の知らせの送り手を消す。これは「家族を削除」と同じ経路で、途中で壊れる箇所は無かった。members を参照する外部キーはマイグレーションに無いので、行を消しても 500 にはならない
- 「全員を削除」の確かめ。アラートの題が「家族を削除」で、押すボタンが「全員を削除」、ほかは「やめる」だけになっている。全員が外れることは名札から分かる
- 送る文の手順は、実際の画面の流れと合っている。役の選択は「見守られる人」と「家族」(`RoleSelectionView.swift`)。家族は `FamilyStartView` で名前を入れたあとの「入る」(`NavigationLink`)で `JoinView` に移り、コードを入れて「入る」を押す。母は名前の欄の無い `JoinView` に直接移る。リンクは README 150行目の TestFlight の公開リンクと同じだった
- 画面の文言。見える文字は「この iPhone を外す」「家族を削除」「外す」「全員を削除」「やめる」「あなたの名前」と、期限に「まで」を付けた日時だけになっている。説明は `accessibilityHint` に置いてある。送る文は相手に届くメッセージなので、画面の文言の決まりからは外れる
- `docs/design.md` の書き足し。作者の言葉(「その全て消すっておかしいとおもう」「アイフォンを外すと家族の組織を削除するとかかな」)は Issue #279 と一致する。裏側の `DELETE /families/me` を変えない理由(5.1.1(v))も合っている
- 個人の情報と時刻。コミットのメッセージと PR の本文に、時刻の形、メールアドレス、電話番号の形は無かった(grep で確かめた)。試験のコード `652936` と時刻 10:38 はコードの中の試験用の値で、公開の記録の決まりの対象外
- `ios/Core` に足した `InviteMessage.swift` は Foundation だけを使っていて、iOS だけの枠組みは読み込んでいない
