## 指摘(重い順)

1. 低い(確からしさ高い、ただしこの Mac では今は起きない)。[`Makefile`](~/develop/mimamori/.claude/worktrees/harness-sim/Makefile) の59〜61行目。機種が違う「mimamori iPhone」が残っていると、知らせを1行出すだけで終了コードは0になる。そのため [`.claude/skills/mm-ios-verify/SKILL.md`](~/develop/mimamori/.claude/worktrees/harness-sim/.claude/skills/mm-ios-verify/SKILL.md) の次の手順(`simctl boot "mimamori iPhone"`、`-destination 'platform=iOS Simulator,name=mimamori iPhone'`、install、screenshot)がそのまま流れる。iPhone Duo だけが残っている場合は、Duo で撮られてしまう。両方残っている場合は同じ名前が2台になり、xcodebuild は先に見つけた方を使い、simctl も名前でどちらか1台を選ぶ。ビルドした機体と撮った機体が食い違うおそれがある。mm-verifier(Sonnet)が数行の出力の中の知らせを読み落とすと気づけない。PR の本文とコメントは「知らせて続ける」をわざと選んでいて、作者の決定と矛盾はしない。ただ、続けても正しい画面が撮れない場面なので、`|| { echo ...; exit 1; }` で止める方が安全だと思う。今この Mac にある「mimamori iPhone」は、使えないものを含めて iOS 26.5 の iPhone 17 Pro の1台だけで、実際には起きない。
2. 低い(確からしさ高い)。同じ Makefile の61〜62行目。知らせは `xcrun simctl delete <udid>` を勧めている。ところが最後の `grep "mimamori iPhone"` の出力には udid しか出ず、機種もランタイムの見出しも出ない。両方残っている場合、どちらの udid を消せばよいか出力からは分からない。正しい方を消してしまう余地がある。jq で `select(.deviceTypeIdentifier != $t) | .udid` を出せば防げる。jq が無いときや JSON が壊れているとき(jq の終了コードは127や5)も、同じ「別の機種がある」という知らせになる。ただ、前の版も jq が必要だったので軽い。

## 確かめて問題なかったこと
- Make の展開。`make -n simulator` の結果、`$$t` は jq の中で `$t` になり、単引用符の中なのでシェルには展開されない。`$(SIM_TYPE)` と `$(SIM_RUNTIME)` は make が展開する。`{ ...; exit 1; }` はレシピのシェルを抜けて make を失敗させる。
- 4つの場合の動き。作り物の `xcrun` を PATH の先頭に置いて確かめた。
  - シミュレータが無いときは、iPhone-17-Pro と iOS-26-5 で `create` を1回呼び、「created mimamori iPhone」と出して終了コード0
  - 正しい機種があるときは、作らずに一覧を出して0
  - iPhone Duo だけ、または両方あるときは、知らせを出して0(指摘1)
  - ランタイムが無いときは、simctl のエラーと「could not create ...」を出して make が Error 1
- `jq -e` に空の配列を渡すと `all` が true で終了コード0になる。名前が一致する機体が無くても誤って知らせは出ない。`.devices[][]` と `deviceTypeIdentifier` は実際の `simctl list devices available -j` の形と合っている。
- `ios/project.yml` の `deploymentTarget` は iOS 26.0で、pbxproj の `IPHONEOS_DEPLOYMENT_TARGET` も2か所とも 26.0。`ios/Core/Package.swift` は `.iOS(.v17)`。どれも 26.5 で動く範囲に収まっている。Swift のコードに `available(iOS 27` は無い。
- iOS 26.5 のランタイムは iPhone-17-Pro を `supportedDeviceTypes` に持っている。iOS 27.1 の方は iPhone-Duo の1つだけ。PR の説明と合っている。
- iOS 27.1 や iPhone Duo を前提にした記述が残っていないか。.claude/skills、agents、hooks、checklists、rules、settings.json、docs、Makefile、scripts、CLAUDE.md を grep した。残っているのは次のものだけで、どれも画面確認の前提ではない。
  - mm-ios-verify の8行目の「Xcode 27.1」(Xcode の版で正しい)
  - mm-release の Xcode 27.1 での計測の話
  - mm-human-queue の作者の端末の iOS 27.2
  - design.md と plan.md の「iOS 27 の提供状況」のリンク
  - dev-log と audits の過去の記録
- 文書と動きの食い違い。SKILL.md の17行目に書かれた次の点は、どれも Makefile の動きと合っている。
  - iPhone 17 Pro と iOS 26.5 で1度だけ作る
  - アプリは iOS 26.0 から対応する
  - 別の機種なら知らせが出るので、消して流し直す
- 個人情報、秘密、外から写したものは差分に無い。
