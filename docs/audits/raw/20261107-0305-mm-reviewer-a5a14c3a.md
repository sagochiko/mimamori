## 確かめて問題なかったこと

- `bash scripts/test-hooks.sh` は終了コード0で、失敗の行は0件だった。
- 例外の形は抜けないと判断した。どちらの形も `^...$` で行全体に合わせている。語に使える文字は `[A-Za-z0-9_./~:,+-]` だけで、区切りは半角の空白1つに限られる。なので、改行、タブ、`|`、`;`、`&`、`>`、`$`、バッククォート、引用符、`*`、`?`、`[`、`=` は入らない。`=` が入らないので、xcodebuild のビルド設定(`NAME=value`)や既定値の上書きも書けない。タブや改行を入れた行は例外に入らず、残りの `.p8` と `AuthKey_` で今までどおり止まる。
- 鍵を2つ書いた行も止まる。`sed` は最初の1か所しか消さないので、`-exportOptionsPlist`、`-exportPath`、`-archivePath` のどれに鍵の道筋を書いても、どちらかの `AuthKey_` が残る。
- 鍵の道筋は必ず `~/` で始まる形にしてあり、`~user/` や絶対の道筋で書くと例外に入らずに止まる。`~` は語の頭に来るので、シェルでは家のフォルダに展開される。
- `mv` の行の後ろに `&&`、`;`、`|`、改行で何かを足すと、`$` の固定で形から外れて止まる。これは例でも確かめられている。
- 例外は `tool_name` が `Bash` のときだけ効く。Monitor、Read、Grep には効かず、Monitor の例もある。`.claude/settings.json` の matcher は `Read|Grep|Glob|Bash|Monitor|Edit|Write|NotebookEdit|WebFetch` だった。
- 例外に入った行は `targets` を `cmd` から作り直す。そのため、`.dev.vars.example` の除去と、バックスラッシュで続く改行の扱いは使われない。ただ、形がバックスラッシュも改行も許さないので、穴にはならない。
- SKILL.md の4が `-authenticationKeyPath` などを xcodebuild 自体の引数として扱っている点は、本文が引く `man xcodebuild` と `xcodebuild -help` の説明と合っている。鍵の中身を読まない決まり(`cat`、`head`、`grep`、Read、コピーをしない)とも合っている。
- CLAUDE.md に足した1文は「中身を読まずに道筋だけを渡す」で、「秘密の値は読まない」と食い違わない。
- 鍵の ID と Issuer ID は、鍵の中身が無ければ使えないので、公開してもよいと判断した。チームの ID は CLAUDE.md で公開してよいとされている。
