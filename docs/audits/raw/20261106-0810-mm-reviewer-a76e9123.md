## 指摘

1. 2回目の指摘1は半分しか閉じていない。伸ばし棒で書いた呼びかけが、まだ前を指すと読まれない(確度は高い。発話でどれだけ出るかは中くらい)
   場所は [`server/src/consult-judge.ts`](server/src/consult-judge.ts) の425行目の `POINTS_BACK` と、[`ios/Core/Sources/MimamoriCore/Chat.swift`](ios/Core/Sources/MimamoriCore/Chat.swift) の117行目。
   正規化と記号を落とす処理を同じにして node で流した結果がこれ。`ー`(U+30FC)は文字の扱いなので消されずに残り、一覧のどの語にも当たらない。
   ```text
   えーっと、それってなに false
   えーと、それってなに   false
   あのー、それってなに   false
   ねー、それってなに     false
   ```
   一覧には「えっと」「ええと」「あのう」「ねえ」があるのに、伸ばし棒の形の「えーっと」「えーと」「あのー」「ねー」が無い。年配の人の話し言葉では、どれも「あのう」と同じくらいかそれより多く出る。たとえば母が前の回に警察を名乗る電話の話をして、次に「あのー、それってなに」と聞いたとする。このとき前の回の言葉が話題の語(`topicWords`)に入らない。`namesSomething` も `!pointsBack` で true になるので、#114 の「前を指すだけ」の道にも乗らない。端末も前の日の会話を送らない。結果は2回目に採った指摘1とまったく同じ壊れ方になる。
   直し方は、両方の正規表現に `えーっと|えーと|あのー|ねー` を足し、[`server/test/fixtures/points-back.json`](server/test/fixtures/points-back.json) に上の4つを true の例として入れること。長い語を先に置く並びのまま入れればよい。

## 確かめて問題なかったこと

- 両側の正規表現は1文字まで同じ。2つのファイルから `/^(ねえ…方))/` を抜き出し、シェルの文字列比較で `SAME` と出た。`NEW_TOPIC` と15文字の上限も変わっていない
- 呼びかけを重ねた例は正しく読めた。「ええ、えー、それってなに」「うーん、うん、それってどういうこと」「えっ、えー、じゃ、それって」「うーんどうすれば」「え〜それってなに」(`〜` は記号として消える)はどれも true。どちらの正規表現の仕組みも後戻りして探すので、並びは最初に試す順を変えるだけで、当たるかどうかは変わらない
- 2回目で挙がった新しい話は前を指さないままだった。「おそれがある」「だれそれ」「そうじ」「えいが」「ええかげん」「ええかげんにして」「ええこと」「じゃそうする」はどれも false
- 「え」「じゃ」を足して新しく true になる道は、「えそれ」「えあれ」「じゃこのやつ」くらいだった。どれも前の会話が余計に付く側にしか倒れない。`namesSomething` では語の一覧と警察の言い回しの照合が `||` でつながっているので、段階の下限や知らせが弱まる道にはならない。止めるものではない
- 共有の例の一覧に足した6件(え、えー、うーん、ええ、あのう、じゃ)は、端末側の `ChatTests.swift` の257行目からも読まれている
- テストは両側とも通った。`server` の Vitest は `Tests 1171 passed (1171)`、`ios/Core` の `swift test` は `Test run with 250 tests in 39 suites passed` だった
