## 指摘

1. 「〜かと思います」の形の言い切りが、問いとして素通りする。確度は高い(node で正規表現を流した)。
   場所は `server/src/claude.ts` の82行の `NOT_ASKED = "(?!(の|です|でしょう|だろう)?か(?!ら))"`。「から」は外したが、「かと思います」の「か」も問いとして除いている。手元で流した結果は次のとおりで、旧の正規表現でも同じく素通りしていた。
   ```text
   MISS 大丈夫かと思います
   MISS 問題ないかと思います
   MISS 心配ないかと思います
   ```
   Claude は日本語の理由を「〜かと思います」でぼかして書くことが多い。3段階の SMS に `reasons: ["いつもの銀行の番号なので問題ないかと思います"]` が返ると、`decide`(208行)がこの理由を残し、母の通知と家族のカードに載る。プロンプトの277行は「問題ない」「心配ない」を書かないよう頼んでいるが、この網はその2枚目の壁にあたる。
   直すときは、「かと」をまとめて問いにしないほうがよい。「大丈夫かと家族に聞いて」は問いで、「詐欺ではないかと思います」は疑っている言い方なので、残すべき理由になる。たとえば `か(?!ら|と思|と存じ)` のように「かと思」だけを言い切りとして扱い、`詐欺(では|じゃ)` の枝だけ今の `NOT_ASKED` のままにする、という分け方がある。落ちる側の試験に「問題ないかと思います」「大丈夫かと思います」、残る側に「詐欺ではないかと思います」を足すとよい。

2. 「大丈夫なのか」が問いなのに消える。確度は高い(実測)。
   `NOT_ASKED` の任意部分に「の」はあるが「なの」が無い。そのため「本当に大丈夫なのか家族に確かめて」は `DROP` になった(旧の `大丈夫です(?!か)` では残っていた)。結果として、家族に確かめるよう勧める理由が規則の理由か `PLACEHOLDER_REASON` に替わる。段階は変わらないので安全の約束は破らないが、消しすぎではある。`(の|なの|です|でしょう|だろう)?` にすれば直る。

3. 言い換えの抜けのうち、軽いものを挙げる。どれも旧の正規表現でも素通りしていて、今回のコミットで悪くなったものではない。マージを止めるほどではないと見ている(確度は中)。
   ```text
   MISS 問題無いです / 心配無い / 危険は無い      (漢字の「無」)
   MISS 詐欺ではなかった / 問題なかった / 危険はなかった (過去形の「なかっ」)
   MISS 問題がないので / 危険がないので / 危険性がない   (「が」)
   MISS だいじょうぶです / 心配不要です / 問題ございません / 詐欺ではございません
   ```
   直すなら、`(ない|なさ|なし|なく)` を `(な[いさしくか]|無[いし])` に、`(は|も)?` を `(は|も|が)?` に広げる程度で済む。

4. 理由を消しすぎる件(参考。確度は高いが影響は小さい)。語幹の `大丈夫${NOT_ASKED}` にしたので、引用符の無い手口の説明が新しく消えるようになった。
   ```text
   DROP old:keep 相手が大丈夫と言って急がせる
   DROP old:keep 大丈夫だと言って口座を移させる
   DROP old:keep 問題なさそうに見せかけたリンク
   ```
   「詐欺ではないと言って」「心配ないと言って」は旧のときから消えていた。プロンプトの259行の例は手口の言葉を「」で囲んでいて、囲めば残る(試験の「「大丈夫です」と言って急がせる」が通る)。消えても段階は残り、規則の理由が代わりに入る。直すなら、プロンプトに「相手の言葉は「」で囲む」と一行足すほうが、正規表現で「と言って」を除くより安全だと思う。
