## 確かめて問題なかったこと

- 役の選択に戻ったときの片付け。[`ios/App/AppModel.swift`](~/develop/mimamori/.claude/worktrees/issue-190-wipe/ios/App/AppModel.swift) の78〜82行の `.chooseRole` の分岐で、`followUp.forget()`(`UserDefaults` の `mimamori.callFollowUp` を `removeObject`)、`followUpPrompt = nil`、`removeDeliveredNotifications(withIdentifiers: ["call-follow-up"])` が走る。`CallFollowUpNotifier.post()` は `trigger: nil` ですぐ届く通知なので、待ちの通知は無い。届いたものを消すだけで足りる。毎日の声かけの予約は、続く `cameToFront()` の `scheduleDailyCheckIns()` が `route != .protectedHome` のとき空で置き換える。
- 401 と家族を抜けたときに困る場面。`onRouteChange` は [`ios/Core/Sources/MimamoriCore/Session.swift`](~/develop/mimamori/.claude/worktrees/issue-190-wipe/ios/Core/Sources/MimamoriCore/Session.swift) の9行の `didSet` で、値が変わったときだけ呼ばれる。初期化の中の `route` の設定は、`onRouteChange` を入れる前に終わっている。なので、再起動のあと最初に解く前の起動(キーチェーンが空に読める間)で記録を誤って消すことは無い。鍵は `kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly` で、一度解いたあとは読めなくならない。参加中に `.chooseRole` へ移るのは、鍵が本当に消えたときだけになる。標準の `UserDefaults` は最初に解いたあとなら書けるので、`chat.clear()` のような `isProtectedDataAvailable` の守りが無くても困らない。鍵の無い端末に通話の記録を残す理由も無い。家族役の端末では記録はもともと空。
- 入り直したときの戻り。もう一度母役で入ると、`refreshFollowUp()` が消えた記録を読むので、古い「さっきの電話」は出ない。`lastAskedAt` も消えるので、その日の毎日の声かけが飛ぶこともない。
- `forget()` のロック。`CallFollowUp` の `lock` の中で `store.clear()` を呼ぶ。`InMemoryCallFollowUpStore` は別のロックを持ち、`UserDefaultsCallFollowUpStore` はロックを持たないので、二重に取って止まることは無い。`CallFollowUpStore` に従う型は、この2つのほかに無い(grep で見た)。
- 試験。`swift test --filter "DeleteEverything|CallFollowUp|DailyCheckIn"` を手元で流し、`Test run with 41 tests in 5 suites passed` だった。足した2件はどちらも落ちうる形になっている。401 の試験は `store.load() == nil`、`route == .chooseRole`、`log.routes == [.chooseRole]` を、`forget` の試験は直前に問いかけが出ることと、消したあと `nil` になって状態が初期値に戻ることを見ている。App の配線(`AppModel` の分岐)には試験が無いが、App のターゲットに単体試験の置き場が無いので、ここで求めるものではない。
- 笑顔の列と主役の相談の画面。[`ios/App/Views/ProtectedHomeView.swift`](~/develop/mimamori/.claude/worktrees/issue-190-wipe/ios/App/Views/ProtectedHomeView.swift) の91行は `HStack` をやめて `SmileStrip(..., showsMenu: true)` 1つに戻した。列は元のとおり幅いっぱいの `ScrollView` になる。メニューの高さはほかの項目と同じ72に揃えてあり、`alignment: .top` の列で高さがずれない。知らせの帯、通話のあとの声かけ、会話、下の欄には触れていない。家族の画面([`ios/App/Views/FamilyHomeView.swift`](~/develop/mimamori/.claude/worktrees/issue-190-wipe/ios/App/Views/FamilyHomeView.swift) の62行)は `SmileStrip()` のままで、既定の `showsMenu = false` のため列にメニューは出ない。家族の画面のメニューはツールバーの1つだけになる。
- `ios/Core` の import は Foundation のままで、`UserNotifications` は App の側([`ios/App/CallFollowUpNotifier.swift`](~/develop/mimamori/.claude/worktrees/issue-190-wipe/ios/App/CallFollowUpNotifier.swift))にだけある。差分に秘密、実在の家族のデータ、外から写したコード、注入された文が宛先や段階を変えられる経路は無い。
