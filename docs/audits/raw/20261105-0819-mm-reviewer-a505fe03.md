## 指摘(重い順)

### 1. 既定のシミュレータを書き換えたまま戻さない(直すべき)

`~/develop/mimamori/.claude/worktrees/harness-screen-guide/.claude/skills/mm-screen-guide/SKILL.md` の27行目で主のセッションに `session_set_defaults` で案内用のシミュレータを既定にさせ、70行目で一時の iOS 27.1 シミュレータを `xcrun simctl delete` させるが、既定を元に戻す手順がどこにも無い。

起きる場面。作者向けの手順を作るため、主のセッションが既定を「mimamori guide 27」に向け、終わりにその端末を消す。同じセッションでそのあと `/mm-task` を回すと、mm-verifier が mobilebuildmcp の既定で `build_run_sim` や `screenshot` を呼び、消した udid に当たって落ちる。`guard-mcp.sh`(PR #96)で検証役は既定を直せないので、報告で親に戻してもらうまで止まる。

根拠。今の既定を `session_show_defaults` で読んだところ `simulatorName: "mimamori mother"`、`simulatorId: 0E43CCD1-…` と名前と udid の両方を持っている。スキーマでも `simulatorId` は「materialized from simulatorName」で、消した端末の udid がそのまま残る。確からしさは高い(本文を読んだ事実と、スキーマの読み取り。消したあとの振る舞いは再現していない)。

直し方は1行で済む。手順4に「消す前に、手順2で `session_show_defaults` が出した値(ふつうは mimamori mother)に `session_set_defaults` で戻す」を足す。

### 2. 作者の iPhone 向けの道(iPhone Duo)に、記録済みの落とし穴が書かれていない(直すべき)

SKILL.md の16行目は作者の iPhone(iOS 27.2)には iOS 27.1 の iPhone Duo を使うと決めているが、同じ日の記録 `~/develop/mimamori/.claude/worktrees/harness-screen-guide/docs/dev-log.md` の412行目に「27.1 でキーボードを叩く試しは、iPhone Duo の画面で押す位置が合わず、送るところまで行けなかった」とある。PR の本文でも、この道具を通したのは 26.5 の撮影だけで、Duo の道は端から端まで通していない。

起きる場面。次に作者向けの手順(iOS 27 の画面)を頼まれたとき、Duo で押す位置が合わず進めない。進めても、印は `tap` の返す点 × `scale` で置く(35行目と `annotate.py` 74行目)ので、Duo では点と画素の比が 17 Pro の「3」と違い(作者のグローバルの `iphone-duo` skill は内側 2007×2853、外側 1398×2034 と2つの画面を持つと書いている)、丸が目標からずれた画像を渡しうる。

この PR が CLAUDE.md に足す決まりは「手順に書かれていない落とし穴に当たったら skill にまとめる」なのに、その決まりを持ち込む skill 自身が、同じ朝の落とし穴を落としている。直し方は、16行目の表に Duo で押す位置が合わなかった記録と、合わないときの逃げ道(26.5 で撮って画像にその旨を書く。19行目の「版が合わないときは画像に書く」で足りる)を書き、scale の説明(35行目)を Duo では内側と外側で違うと直す。確からしさは、記録は事実、設定アプリやショートカットでも再現するかは未確認。

### 3. `annotate.py` の折り返しで、閉じかっこが続くと枠からはみ出す(低)

`~/develop/mimamori/.claude/worktrees/harness-screen-guide/.claude/skills/mm-screen-guide/annotate.py` 36〜50行目の `wrap`。42行目で `NO_LINE_START` の文字は幅を見ずに足すので、閉じが連続すると1文字分の余白を超える。実測(26pt、幅 502 に全角19字 = 494px を置いた上で)。

```text
'」'    → 520px(余白の内側 528 に収まる)
'」。'  → 546px(528 を超え、枠 560 の内側)
'」）。' → 572px(x=16 から描くので 588 まで伸び、枠 560 で切れる)
```

`（「通知」）。` のような末尾で最後の字が欠ける。docstring と自己テスト(`<= W - 32`)は閉じ1文字しか想定していない。直すなら、閉じを足したあとに幅を超えていたら前の文字ごと次の行へ送る。確からしさは実測。

### 4. `annotate.py` の題名は折り返さず、画像の外の印は黙って消える(低)

91行目の題名は折り返さない。40字の題名を測ると 1312px で、用紙の幅 1192px を超えて切れる。74行目の印は画像の外でもエラーにならず、点の座標の代わりに画素の座標(例 600, 1200)を入れると丸が描かれないまま通る(再現した)。手順4の目視で拾えるが、`build` で画像の外なら `raise`、題名は折り返すか `assert` にすれば数行で済む。

### 5. `scripts/test-hooks.sh` の関門と本番で python の呼び方が違う(低)

`~/develop/mimamori/.claude/worktrees/harness-screen-guide/scripts/test-hooks.sh` 539行目は `python3 -c 'import PIL'` で見て、540行目は `python3 -I` で流す。`-I` はユーザーの site-packages を外すので、Pillow が `pip install --user` で入った Mac では関門を通ってテストが ImportError で落ち、`>/dev/null 2>&1` で理由が消える。この Mac は pyenv の site-packages(`~/.pyenv/versions/3.13.12/lib/python3.13/site-packages/PIL`)なので両方通る。関門も `python3 -I -c` にし、落ちたときは stderr を出すとよい。確からしさは `-I` の仕様からの推測で、再現はしていない。

`.claude/settings.json` の allow に `python3` は無い(19〜38行目を見た)。skills の文書どおり frontmatter に `allowed-tools: Bash(python3 -I ${CLAUDE_SKILL_DIR}/annotate.py *)` を置けば、確認の画面を出さずに流せる。
