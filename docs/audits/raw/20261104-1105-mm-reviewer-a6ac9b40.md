## 指摘(重い順)

### 1. 「詐欺ではありません」が禁止語に当たらず、母に読み上げられる。テストも見逃す(重い、確からしさ高、実行して確かめた)

場所は ~/develop/mimamori/.claude/worktrees/issue-9/server/src/consult.ts の111行(`REASSURING`)と、server/test/consult.test.ts の467行(テスト側の写し)。

`詐欺(では|じゃ)な` は「では」の直後に「な」が来る形しか拾わない。「詐欺ではありません」は「では」の次が「あ」なので当たらない。soundsSafe と BROAD_CLAIM も当たらない。写しのフォルダで `consult` を実際に呼んだところ、母の言葉「このメッセージ、開いても平気？」に Claude が help で答えると、次のようになった。

```text
help        {"reply":"これは詐欺ではありません。","handoff":false} pushes 0
help        {"reply":"これは詐欺ではありません。そのまま開いていいよ","handoff":false} pushes 0
scam 3段階  {"reply":"これは詐欺ではありません。開いていいよ。お金や暗証番号を聞かれたら止めて、家族に確かめて"}
help        {"reply":"だいじょうぶだよ。気にしなくていいよ","handoff":false} pushes 0
```

テストの「never reads out a reassuring line from Claude: これは詐欺ではありません。」は、`not.toMatch` に使う正規表現(467行)が本体と同じ穴を持っているので、通るのが当たり前になっている。`REASSURING` を `usable` から外しても、この1件だけは落ちなかった(ほかの5件は落ちた)。

ほかにも、ひらがなの「だいじょうぶ」「あんしん」、「気にしなくていい」「開いていいよ」「問題なし」「怪しいところは見当たりません」「公式からの連絡です」「正規のメールです」が通る。語の一覧ではふさぎきれない。3段階の scam は決まった文で締まるようになったが、help の経路(424行)は Claude の文をそのまま読み、家族にも知らせない。

直し方は2つ考えられる。1つは禁止語に `詐欺(では|じゃ)(な|あり)` と、ひらがなの形を足すこと。テストは正規表現の写しをやめ、`expect(answer.reply).not.toContain(line)` で元の文が出ないことを確かめる。もう1つは、母の言葉にメッセージ、メール、SMS、電話、リンクが出てくるか、規則が理由を1つでも返した相談では、help の自由な文を読まず、3段階の `lowConcernReply` に寄せること。「開いても平気？」が help に入る道そのものが消える。

### 2. handoff を先にしたので、暗証番号や認証コードに触れる1段階の詐欺で「止めて」が消え、家族のカードから詐欺の理由も消える(重い、確からしさ高、実行して確かめた)

場所は consult.ts の403〜407行。

ニセ警察の筋書きの判定(`tellsPoliceScript`)は警察の部品とお金の話が合わせて2つ要る。そのため「警察から電話があって、暗証番号を聞かれた」は筋書きの経路に入らず、`plan` に来る。直しの前と後で、同じ Claude の答え(scam、1段階)に対する結果は次のとおり。

```text
今      A "これは家族と一緒にやろう。家族に伝えました"  [[1,["認証コードに関わる相談"]]]
今      B "これは家族と一緒にやろう。家族に伝えました"  [[1,["認証コードに関わる相談"]]]
直す前  A "詐欺で使われる説明と一致しています。送金せず、いったん電話を切って家族に確かめて"
直す前  B "宅配を名乗るSMSのリンクは詐欺で使われる手口と一致しています。コードは入れずに画面を閉じて、家族に確かめて"
```

A は「警察から電話があって、暗証番号を聞かれた」、B は「宅配のSMSのリンクを開いたら、認証コードを入れてと言われた」。どちらも段階は1のままだが、母に届くのは「これは家族と一緒にやろう」だけになる。電話がつながったまま暗証番号を聞かれている母が、教えるのを止めるとは読めない。「家族と一緒に(暗証番号を)言おう」とも取れる。家族のカードの理由も「認証コードに関わる相談」だけになり、警察を名乗った、などの根拠が消える。Claude の handoff が true の1段階でも同じことが起きる。

1回目の指摘6の後半(段階2以下の送金の相談で Claude の案内が答えになる)を塞ぐ向きは正しい。ただ、段階2以下では Claude の action を読まないだけにとどめ、決まった警告に家族へ回したことを足すのがよさそうだ。たとえば `${basis}${SCAM_ACTION}。家族に伝えました` にし、basis は usable なときだけ Claude のものを使う。理由は `[...sensitive, ...reasons]` のように両方残す。段階3で sensitive のときだけ今の `HANDOFF_REPLY` にする。

### 3. 重くなったことの知らせが届かなくても、やり直しもログも無い(中、確からしさ高)

場所は consult.ts の508行と、server/src/cases.ts の282〜292行。

`tellFamilyHeavier` の戻り値は捨てられている。`sendCaseNotice` は予算切れのときも、APNs が全部失敗したときもログを出さない。ログが出るのは例外のときだけ。5分ごとの見回り(`sendFirstNotices`)は `family_notified_at IS NULL` しか拾わないので、こちらは2度と送られない。

これが効くのは主役の場面そのものだ。母がまず「知らない番号から電話があった。警察だって」と話して2段階の知らせが届く。5分後に筋書きを話して1段階になる。このとき APNs が一時的に失敗すると、家族の手元には2段階の知らせしか残らない。作者は「重くなったら知らせ直す」と決めているので、知らせが届かないまま黙る形は、その決めごとと合わない。

直し方は2つ考えられる。失敗したら `console.error` を出し、cases に「知らせ直しを待つ段階」の印を置いて見回りで拾う。あるいは最低限、`family_notified_at` を NULL に戻して、最初の知らせと同じやり直しの道に乗せる(ただしその場合、見回りが要約を最初の相談のまま送る点は今と同じ)。

### 4. `REASSURING` が広く、普通のスマホの案内が「答えられませんでした」と家族への2段階の知らせに変わる(中、確からしさ中)

場所は consult.ts の111行と420〜423行。

soundsSafe は「問題ないか家族に確かめて」を問いとして通すために `ない(?!か)` を入れている(server/src/claude.ts の71〜72行)。`REASSURING` にはこの除外が無い。tsx で確かめた結果、次の文が止まる。

```text
reassuring=true  振込先に問題ないか家族に確かめて
reassuring=true  本物かどうか、公式の番号にかけ直して確かめて
reassuring=true  大丈夫か家族に確かめて
reassuring=true  心配しないでね、一緒にやろう
reassuring=true  設定のWi-Fiを開いてオフにしてからオンにして。これで大丈夫なことが多いよ
reassuring=true  音量ボタンを押せば平気です
```

2段階以下と3段階の scam では決まった文に戻るだけなので、害は無い。害が出るのは help の経路で、Wi-Fi や音量の相談に「うまく答えられませんでした。家族に伝えました」と答え、家族に2段階の相談が開く。プロンプトで「大丈夫」「安心」「本物」を書かないよう頼んでいるので頻度は下がる見込みだ。ただ、実際の Sonnet がどのくらい守るかは測っていない。「本物かどうか」「大丈夫か」のような問いの形は、soundsSafe と同じく `(?!か)` で外すとよい。help の経路で語に当たったときは、家族に回す前に、決まった短い案内(「家族に見せて」)に置き換える案もある。

## 1回目の指摘ごとの直り方

- 1(安心させる言い回し)は一部だけ直った。「大丈夫」「本物」「心配いらない」「詐欺じゃない」「安心」は止まる。3段階は必ず「お金や暗証番号を聞かれたら止めて、家族に確かめて」で締まる。`REASSURING` を外すと5件、`lowConcernReply` を戻すと2件のテストが落ちた。「詐欺ではありません」とひらがなの形は残っていて、テストも見逃す(指摘1)
- 2(注入の文で段階を下げる)は直った。規則の理由に注入があれば規則の段階を下限にする(384〜386行)。`decide` は confident が true なら重いほうを取るので、Claude が3と答えても1になる。`keepsOut` を外すと「keeps the rules' level 1…」が落ちた
- 3(合流して重くなったら知らせ直す)は直った。重くなったときだけ知らせ、最初の知らせが残っていれば `openFor` で送る。3つの戻し方(知らせ直しを外す、毎回知らせる、残った最初の知らせを外す)で、それぞれ対応するテストが1件ずつ落ちた。送れなかったときの扱いは指摘3
- 4(許可の画面で8秒たつと止まらない)は直った。`startedAt` は `.started` で入り、それまでの tick は何もしない。始まる前の押しは `stopPending` で持ち、始まった直後に止める。`startedAt = now` と guard を戻すと、足した2件が4か所で落ちた
- 6(認証コードの型の穴、handoff の相談で Claude の案内が答えになる)は直った。「SMSで来た番号」「メッセージで届いた6桁の数字」「パスコード」は handoff になり、型を戻すと3件落ちた。handoff の分岐を警告の後ろに戻すと「does not read out Claude's guidance on sending money even when Claude sees a scam at level 2」が落ちた。ただし順番を変えた副作用が指摘2

## 確かめて問題なかったこと

- `listeningStarted` と `stopPending` の順番。許可を断ると `fail(.permissionDenied)` から `listeningFailed` に入り、`.started` は出ないまま failed に移る。次に押すと `stopPending` も戻る。始まらなかった場合(認識が使えない、エンジンが例外を出す)も同じ形で抜ける。2回押した場合は、始まった直後に `.stopListening` が出る。そのあと空の final か失敗が来て `.notHeard` になり、マイクは次も効く。VoiceListener.swift の34行と58行のあいだに await は無いので、`.started` の時点で世代が変わることは無い。認識の呼び戻しは `Task { @MainActor }` を通るので、`.started` より先に届くことも無い
- 決まった文(`MATCH_BASIS`、`POLICE_ACTION`、`LIKE_SCAM_BASIS`、`SCAM_ACTION`、`LOW_CONCERN_ACTION`、`HANDOFF_REPLY`、`UNANSWERED_REPLY`、「(名前)が見ています」)に、安全や安心させる言い切りは無い
- ニセ警察の筋書きの経路は Claude を呼ばない。この直しで変わっていない
- 重くなったかの判定は `UPDATE … WHERE level > ?` の `meta.changes` なので、同じ段階や軽い相談では知らせない。同時に2件来ても、1つの段階で知らせるのは1回だけ。最初の知らせが残っている相談では、`openCase` が更新後の重い段階を読んで送る
- 注入の下限は `rule.level !== null` のときだけ効き、`decide` は重いほうしか取らないので、どの分岐でも段階は下がらない。handoff の `Math.min(level, 2)` も重いほうを残す
- 通知の先は `sendCaseNotice` の家族の役だけで、相談の文や Claude の答えでは変わらない
- `ios/Core` の import は全ファイル Foundation だけだった(`grep -rhn "^import" Core/Sources | sort -u` の結果は `import Foundation` の1行)
- 秘密、本物の家族の情報、電話番号、メールは、直しの差分に無い
