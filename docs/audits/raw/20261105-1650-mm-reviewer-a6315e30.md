## 確かめて問題なかったこと

番号が `origin/main` の次であること。`origin/main`(`fafdaa6`)の `ios/project.yml` の25行は `CURRENT_PROJECT_VERSION: "3"`、HEAD は `"4"`。`git merge-base origin/main HEAD` は `fafdaa6` で `origin/main` の先端と同じなので、手順1のとおり今の `origin/main` から切ったブランチに1コミットだけ乗っている。ローカルの HEAD と `origin/release-build-4` は同じ(`git status --short --branch` に ahead も behind も無い)。

差分の形。`git diff origin/main...HEAD --stat` は次のとおりで、手順1に書かれた「`project.yml` に1行、`.pbxproj` に2行」と一致する。ほかの設定は混ざっていない。

```text
 ios/Mimamori.xcodeproj/project.pbxproj | 4 ++--
 ios/project.yml                        | 2 +-
 2 files changed, 3 insertions(+), 3 deletions(-)
```

変わった行は `~/develop/mimamori/.claude/worktrees/release-build-4/ios/project.yml` の25行と、`~/develop/mimamori/.claude/worktrees/release-build-4/ios/Mimamori.xcodeproj/project.pbxproj` の831行(Debug)と933行(Release)で、いずれも `3` を `4` にしただけ。pbxproj に `CURRENT_PROJECT_VERSION` はこの2か所しか無く、各ターゲットの `CFBundleVersion` は `project.yml` の `$(CURRENT_PROJECT_VERSION)` を読むので、拡張機能も同じ番号になる。差分の文脈に `DEVELOPMENT_TEAM = CTK4XXPWH9` が見えるが、チームの ID は `CLAUDE.md` が公開してよいとしているもの。

pbxproj が xcodegen の出力そのものであること。`ios/` をスクラッチパッドにコピーし、HEAD の `project.yml` に対して `/opt/homebrew/bin/xcodegen generate`(2.45.4)を流して `diff -r` で `.xcodeproj` 全体を比べたところ、`IDENTICAL` だった。手で書き換えた形跡や、生成し直すと消える設定は無い。作業の木は触っておらず、確かめたあとの `git status --short` は空で、コピーは消した。

コミットの形。`git log -1` の中身は次のとおり。

```text
chore(ios): ビルド番号を 4 にする

TestFlight に上げる版の番号を git の番号と一致させるため。

Co-Authored-By: Claude <noreply@anthropic.com>
```

種類 `chore`、範囲 `ios`、要約は12字で50字以内。本文に理由がある。Issue が無いので `Refs` は無くてよい。`Claude-Session:` の行は無い。`.githooks/commit-msg` の正規表現 `^(feat|fix|test|docs|refactor|chore|eval|harness)(\((ios|server|eval|harness|docs|plan|repo)\))?: .+` に通る。手順1の `git commit -m ... -m ... -m ...` が作る文面と一字一句同じ。ブランチ名 `release-build-4` も手順1の `release-build-$N` のとおり。ビルド3の bump(`1b49d52`、PR #76)も `ios/project.yml` と `project.pbxproj` の同じ2ファイルの変更で、形がそろっている。

手順0の前提のうちリポジトリから見えるもの。`~/develop/mimamori/.claude/worktrees/release-build-4/ios/Config/Shared.xcconfig` の5行は `MIMAMORI_API_HOST = mimamori.sago3.workers.dev` で、`*.placeholder.invalid` ではない。PR の本文にあるホスト名はこの既にコミット済みの値と同じで、新しく外へ出る情報ではない。PR の本文に母や家族の名前、電話番号、メールは無い(内部テストのグループ名「家族」は固有名ではない)。

範囲。`CONDITIONS.md` の今の条件では、母の iPhone への配布(#2)は周りの機能の条件に入らず、審査が通ったら先に進めるとある。この PR は番号を `main` に残すだけで、周りの機能には触れていない。
