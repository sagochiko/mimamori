## 確かめて問題なかったこと

- `docs/design.md` 117行との食い違い。閉じているときは帯の下の端まで上の段を広げ(`closedStripBottom`)、開いているときは `nil` を渡して4割で止めその中でずらす(`ProtectedHomeView.swift` 109〜115行)。3件までと並び順は `notices(from:now:)` と `mostPressing` に触れていない。「家族に伝えました」の2行制限 `closedLineLimit` もそのまま
- `stripBottom` の測り方。`.coordinateSpace(.named(topSpace))` は `.padding(.vertical, 8)` の外側に付くので `maxY` に上の8ポイントが入り、`topHeight(hasNotices:)` の `+ 8` が下の余白ぶん。名前付きの座標系は中身と一緒に動くのでスクロール位置の影響を受けない。`ScrollView` の中身の高さは枠の高さに依存しないので、測った値で枠を決めても循環しない。`hasNotices && !noticesOpen` の条件で、帯が消えたり開いたりしたあとの古い `stripBottom` は使われない
- 標準の文字の大きさの並び。`strip(first:)` の `else` 側は `HStack(spacing: 8)` に印、文、件数、矢印の順で、修飾子、`.padding(.horizontal, 16)`、`.padding(.vertical, 10)`、`.contentShape(Rectangle())` とも直す前と同じ。押せる範囲は Button の label 全体で変わらない。アクセシビリティの大きさでは印と件数と矢印の行の下に文を幅いっぱいで置く形で、設計の「先頭の1件と件数」は保たれている
- VoiceOver。Button の `accessibilityLabel`(「<状態>、ほか n 件」)と `accessibilityHint`(`closedHint`、開いているときは「押すと閉じます」)は差分に入っておらず、`ProtectedHomeView.swift` 476〜479行で前と同じ
- テスト。`ProtectedTopHeightTests` の5件は純粋な関数を直に当てており、`keepsClosedStrip`(content 900、screen 1000、closedStripBottom 520 で 520)は直す前の式 `min(content, max(screen*0.4, 120))` だと 400 になって落ちる。`swift test --filter ProtectedTopHeight` を流して5件通った
- `ios/Core` は `import Foundation` だけ。iOS 専用のフレームワークは入っていない
- `CaseCards.swift` 78〜80行の `guard` の折り返しは整形だけで、本体も戻り値も同じ
- 秘密の値、家族の実データ、外から写したコードは差分に無い。通知の宛先、共有の範囲、危なさの段階に触れる変更も無く、注入で変えられる経路は増えていない
