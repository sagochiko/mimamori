## 指摘の一覧

### 1. 直すべき。前の母の言葉に仕込みの文が1回あると、そのあと関係のない問いかけまで1段階で家族に回る
場所は `server/src/consult.ts` の `consult()` の `earlierKeepsOut` と `floor`、`decidePlan` の `keepsOut`。

前の6件の母の言葉に INJECTION が1件でもあると、つないだ文の規則の判定が下限になる。INJECTION は強い規則なので、つないだ文の判定は必ず1段階になる。そのため、ふつうの困りごとまで1段階の警告になり、家族に回る。

写しで再現した結果は次のとおり。

```text
6  前の母の言葉が仕込みのメールの1文、今の言葉が「Wi-Fi がつながらない」、Claude は Wi-Fi の案内
   reply=詐欺の手口と似ているところがあります。お金や暗証番号の話には応じず、家族に確かめて
   alerts=[[1,1,"警告を止めさせようとする文がある",...]] pushes=2
6b 仕込みのメールが5件前、今の言葉が「ストレージがいっぱいと出た」
   同じく level 1、pushes=2
judgeByRules(仕込みのメールの1文 + "\nWi-Fi がつながらない") = {"level":1,"reasons":["警告を止めさせようとする文がある"],...}
```

1回目の指摘1と同じ症状が、別の枝で出ている。ありそうな流れはこうなる。1回目の相談でメールを見せ、家族に知らせが行く。家族が電話して「解決」を押す。そのあと60分の中でストレージのことを聞くと、新しい1段階の知らせが家族全員に飛び、母には警告しか返らない。

直し方の案は、下限を当てるのを、今の言葉が前を指すとき(`pointsBack`)か、今の言葉が連絡の話(CONTACT)か規則の理由を持つときに限ること。2の「そのメールのリンクを開いてもいい?」は CONTACT に当たるので、この形でも下限がかかる。どれにするかは推測の域を出ないので、親が決めてほしい。今のテスト「gives the same level and tells the family the same…」には、関係のない問いかけで家族に回らない、という否定の側が無い。

### 2. 直すべき。`pointsBack` に当たらない続きの問いかけで、送金の案内が Claude の判断だけで読み上げられる
場所は `server/src/consult.ts` の `pointsBack`、`topicWords`、`decidePlan` の `sensitive`。

再現した結果。前の母の言葉は「振込のやり方を教えて」、Claude の偽物は help で action が「ATM の「振込」を押して、口座番号を入れます」。

```text
4a 今の言葉「さっき言ってたやつってどうやればできるの?」(20字)       -> reply=ATM の「振込」を押して… handoff=false
4b 今の言葉「次は何を押すの?」(指す言葉が無い)                       -> 同じく ATM の案内、handoff=false
4d 「振込のやり方を教えて」「(AI)…」「うん」のあとの「それってどうやるの?」 -> 同じく ATM の案内(見るのは直前の1件だけなので「うん」しか見ない)
4c 今の言葉「それってどうやるの?」(直前の1件が振込)                  -> HANDOFF、家族に回る(期待どおり)
```

#73 より前は、前のやり取りが渡らなかった。「次は何を押すの?」だけでは、Claude に送金の文脈が見えなかった。今は、Claude には history で送金の話だと分かるのに、決まった規則の壁(SENSITIVE)は今の言葉しか見ない。だから送金や削除の案内を止めるのは、system の「案内しません」と Claude の handoff だけになる。実装役の懸念が当たっている。

本物の Claude が案内してしまうかは確かめていない。ここで見たのは偽物の答えのときの道だけだ。直し方の案は、決まった規則の壁を出力の側にも置くこと。たとえば、直前の母の言葉が SENSITIVE に当たり、Claude が help で答えたら、Claude の action にも SENSITIVE の型を当て、当たれば読み上げない。これなら言い方によらない。

### 3. 軽い。「この」「その」で始まる15字以内の別の話題が、前の言葉の SENSITIVE を拾う
場所は `server/src/consult.ts` の `POINTS_BACK`。

「LINE のトーク履歴を消したい」のあとの「このアプリの文字を大きくしたい」(15字)で、`reply=これは家族と一緒にやろう。家族に伝えました`、`alerts=[[2,1,"文字の大きさの相談","[\"データの削除に関わる相談\"]"]] pushes=2` になった。写しで再現した。指摘1の狭い形が残っている。「この」「その」「そう」は、指す言葉だけの問いかけ以外にもよく出る。

### 4. 気づき。ai の行の仕込みの文は下限に使わない
`earlierKeepsOut` は母の言葉(`said.earlier`)しか見ない。ai の行に仕込みの文があり、Claude の偽物が level 3 を返すと、level 3 で家族への知らせは0件になる(再現の7)。ai の行は裏側の答えを端末が残したものなので、書き換えられるのは端末そのものを書き換えられたときに限る。カードの行の差し替え(`earlierSteers`)は ai の行も見ている。今のままでよいと考えるが、設計に一言あるとよい。

### 5. 軽い。ロック中に401が来ると会話が残る
場所は `ios/App/AppModel.swift` の `onRouteChange`。

`clear()` は `isProtectedDataAvailable` のときしか呼ばれない。最初のロック解除の後でも、画面のロック中に401が来ると(APNs の登録のように画面の無い呼び出しで)、鍵は消えて route は `.chooseRole` になるのに、会話は消えない。ロックを解いて `refresh()` が走っても、route は変わらないので `onRouteChange` は呼ばれない。そのため、会話は次に家族に入るまで残る。

コードで見た(Session.swift の `didSet { if route != oldValue … }`)。起きる場面は狭い。
