## 指摘

### 1. 前を指さない詐欺の続きで、家族への知らせが落ちる(重い。コードの道は実測で確かめた。Claude の答え方は推測)

[`server/src/consult-judge.ts`](server/src/consult-judge.ts) の1062行目と1067行目で、`goesOn` は `pointsBack`、`CONTACT`、`rule.reasons.length > 0` の3つだけで決まる。この3つに当たらない言葉では、Claude は前のやり取りを見ずに答える。ブランチの上で `npx tsx -e` から `judgeConsult` を呼び、`ask` に渡る `turns` の長さを数えた。

前の言葉が「息子から電話があって、携帯の番号が変わったって」の会話で、次の言葉はどれも `ALONE`(Claude に前を渡さない)になり、`rule.reasons` は `[]` だった。

```text
ALONE 会社のお金をなくしたから明日までに用意してって [] -> 3 false
ALONE 息子が会社の人を家によこすって [] -> 3 false
ALONE 上司の人が取りに来るらしい [] -> 3 false
ALONE キャッシュカードを預けてって [] -> 3 false
ALONE 100万円貸してほしいって [] -> 3 false
WITH  今日中に振り込んでほしいって ["急がせる言い回しがある","お金を動かす話がある"] -> 1 true
```

偽の Claude は、前を見せられたら1段階、見せられなければ3段階の help と答える形にした。前が「息子を名乗る人から電話で、会社のお金をなくしたから助けてと言われた」でも、「今からコンビニに行ってくる」「銀行に行ってくるね」「300万円おろしてくる」「会社の人が家に取りに来るって」「かけ直したら本当だった」「封筒に入れて渡すの」「内緒にしてって言われた」はすべて `ALONE` で、3段階になり、家族に届かなかった。

起きうる場面はこう。オレオレ詐欺を2回に分けて話し、1回目は「息子から電話、番号が変わった」、2回目は「上司の人が取りに来るらしい」とする。直す前なら、2回目は Claude が前のやり取りを見て受け子の筋だと気づけた。直したあとは、2回目だけを見ると無害な予定の話なので、3段階で誰にも知らせない道になる(Claude が単独で3と答えるかは推測)。1回目で家族にカードが届いていても、受け子が家に来るという肝心の続きは家族に伝わらない。

design.md に書き足した段落は、失うものを「指す言葉の無い操作の続き(『次は何を押すの?』)には前の話が付かなくなる」とだけ書き、「今の言葉だけで危ない相談は今までどおり」と言っている。けれど、2回目だけでは危なく見えない詐欺の続きも失っている。dev-log が数えた「前を指さず、電話やメッセージでもなく、規則も見つけない例文は1件」も、eval が履歴なしでしか測らないための数字で、続きの相談はそもそも含まれていない。

直し方の案は2つある。1つは、お金や受け渡しや来訪の語(`取りに来`、`預け`、`貸し`、`万円`、`おろ`、`用意`、`渡す`、`内緒` など)を `goesOn` に足す。挨拶や礼には当たらないので、#219 の直しは残る。もう1つは、少なくとも design.md と dev-log に、この見逃しを失うものとして書き、作者に判断を渡す。上の言葉を試験に足し、前のやり取りつきで2段階以上になることを確かめる。

### 2. docs/plan.md の153行目が新しい振る舞いと食い違う(軽い。文書で見た)

[`docs/plan.md`](docs/plan.md) の153行目(`POST /consult` の行)は、今も「前のやり取りは Claude に `<untrusted>` の中のデータとして渡し」と条件なしに書いている。design.md の209行目は「前を指す問いかけ、メッセージや電話の話、規則が何かを見つけた言葉のときだけ」に改めた。plan.md はつなぎ目の約束を置く文書なので、同じ条件を書き足すべきだ。端末が送る `history` の形は変わらないので、API の形を直す必要はない。

## 確かめて問題なかったこと

- #219 の直し自体。`おはよう` と `ありがとう` は `goesOn` が偽になり、`ask` には `[]` が渡る。consult.test.ts の3505行目の試験は `turns === undefined` を前を見た扱いにしているので、直す前のコード(`ask(rule)`)では落ちる。consult の段の試験も `seen` が `[[]]` であることを見ている。偽の Claude は見せられた履歴で答えを変えるので、自分自身を確かめるだけのモックにはなっていない。
- 前を指す問い(#114 #118 #128)。`pointsBack` に当たれば今までどおり履歴が渡る。`pointsBackAtScript` と `summaryOf` は `said` から決まり、`ask` に渡す履歴とは関係しない。試験の「それってどういうこと?」で `seen` が `[told]`、題が「警察を名乗る電話の相談」になることを確かめている。
- 家族を外そうとする前の文の下限(#73、PR #79)。`earlierKeepsOut` は前と同じく `goesOn` の条件のままで変わらない。`plan()` の `earlierSteers` は今も全部の `history` を見るので、前の行に仕込みの文があれば Claude の行は家族のカードに使われない。Claude に履歴を渡さない場面が増えるので、注入された文が Claude に届く道はむしろ狭くなった。
- eval と本番の食い違い。eval/lib/score.ts の190行目は `judgeConsult(text, [], async (rule) => ...)` で、履歴はいつも `[]` だ。`goesOn` の真偽に関係なく Claude に渡るのは `[]` なので、測る経路は直す前と同じで、本番とも食い違わない(ただし、上の指摘1のとおり eval は続きの相談を測れない)。
- 筋書きの続き(「また警察から電話が来た」「お金を振り込めと言われた」)は、規則だけで1段階のまま Claude を呼ばない。Wi-Fi の会話のあとでも、CONTACT と規則の理由で `goesOn` が真になり、履歴が渡る。
- 「安全です」と返す道、知らせる相手、共有の範囲、30日の削除は、この差分では変わらない。家族のカードの題と理由の作り方(`summaryOf`、`cardReasons`)も変わらない。
- 秘密、実在の家族のデータ、外から写したコードは差分に無い。`ios/Core` は触っていない。
- `npx tsc --noEmit` は通った。`npx vitest run test/consult.test.ts test/rules.test.ts` は `Tests 976 passed (976)` だった。
