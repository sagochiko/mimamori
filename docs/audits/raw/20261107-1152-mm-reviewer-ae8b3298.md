## 指摘

1. 数え方として書いたコマンドを、書いたとおりに流しても数が出ない(確度は高い。手元で流して確かめた)

   場所は `~/develop/mimamori/.claude/worktrees/docs-1107-features/README.md` の「Built during the hackathon」(165行目付近、`Counted with ...` の文)と、`~/develop/mimamori/.claude/worktrees/docs-1107-features/README.ja.md` の「期間中に作ったこと」(`数えたのは ...` の文)。`~/develop/mimamori/.claude/worktrees/docs-1107-features/docs/submission.md` も「数え方は README に書いた」としているので、同じ穴を引き継ぐ。

   数そのものは合っている。a916f02 で数え直した結果は 922、711、674、PR 119、Issue 105(閉じたもの 74)、マイグレーション 9、`mm-reviewer` の原文 209、dev-log 91 件。合わないのは書いてある手順のほうで、2つある。
   - `gh pr list --state merged` と `gh issue list --state all` は既定で30件までしか返さない。実際に流すと PR も Issue も `30` だった。審査員がこの手順で確かめると、119 も 105 も再現できない。`--limit 500` が要る
   - 674 は `--no-merges` と `--grep='^Co-Authored-By: Claude'` を同時に付けたときの数。`git rev-list --count --grep='^Co-Authored-By: Claude' a916f02` だけだと `676` になる。英語の「(with `--no-merges`, and `--grep=...`)」も、日本語の「(`--no-merges` と `--grep=...` も)」も、2つを重ねるとは読めない
   - 参照を書いていないので、後日流すと別の数になる。ただし時点に `a916f02` と書いてあるので、軽い

   直すなら、たとえばこう書ける。
   ```sh
   git rev-list --count a916f02
   git rev-list --count --no-merges a916f02
   git rev-list --count --no-merges --grep='^Co-Authored-By: Claude' a916f02
   gh pr list --state merged --limit 500 --json number --jq length
   gh issue list --state all --limit 500 --json number --jq length
   gh issue list --state closed --limit 500 --json number --jq length
   ```
   Issue と PR の数は、後から特定の時点の値に戻して数え直す手段が無い。2026年11月7日に数えた値だと添えておくと、審査員が誤解しにくい。

2. 新しい節「作者の iPhone で確かめたもの」の冒頭が、Safari の確かめの条件を違って言っている(確度は高い。#145 のコメントで見た)

   場所は `README.ja.md` の「作者の iPhone で確かめたもの」の最初の段落と、`README.md` の「Tried on the author's iPhone」の最初の段落。冒頭は「作者が自分の iPhone(iOS 27.2)で母の役になり、シミュレータを家族の役にして確かめた」と全部の項目をまとめ、Safari だけを「その前にビルド7で」と分けている。けれど #145 の2026年11月5日のコメントには「作者の端末は家族の役なので、家族への知らせには回らない(母の端末から来たページだけを回す作り)」とある。Safari のときの作者の端末は家族の役で、家族に知らせる経路は通していない。

   箇条の文(「危ないページに警告を重ねること」)だけを見れば正しい。それでも冒頭の言い方だと、審査員は母の役で通し、家族への知らせまで動いたと読みかねない。ビルドの番号に加えて、Safari のときは作者の端末が家族の役だったこと、確かめたのは警告の覆いだけだったことを、日本語と英語の両方で分けて書くのがよい。
