## 指摘

### 1. 公式のホストの判定が「共有のホスト」を公式と同じに扱い、Google サイトや Google フォームの偽ページで欄と電話番号を見なくなった(確かめ方: 再現した)

`~/develop/mimamori/.claude/worktrees/issue-137-unmarked-to-claude/server/src/page-gate.ts` の 92〜94行目。

```ts
if (officialBrandOf(host(page)) !== null) return false;
return page.hasSecretField === true || callsForSupport(page);
```

`officialBrandOf` は `google.com`、`icloud.com`、`yahoo.co.jp`、`line.me` の下位ドメインも公式と返す。同じファイル `rules/domains.ts` の 143〜152行目には「誰でもページを置ける」`USER_CONTENT_HOSTS`(`sites.google.com`、`docs.google.com`、`drive.google.com`、`script.google.com`、`line.me`、`chiebukuro.yahoo.co.jp`)と、`www.icloud.com` の共有パス(`/notes/` など)が別に定義され、`trustOf()` はそれらを `shared` と返す。この関門は `trustOf` ではなく `officialBrandOf` を見るので、共有のホストが公式と同じ扱いになる。

規則が `{ level: null, reasons: [] }` のときに `pageWorthAsking` が返した値。

- `https://sites.google.com/view/pc-support`、本文「サポート窓口 050-0000-0000 まで」→ `false`(期待は `true`)
- `https://docs.google.com/forms/d/abc/viewform`、本文「ご注文フォーム お名前 ご住所 お電話番号」、`hasSecretField: true` → `false`
- `https://www.icloud.com/notes/0abc`、本文「サポート窓口 050-0000-0000 まで」→ `false`
- `https://chiebukuro.yahoo.co.jp/q/1`、`hasSecretField: true` → `false`

起きること。Google サイトに置いた偽サポートページ(会社の名を出さず「サポート窓口」と番号だけ、急がせる語も無い)を母が開くと、c104fe8 の前は `callsForSupport` で Claude に回っていたが、今は回らない。急がせる語や会社の名があれば規則か `speaksAsOtherBrand` が拾うので(「ウイルス感染の警告。今すぐ」の形は規則の印で回ることを確かめた)、穴は「語の静かな偽サポートと偽フォーム」に限られる。c104fe8 で新しく開いた穴なので直してほしい。

直し方の案。`officialBrandOf(host(page)) !== null` を `trustOf(host(page), false, new URL(page.url).pathname).trust === "official"` に替える(`url` が壊れていれば `host()` と同じく空にして `other` 扱い)。`page.test.ts` の「does not send」の組に `sites.google.com` の偽サポートを「sends」側で足すと、戻ったときに落ちる。確かさは高い(再現した)。
