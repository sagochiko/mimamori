## 見てほしいと言われた4点

### 1. 実行時のチェックが本当に消えるか

消える。どのビルド設定でも同じだった。

プロジェクトの設定は、`xcodebuild -project ios/Mimamori.xcodeproj -target Mimamori -configuration Debug -showBuildSettings` で Swift 関係を抜き出すとこれだけだった。

```text
EFFECTIVE_SWIFT_VERSION = 6
SWIFT_ENABLE_EXPLICIT_MODULES = YES
SWIFT_ENABLE_TESTABILITY = YES
SWIFT_VERSION = 6.0
```

`SWIFT_DEFAULT_ACTOR_ISOLATION`、`SWIFT_APPROACHABLE_CONCURRENCY`、`SWIFT_UPCOMING_FEATURE_*`、`OTHER_SWIFT_FLAGS` はどれも無い。`ios/project.yml` と `ios/Config/Shared.xcconfig` にも無く、pbxproj にあるのは `SWIFT_VERSION = 6.0` の2行(758〜760行と853〜855行)だけ。NonisolatedNonsendingByDefault も既定の MainActor 隔離も有効になっていない。

念のため設定を振って確かめた。Xcode 27.1 の Swift 6.4 と iPhoneOS27.1 SDK で、元の版、直した版、`@Sendable` 無しの版を `-swift-version 6 -emit-sil` で落とし、`swift_task_isCurrentExecutor` の呼び出しを数えた。

| 版 | 既定 | NonisolatedNonsendingByDefault | -default-isolation MainActor |
|---|---|---|---|
| 元(main) | 11 | 11 | 13 |
| 直した版 | 0 | 0 | 9(全部 deinit の中で、閉包には無い) |

元の版でチェックが入っていた関数を demangle すると「closure #1 in closure #1 in static VL.permitted()」になった。落ちた記録のフレームと同じ形をしている。nonsending が将来有効になると `permitted()` 自体は呼び出し元の役者で走る。それでも閉包は静的にメインに隔離されず、チェックは出なかった。

### 2. `AVAudioApplication.requestRecordPermission()` を nonisolated から呼ぶこと

問題ない。SDK の AVAudioApplication.h の71行に `NS_SWIFT_SENDABLE`、119行に `+requestRecordPermissionWithCompletionHandler:` があり、注記に「the block may be called in a different thread context」と書かれている。async 版はこの completion を自動で取り込んだもので、続きは Swift 側の継続で再開される。返り値は Bool。直した版の SIL ではこの経路にチェックが0件だった。`start()` は `@MainActor` なので、`await Self.permitted()` のあとはメインに戻る(VoiceListener.swift の33行)。

### 3. 同じ落ち方がほかに残っていないか

見つからなかった。App 全体(ios/App、Views、Debug)を Core のモジュールと一緒に `-wmo -emit-sil` で落とし、チェックを持つ関数をすべて並べた。残っていたのは SwiftUI の body、ボタンの action、`.onChange`、`.onReceive` の閉包と、`ReplySpeaker.speak(_:)` の中の `lines.map { ... }` だけだった。どれもメインで呼ばれる。`map` は同期で、`protectedDataDidBecomeAvailableNotification` は UIKit がメインで投げる。

拡張機能の MessageFilter、CallDirectory、SafariExtension、ShareExtension はそれぞれ SIL に落としてチェック0件。4つとも同期のスタブで、隔離の注記も無い。

コードで見た個所もある。

- ReplySpeaker.swift の52行と57行。`AVSpeechSynthesizerDelegate` の2つは `nonisolated` で、中から `Task { @MainActor in ... }` へ渡している
- MimamoriApp.swift の40行と47行。`UNUserNotificationCenterDelegate` の async 版は `nonisolated`。51行の `didRegisterForRemoteNotificationsWithDeviceToken` は UIKit がメインで呼ぶ
- VoiceListener.swift の52〜57行。`recognize` の `report` は `@Sendable` 引数なので、`start()` の中で作っても nonisolated になる
- AppModel.swift の236行は async の取り込み版。Session.swift の6行は `@MainActor` で、`onRouteChange` と `isProtectedDataAvailable` は同じ役者の中でしか呼ばれない
