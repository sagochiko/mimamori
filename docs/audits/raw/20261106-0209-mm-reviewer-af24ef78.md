## 指摘

### 1. `listed` の鍵に応答の全文が入るので、「同じ状態には1回」が効かず、上限が無い(確度 高)

`keep-going.sh` の 56 行目で、`listed` が立つと `$msg` の全文を鍵に混ぜる。応答の文字が1字でも違えば新しい鍵になるので、worktree が残ったまま「次の Issue」「残りの Issue」のような語を含む応答で終えるたびに毎回 block が返る。文書どおり 8 回の上限はツールを呼ぶたびに数え直され、`stop_hook_active` が継続の連鎖で true のままかどうかは文書に書かれていない(「already continuing as a result of a stop hook」とだけ)ので、それが無いときの止め手は、Claude が応答の末尾を `？` にするか、前と同じ文字列で終えることだけになる。

再現(同じ `session_id`、worktree が2つある本物の木、`background_tasks:[]`)。

```text
B1 "#140 を終えた。次の Issue は #141。"  → {"decision":"block",...}
B2 "#141 を終えた。次の Issue は #142。"  → {"decision":"block",...}
B3 B2 と同じ文                             → 通る
```

具体的に困る場面は、残りの Issue が全部「作者: 」待ちのとき。「残りの Issue は全部作者待ちなので返事を待つ。」で終えると `残りの Issue` に当たって block され、言い直すたびにまた block される。直し方の案は、鍵を `left` と「当たった語の組」にする(全文を入れない)、あるいはセッションごとの block の回数に上限を置く、または「作者待ち」「作者の返事」を含む応答を通す。

### 2. worktree が残っているだけで、作者と話している応答も止める(確度 高)

43〜50 行目の `left` は `.claude/worktrees/` の有無だけを見るので、別のセッションや作者待ちの Issue のために worktree が置いてあるあいだ、主のセッションが作者の質問に答えただけの応答も1回止める。

```text
A "差分を説明した。"(cwd=~/develop/mimamori)
→ {"decision":"block","reason":"作業中の木が残っている(harness-stop-continue issue-137-unmarked-to-claude)のに、裏で動くものが無い。手を止めずに続ける。..."}
```

いまの木には `issue-137-unmarked-to-claude` が置いてあり(`git worktree list`)、作者が主と話すセッションでは最初の応答で必ずこれが出る。1回だけ(鍵は worktree の組)なので致命ではないが、worktree の組が変わるたびに(別のセッションが足す、消す)また出る。意図した挙動なら `docs/harness.md` に「作者と話しているセッションでも1回出る」と書いておく。意図していないなら、worktree の持ち主(ブランチが `issue-` で始まり、そのセッションが作ったもの)に絞るか、`cwd` が main 以外のブランチのときだけに絞る。
