確かめ方は2つ。[`scripts/review-record.sh`](~/develop/mimamori/.claude/worktrees/harness-review-record-id/scripts/review-record.sh) の58〜67行目のコードを読んで場面ごとにたどったことと、`bash scripts/test-hooks.sh` を流したこと(`exit=0`)。直しを外した版はファイルを書き換えないと作れないので、走らせていない。試験が落ちるかは、コードをたどって判断した。

参考までに、指摘にはしない残りの道が1つある。id で探して `fresh` に追跡されていない原文が1つ残ったときは、回を確かめない(60行目の条件は追跡済みのときだけ)。ふつうの流れでは、その原文が今回の回だ。外れるのは、前の回の原文が作業の木か本体の木に追跡されないまま残り、今回の保存が失敗したときだけになる。今回の直しの範囲の外で、起きにくいと見ている。確かさは中くらい。

## 確かめて問題なかったこと

- 前の回を今回として出す道は塞がった。1回目だけが追跡済みのときに id と `2` を渡すと、`count=1` のまま `name` に1回目が入る。そのあと60行目で追跡済みと分かり、`git log -1 --format=%s` の件名「1回目」と `2` が違うので止まる。このとき `all` の名前を出し、`mv` もコメントの本文の書き出しもコミットもしない(すべて止まる位置より後ろにある)。1回目と2回目が追跡済みのときに `3` を渡す場合も同じで、`tail -n 1` が2回目を選び、件名「2回目」と `3` が違うので止まる。
- 正しい流し直しは止めていない。2回目が追跡済みになったあと、id と `2` で流し直すと、件名は「2回目」なので通る。既存の試験2つ(`55556666` の流し直し、`11112222` の HEAD での流し直し)が今も通る。主の場面も通る。1回目が追跡済みで、2回目が本体の木にまだ追跡されずにある場面で、2回目は追跡されていないので回の確かめを通らずに使われ、そのあとスクリプト自身が件名「2回目」でコミットする。
- 安全側に倒れる場合がある。追跡済みの古い回を id で流し直そうとしたとき(1回目と2回目が追跡済みで `1` を渡す)は止まる。原文を入れたコミットが決まった件名でないときも止まる。どちらも名前の一覧が出て、名前を全部渡せば通る。黙って出すことはない。
- 試験は直しを外すと落ちる(コードをたどって判断した)。直しが無いと、`77778888` と `2` は `count=1` で1回目を使い、終了コード0でコメントの本文を書くので、「止まる」と「何も書かない」の2つの確かめが落ちる。`55556666` と `3` は `tail` で2回目を使って0で終わるので、同じように落ちる。名前の一覧の確かめは、2つ目の試験で r1 と r2 の両方を求めている。止まるときに `found` ではなく `all` を出していることまで、この確かめで見ている。
- `set -u` の下でも壊れない。名前を全部渡すときは `by_id` も `all` も設定されないが、`${by_id:-}` で守っていて、`all` を読むのはその分岐の中だけ。件名は `%s` なので、本文の `Refs` の行は正規表現の照合に入らない。
