## 指摘

1. Safari の手順に、サイトへのアクセスを許可する段がない。このままだと拡張機能が動かない(確度は高い)

   場所は `ios/Core/Sources/MimamoriCore/ExtensionGuide.swift` の `.safari` の `steps`(37〜44行あたり)。最後の段が「「機能拡張を許可」をオンにする」で終わっている。

   拡張機能の [`ios/SafariExtension/Resources/manifest.json`](ios/SafariExtension/Resources/manifest.json) は、`content_scripts` の `matches` を `["http://*/*", "https://*/*"]` にしている。`host_permissions` は無い。iOS の Safari では、この形の content script はサイトへのアクセスが許可されるまで走らない。撮った `06-safari-guide-bottom.png` にも、スイッチの下の「アクセス権」の欄に「この機能拡張はまだどのWebサイトにも許可していません。」と出ている。

   母が手順どおり5段目まで進めてスイッチをオンにしても、怪しいページの知らせは出ない。画面にもその先の段が無いので、本人も家族も動いていないことに気づけない。Issue #287 は、手順に「すべての Web サイト」(などアクセス権の行)を「許可」までを入れるよう指定している。

   写真が無い段は了承済みだが、この段は文ごと無い。SMS の3段目と同じように写真なしの6段目を足せば直る。例として「「アクセス権」の下の行を押して「許可」を選ぶ」のように、撮れていない行の名前を引用しない文にする。「アクセス権」と「Webページのコンテンツと閲覧履歴」は `06` の写真に写っているので引用してよい。足したら `ExtensionGuideTests.safariSteps` の「すべてに画像がある」という期待も直す。

## 確かめて問題なかったこと

- 手順の言葉と写真の文言が合っている。`01`〜`06` と `11`〜`13` を開いて見た。
  - 画面で「アプリ」「Safari」「機能拡張」「mimamori」「機能拡張を許可」を確かめた。拡張の一覧の名前は、manifest の `name` のとおり英字の「mimamori」で出ている。
  - 「メッセージ」は、アプリの一覧の「ま」の欄にある。
  - 1枚目の写真には「デベロッパ」の行が写っている。シミュレータの開発者モードによるもので、手順を誤らせるものではない。
- SMS の3段目の「みまもり」は、Message Filter の `CFBundleDisplayName: みまもり`(`ios/project.yml` 104行)と合っている。行の名前を記憶で引用していない。
- 画面の文言の決まりと読み上げ。
  - 手順の文は、Issue で主が決まりの対象外と判断した部分にあたる。それ以外に足された文言は、名札2つと「設定を開く」だけ。
  - 写真には「N番目、〜」の `accessibilityLabel` が付いている。写真がある段は文を `accessibilityHidden` にして二重に読まれないようにし、写真が無い段は文がそのまま読まれる。行とボタンの補足は `accessibilityHint` にある。
- 家族の画面には出ない。`RootView.swift` の110行は `familyHome` のとき `FamilySettingsView()` を出し、それ以外のときに `SettingsView()` を出す。2行が足されたのは `SettingsView` だけ。
- テストについて。`imagesExist` は、手順にある画像名がすべて `App/Assets.xcassets/<名前>.imageset/<名前>.png` にあることを確かめる。アセットの名前を変えたり消したりすれば落ちる。写真の中身と文が合っているかはテストでは捕まえられないが、データで書く形なのでそこまでは求められない。
- `ios/Core` の `ExtensionGuide.swift` は `Foundation` しか読み込んでいない。iOS だけの枠組みは読んでいない。
- 秘密の値、家族の情報、外から写したものは差分に無い。`docs/dev-log.md` に足された記録にも時刻は無い。
- 「設定を開く」で着く先は親が確かめた範囲を採った。設定アプリが動いている間に押したときと実機での着地は、レビューでは見ていない。
