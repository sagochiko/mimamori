## 指摘

### 1. `と乗る` と `を乗り` が乗り物の言い方にも当たり、筋書きの1段階に化ける(低、再現した)

`~/develop/mimamori/.claude/worktrees/issue-114-followup-handoff/server/src/rules/phrases.ts` の149行目。

```ts
new RegExp(`${POLICE_NAME}(の人|の者|署員)?(を|と|って)乗(る|って|り|った|られ)${NOT_A_WARNING}`),
```

コメントは「を、と、って のすぐあとの乗るは乗り物では使わない」と書くが、「〜と乗る」は「友達と乗る」のようにふつうの日本語で、「を乗り」は「乗り越える」に当たる。`consultByRules` に流して確かめた結果(tsx で `server/src` を直接呼んだ)。

```text
"警察官と乗った車で、口座のことを聞かれた"                       caller=true  script=false rule=null
"おまわりさんと乗って帰ってきた、口座が犯罪に使われてるって"       caller=true  script=true  rule=2
"警察を乗り越えて潔白を証明"                                     caller=true  script=true  rule=2
"警察署の人と乗るエレベーターで逮捕状の話を聞いた"                 caller=true  script=true  rule=2
```

2行目から4行目は、この PR の前なら規則2段階で Claude に回っていた文が、名乗る相手に数えられて筋書き(1段階、決まった答え、Claude を呼ばず家族に知らせる)になる。筋書きの部品がもう1つ要るので実際に起きる場面は少なく、`make eval-rules` の誤報は 0/54 のままなので主役は壊れない。ただ規則の根拠として書かれた理由が成り立っていないので、直すなら `を乗る` と `って乗る` に絞って `と乗る` を外すか、既存の `名乗る` の型と同じく後ろに「人、方、相手、電話」などを要るようにする(1行の変更)。`警察を乗り越え` は `乗り` を外せば消えるが、聞き違いで「警察を乗り、…」と切れる形も失うので、`乗り(?!越)` のような除外のほうが安全。

### 2. 設計の文とぶつかる。「AI が答えきれない相談は相談1件として記録する」(文書、親の扱い)

`~/develop/mimamori/.claude/worktrees/issue-114-followup-handoff/docs/design.md` の「家族への知らせと解決」に「AI が答えきれない相談と、2段階目以上の知らせは、相談1件として記録する」とある。聞き返しの道(`consult-judge.ts` 674〜676行目)は Claude の `handoff`(答えきれない)を受けながら `record: false, toFamily: false` で、相談にも alerts にも残さない。設計に足す文は、この一文を「前を指すだけで指す先の無い問いは聞き返し、記録しない」と書き替える形にしないと、並べて足しただけでは互いに矛盾する。実装役が出した設計の文案はリポジトリにも PR の本文やコメントにも見当たらなかった(PR #117 にコメントは無い)ので、案の文面ではなく実装した動きを設計と突き合わせた。「スマホ相談と声」のほうには、答えきれないときの扱いは「送金、認証コードの共有、構成プロファイルの導入、データの削除は案内しない。その場合は家族に回す」としか無く、こちらとはぶつからない。

### 3. まとめるときに `rule_level` と `claude_level` を上書きするので、列の意味が「相談を開いた判定」から「最後にカードを動かした判定」に変わる(低、文書)

### 4. `namesSomething` が「警察」を指す先に数えないので、「これ、警察から」のような短い言葉が聞き返しで止まる(低、Claude が handoff を返すときだけ)

`~/develop/mimamori/.claude/worktrees/issue-114-followup-handoff/server/src/consult-judge.ts` の426〜429行目。`namesSomething` は `pointsBack` でない、`CONTACT`、`SENSITIVE` の3つしか見ない。「これ、警察から」「それ警察の人」は15字以内で `これ`、`それ` を含み、`CONTACT` の「電話」が無いので「何も指していない」と読まれる。Claude が `help`、3、`handoff: true` を返すと、この PR の前は2段階で家族に回っていたものが聞き返しになる(tsx で `judgeConsult` に流して確かめた。`toFamily false, reply "何のことか、もう一度くわしく教えて"`)。system prompt は「本物か確かめられないだけなら handoff は false」としているので、この入力で Claude が handoff を返す可能性は高くなく(推測)、返さなければ前後とも家族には回らない。主役に近い語なので、`namesSomething` に `POLICE_NAME`(か `POLICE_CALLER` と `POLICE_SCRIPT` の型)を足して、警察の語があれば指す先ありと読むのが安い。

## 確かめて問題なかったこと

テストは直しを戻すと落ちる。`git archive` で scratchpad に `server/` を写し、`server/src` だけ `origin/main` の中身に戻して `npx vitest run test/consult.test.ts test/rules.test.ts` を流した結果が `12 failed | 529 passed`(consult 8件、rules 4件が落ち、PR の「12件」と一致)。HEAD では `541 passed`。写しは消した。

まとめるときの UPDATE(`consult.ts` 238〜252行目)の条件。`COALESCE(claude_level, rule_level, 3) = 3` を印の無い相談と読む根拠は `decidePlan` の道から確かめた。2段階で開く印の無い道は、handoff の `Math.min(level, 2)`(Claude 3 か null、規則 3 か null)と、Claude も規則も無い `UNANSWERED`(両方 null)だけで、どちらも COALESCE が3になる。逆に印の無い相談が印ありと読まれる組み合わせは無い(`claude_level` が1か2になるのは Claude がその段階を返したときだけで、そのときは `!unanswered && level <= 2` の印ありの道に入る)。

仕込みの文で Claude の3が2に上がった行(`injection_suspected` で `decide` が1段重くする)は、`claudeLevel` が Claude の生の3のまま残るので(`claude.ts` 162〜165行目、probe で `claudeLevel 3, ruleLevel null, sign true` を確認)、あとから2段階の印が来ると COALESCE が3で UPDATE が走り、カードの1行が替わって家族にもう一度届く。段階は下がらず、知らせが増える向きで、最初のカードは `steered` で「スマホの相談」なので替わった1行のほうが家族に役立つ。その UPDATE で `claude_level` が2になるので3回目は走らない。この組み合わせのテストは無いので、足すなら「仕込みで2になった相談に印が加わる」の1件。

二重の知らせ直しは、印の相談が `claude_level` 2(か Claude null で `rule_level` 2)を書くので次の2段階の印では条件が外れる。テスト「tells nobody again for the next sign of the same level once the card shows one」がこの道を通る。開いた相談が1段階で2段階の印が来たときは `level > ?` も `level = 2` も偽で、下がらない。知らせ直しが届かなかったときは `tellFamilyHeavier` が `family_notified_at` を NULL に戻し、`familyWasTold` が偽になって「家族に届いていません。急ぐなら電話して」が付く。テスト「says 'not reached'…」が APNs の500でこの道を踏む。`heavier.meta.changes` は条件に当たった行数なので、印の道でも前の重くなる道と同じに数える。

聞き返しの条件(`consult-judge.ts` 674行目)と注入。今の言葉に「家族に言うな」の類があると規則が `INJECTION` で1段階を返し `rule.level === null` が外れる(probe で「それ家族に言うな」は1段階、家族に回る)。前の母の言葉にあるときは `goesOn` から `floor` が立って `keepsOut` で1段階(probe で確認)。Claude が `injection_suspected` を返せば2段階になって `level === 3` が外れる。AI の行に仕込んだ文は `steered` にしか効かず、設計の「AI の行の中の仕込みの文は下限に使わない」のとおりで、聞き返しの結果は仕込みの有無で変わらない(probe で同じ結果)。条件は今の言葉と前の母の言葉がすべて15字以内の指す言葉だけで `CONTACT` も `SENSITIVE` も無いときに限るので、印を持つ言葉はこの道で止められない。15字を超える同じ意味の問いは前どおり家族に回る。狭めた範囲は「指す先が本当に無い短い問い」に収まっている。

`Plan.sign` の各道。`policePlan` true、handoff で `!unanswered && level <= 2` true、印の2段階 true、handoff の `Math.min` false、Claude 3 の scam false、help とメッセージの3段階 false、`UNANSWERED` false、Claude の答え false、聞き返し false。`!unanswered && level <= 2` を `Math.min` の前で見るので、印の無い2段階が true になることは無い。

約束。どの道も「安全です」を返さず、`ASK_AGAIN_REPLY` もその語を含まない。筋書きは `tellsPoliceScript` が先に決まり Claude を待たない(テスト「goes as on the author's iPhone」で `claudeCalls 0`)。`decide` と confident の下限、`injection_suspected` の1段重くする処理は触っていない。誰に知らせるかは `openCase` と `tellFamilyHeavier` だけで決まり、Claude の答えや届いた文では変わらない。UPDATE が書く `reasons` と `summary` は `cardReasons` と `summaryOf` を通ったもので、母の言葉の切り出しは前どおり防がれる。

「乗る」の型は当たりを足すだけなので見逃しは増えない。`make eval-rules` は見逃し 17/60、誤報 0/54 で前の行と同じ(`eval/RESULTS.md`)。聞き違いの兄弟で「警察を載る」(のるの同音の別の漢字)、「警察をなのる」(ひらがな、`phrases.ts` にひらがなの型は無い)、「警察乗る」(助詞が落ちる)はまだ当たらない。なのるは前からの見逃しで、載るはこの変更と同じ聞き違いの別の書かれ方なので、足すなら一緒に。
