## 指摘

1. (中の下、確かさは高い) 「すべて消す」と1分ごとの読み直しが重なると、消したあとに前の家族の「入った」が残る。[`ios/App/AppModel.swift`](ios/App/AppModel.swift) の `loadCases()`(219行あたり)と `loadSmiles()`(243行あたり)は、`guard route != .chooseRole` を await の前でしか見ていない。`keepCasesFresh` の `GET /cases` が飛んでいるあいだに `deleteEverything` が 2xx を返すと、`onRouteChange(.chooseRole)` が `presence.forget()` を呼ぶ。そのあとに前の家族の相談が入った答えが戻ると、`cases = fresh` のあとの `notePresence()` が `UserDefaults` の `mimamori.protectedJoined` に true を書き直す。作者が家族を作り直すと、母が入る前なのに入ったあとの形が出て、真ん中の「招待」が出ない。`cases` は次の読み直しで空に戻るが、`ProtectedPresence` は一度 true になると下がらないので、起動し直しても残る。右上の「招待」は残るので、招待できなくなることはない。直し方は、2つの関数の await のあとで `guard route != .chooseRole else { return }` をもう一度見ること。前の家族の `cases` が一瞬映るのは main からある挙動だが、それが端末に覚えられて消えないのはこの PR から起きる。
   これに近い道がもう1つある(確かさは中)。`init` の時点で `session.route` が最初から `.chooseRole` だと、`onRouteChange` が呼ばれないので `forget()` も呼ばれない。鍵はキーチェーンの `kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`(`ios/App/KeychainDeviceKeyStore.swift:61`)にあるが、`UserDefaults` と Application Support の印はバックアップから戻る。なので、新しい iPhone へバックアップから移すと、鍵は無いのに true が残る。`init` で、保護されたデータが読めて `session.route == .chooseRole` のときに `presence.forget()` を呼べば塞がる。

2. (軽い、確かさは中) 入ったあとの「招待」のシートは、通信に失敗すると読み込みの表示のまま止まる。[`ios/App/Views/FamilyHomeView.swift`](ios/App/Views/FamilyHomeView.swift) の `InviteSheet` は、`model.invite == nil` のあいだ `ProgressView()` しか出さない。出し直しのボタン(`NewCodeButton`)は `invite` があるときにしか出ないので、押し直す手段が無い。`problem` の知らせは `RootView` に付いているので、シートが開いているあいだは出ないと見ている(SwiftUI は出ている sheet の下の view から alert を重ねない。実機では確かめていない)。シートを閉じれば知らせが出て、開き直せば `.task` がもう一度走るので、止まりきりにはならない。`invite == nil` かつ `!model.isBusy` のときに `NewCodeButton` か「招待」を出せば直る。

3. (軽い、確かさは中) 母の家族用のビルド(`Mother.xcconfig` で本物の `familyToken` を入れたもの)を家族が自分の iPhone に入れ、Message Filter を入れると、家族自身の SMS から相談が生まれ、`ProtectedPresence` が「母が入った」と見なす。`POST /sms/{familyToken}`(`server/src/sms.ts:107`)は役を見ないからだ。設計の「相談は母の端末からしか生まれない」は、`page.ts`(`me.role === "protected"`)、`gmail.ts`、`consult.ts` では成り立つ。SMS では、どの端末のビルドに本物の印が入るかで決まる。配り方の確認だけでよく、この PR で直すものではない。

## 確かめて問題なかったこと

- `ProtectedPresence.update(smiles:cases:)` は役が `.protected` の笑顔だけを数える。抜けた人(`role` が nil)と家族の笑顔は数えない。相談は1件でもあれば入ったとみなし、一度 true になると下がらない。`cases` を書いたのと同じ main actor の流れで `protectedJoined` を書くので、相談があるのに招待だけの画面になってカードが隠れる道は無い。全員が同じカードを見る約束は保たれている。`swift test --filter ProtectedPresence` を流し、7件が通った(`Test run with 7 tests in 1 suite passed`)。試験は本物の `ProtectedPresence` と `InMemoryProtectedPresenceStore` を通しており、自分自身を確かめているだけの mock ではない。
- `forget()` は `onRouteChange` の `.chooseRole` の分かれ道で呼ばれる。401 も「すべて消す」もこの道を通る(`Session.call` の `defer`)。家族を作り直すには役の選択を通るしかないので、指摘1の重なりを除けば、前の家族の true は消える。最初のロック解除の前の起動では `.chooseRole` から家族の画面に移るだけで、`forget()` は呼ばれないので、覚えた値は消えない。
- `FamilyHomeView` について。入る前の画面では「招待」を押すと `createInvite` が走り、コード、「送る」(`ShareLink`)、小さな丸い出し直しのボタンが出る。入ったあとの画面では、右上の「招待」がシートを開き、同じ `InviteCodeView` と `NewCodeButton` を出す。`CaseCardView` は `JoinedSection` の `ForEach(model.familyCards)` にそのまま残っている。中身の「電話する」「解決」と確かめのダイアログは触っていない。
- DEBUG だけの `.onChange` と `.onAppear` は、中身がどれも `#if DEBUG` の中にある。参照している `ScreenshotStubTransport` はファイル全体が `#if DEBUG` で囲まれている。Release では空の閉包になるだけで、ビルドも動きも変わらない。
- main の取り込み。`init` は `pictureStore` と `presenceStore` を両方持つ。見本の `AppModel.live()` も `ScreenshotStubTransport.pictureStore`(同じファイルの64行にある)と `InMemoryProtectedPresenceStore()` を両方渡している。ほかの呼び出し元は既定の値で通る。
- 画面の文言は `.claude/rules/ios.md` に合っている。目に見えるのは「招待」「笑顔」「送る」と矢印の記号、コードの数字、期限の日時だけ。説明は `accessibilityLabel` と `accessibilityHint` に移っている。
- 設計の書き足し(`docs/design.md` の家族の画面の段落)はコードと合う。PR 本文の「残ること」(母が入っても笑顔も相談も無いあいだは招待だけ)も設計に書かれ、通知で入ったことが分かるとまで書いてある。`docs/plan.md` の API の表は変わっておらず、新しい呼び出しも足していない。
- 安全の約束は差分の外にある。段階、「安全です」と言わない決まり、だれに知らせるか、母の言葉や届いた文を家族に出さない決まり、30日での削除、注入された文の扱いには、この差分は触れていない。`ios/Core` の新しいファイルは Foundation だけを import している。秘密の値、実際の家族のデータ、外から写したコードも入っていない。
