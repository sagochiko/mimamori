## 確かめて問題なかったこと

- 試行をすべて `join_daily` で数える判断は正しい。新しい接続元だけを数えると、表にもうある接続元は1分に5回、1日に7,200回まで書ける。数百の接続元でも1日10万行に届くので、新しい接続元の上限では枠を縛れない。実装役の理由はそのとおりだった。D1 の文書では、新しい行は表と索引で2行、既にある行の更新は1行と読める。なので、1回の試行で書くのは多くて4行ほどで、1日2,000回なら8,000行くらいに収まる。Free の100,000行のうち、知らせ、相談、笑顔の分は残る。
- 代償は受け入れられる範囲だと思う。1つの接続元から1分に5回なら、2,000回まで約6.7時間かかる。接続元を数百そろえれば数分で届き、届くと UTC の日付が変わるまで、日本時間では翌朝9時まで、母と家族の参加もすべて 429 になる。ただし、参加は家族を作るときの数回だけで、[`docs/plan.md`](docs/plan.md) の API の表に「攻撃のあいだ止まるのは受け入れる」と約束として書いてある。知らせと DNS は止まらない。気をつけるのは、審査の期間中に審査員が2台目を参加させる場面で同じ止まり方が起こりうることくらいで、起こる見込みは低い。
- `join_daily` の条件つき UPSERT は、上限で断ったときに何も書かない。Node の `node:sqlite` で同じ文を上限2で4回流して確かめた。

  ```text
  0 [{"writes":1}] changes 1
  1 [{"writes":2}] changes 1
  2 [] changes 0
  3 [] changes 0
  ```

  上限に達すると `RETURNING` は空になり、`changes()` は0になる。`takeJoinAttempt` は空なら `join_attempts` に触れずに false を返す。接続元ごとの事前の SELECT が `join_daily` より先にあるので、1分に5回を超えた試行は日の数えも増やさない。同時に来た試行が日の数えを少し多めに数えることはあるが、多めに倒れるだけで害は無い。上限と同時の8回のテストで、通るのはちょうど4回。
- 30日の削除と参加の行の削除を分けた形。30日の batch を先に送り、参加の2つの DELETE は別の batch にした。参加の削除が壊れても30日の削除は進む。テストは参加の表の `prepare` を投げさせても、31日前の alert が消えることを見ている。2つを1つの batch に戻すと配列を組む段階で投げて alert が残るので、このテストは落ちうる形になっている。`budget.ts` の「three calls」は、写真の SELECT と batch 2つで3回なので合う。`join_daily` は昨日の分まで残し、おととい以前を消す。plan の「おとといより前の行は毎日の削除が消す」と同じ。
- `addressGroup` の /48 と IPv4 射影。`expandIpv6` は、末尾の点区切りを2つの hextet に直してから `::` を展開し、形の崩れたものは null で元の文字のまま返す。先頭5つが0で6つ目が `ffff` のときだけ IPv4 に戻す。点区切りの形、16進の形(`::ffff:c000:201`)、大文字、`0:0:0:0:0:ffff:` の書き方は、どれもテストで見ている。前回挙げた「点区切りで埋める0の数がずれる」も、この書き直しで消えた。携帯の回線では、1つの /48 に多くの契約者の /64 が入っている見込みがある。そうだとすると、同じ /48 の他人と1分に5回を分け合うことになる。今の利用者の規模なら、正しい参加が巻き込まれることは無いと見ている。
- 文書。[`docs/plan.md`](docs/plan.md) の `join_attempts`(/48、射影の扱い)と `join_daily` の行、API の表の 429 の説明は、コードの定数(`JOIN_WRITES_PER_DAY = 2000`、UTC の日付)と合う。[`.claude/skills/mm-deploy/SKILL.md`](.claude/skills/mm-deploy/SKILL.md) の手順5の直しも実際の書き込みと合う。join のループだけが書き、`join_attempts` に1分5回まで、それと日の数えを書き、毎日の削除が消す。0009 のマイグレーションのコメントも /48 と `join_daily` に直っている。
- 日の上限の 404 から 429 への切り替えは、経路のテストで見ている。上限の1つ手前に置いて404、次が429になる。終わったあとは元の値に戻している。
- 検証。`npx tsc --noEmit` はエラー無し。`npx vitest run` は `Test Files 20 passed (20)`、`Tests 1679 passed (1679)`。
