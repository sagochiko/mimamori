### 1. カードの「理由」に、母の言葉や届いた SMS の文がそのまま残る(確からしさ高、写しで確認済み)
- 該当箇所は `server/src/consult.ts:498`(insertAlert)、`:562`(合流して段階が重くなったときの UPDATE)、`server/src/judge.ts:375` の3つ。`quotes()` を通るのは `summary` を選ぶときだけで、Claude の `reasons` は `decide()` の `soundsSafe` を抜けたものが、そのまま `alerts.reasons` に入る。

- 具体的な壊れ方。母が「口座が凍結されるって電話で言われて…」と相談し、Claude が理由に「口座が凍結されると急がせている」と書くと、要約の1行には使われない。でもカードの理由には「口座が凍結される」(8字)が残る。SMS でも同じで、judge.test の「skips a reason that quotes the message」の場合、「「この口座は安全です」と移し替えを求める」が理由の欄に残る。
- テストが見落とした理由。`server/test/consult.test.ts:862` と `:876` の `expectNothingOf` は、通知の本文しか見ていない。作業用のコピーで `:862` の直後に `expectNothingOf(said, card.alert.reasons)` を足して流すと落ちた。
  ```text
  CARD_REASONS ["口座が凍結されると急がせている","お金の話で急がせている"]
  AssertionError: expected '口座が凍結されると急がせている\nお金の話で急がせている' not to contain '口座が凍結される'
  ```
  ニセ警察のテストの理由の確かめ(`fixed.includes(r) || /^[^「」]+$/.test(r)`)も、かっこが無ければ何でも通るので、意味のある確かめになっていない。
- 直し方の案。保存する前に、規則の決まった理由以外を `quotes(r, sources)` でふるい、全部落ちたら規則の理由か PLACEHOLDER に戻す。consult、judge、合流の UPDATE の3か所すべてで行い、カードの `reasons` にも抜粋が無いことをテストで確かめる。

## 確かめて問題なかったこと
- 引き受けと返事の経路は外れている。`server/src/index.ts` から2つの経路が消え、どの家族の端末からでも 404 になり、`relays` は0件のまま、通知も0件だった(cases.test)。`relays` と `accepted_at` に書き込むのは、消すとき(retention、すべて消す)だけで、ほかの経路からは書けない。
- 前の版の `accepted` は、裏側(`loadViews`)でも iOS(`CaseState.init(from:)`)でも、解決していないものとして読む。どちらでも解決にでき、`assignee_member_id` は解決を押した人で上書きされる。
- 解決を押せるのは家族だけで、母は 403、ほかの家族の相談は 404。同時に押したときは条件付きの UPDATE で1人だけが記録し、知らせは1回だけ。もう一度押しても誰にも知らせない。解決の知らせは母にも押した本人にも行かない。いずれもテストがある。
- AI はいつも答える。`watching` と `deliverAiReply` が消え、`recordAiReply` は状態を見ずに書く。「見ています」が出ないこともテストで確かめている。
- 30分の見張りは「解決していない」で動き、家族への知らせの題は「まだ解決していません」で、母への通知に「解決」「対応中」「見ています」「安全」が出ない(テスト)。iOS では、`renotifiedAt` があるか30分たつと「家族から返事がまだ。急ぐなら電話して」に変わり、解決したら消え、3日たつと消える。
- 要約の1行が通る経路。ニセ警察は決まった1行。Claude の topic と理由は8字の写しと「安全」を外す。SMS などは経路、理由、ドメインから作る。合流して重くなったときは、要約も重いほうの1行に替わる。見張りの再通知と、知らせ直しのたびに作る通知は、同じ `alerts.summary` を使う(古い行は指摘2を参照)。
- `ios/Core` が import しているのは Foundation だけ(11ファイル)。iOS 側に古い記号や文言(accept、relay、assignee、対応中、見ています、引き受)は残っていない。母の画面の文言は名札と状態だけで、説明は accessibilityHint に移してある。
- 消したテストは、引き受け、返事、読み上げ、受け持ちが抜けたときのものに対応している。残ったテスト(PhoneNumber、3件まで、3日で消える、30分)は CaseCardTests に移っていて、弱めた跡は無い。
- 文書の古い言葉。CLAUDE.md、CONDITIONS.md、mm-reviewer.md、audit.md、design.md のデモと差の示し方は、新しい決まりに合わせてある(残りは指摘7)。
