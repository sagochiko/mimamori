## 指摘

### 1. `では` を使わない打ち消しが `DENIES` を抜け、安心させる行が家族のカードに載る(重い抜け、確度は高い)

場所は [`server/src/agents.ts`](~/develop/mimamori/.claude/worktrees/issue-12-managed-agents/server/src/agents.ts) の365行目。

```ts
const DENIES = /(では|じゃ)(な|ありません|ございません)|形跡は?(な|無)|もの(では|じゃ)な|ではありません/;
```

`server/` で `npx tsx -e` から本物の `parseEvidence` を呼んだ(URL は `https://www.npa.go.jp/x`、1行ずつ渡した)。次の行はどれも `KEEP` になる。

```text
KEEP 偽装でなく、注意喚起にも載っていない
KEEP 偽装されていない、詐欺の手口と一致しない
KEEP 偽装の疑いはなく、注意喚起の対象外
KEEP 偽装は見られず、正規を装う手口とは異なる
KEEP 偽装の跡はなく注意喚起とも合わない
KEEP なりすましとは考えにくく、被害の報告も無い
KEEP なりすましの可能性は低いと警察庁の注意喚起から読める
KEEP なりすましに当たらない、と注意喚起から分かる
KEEP 偽装とは言えない、注意喚起にない手口
KEEP 偽装を疑う理由は無いと警告の内容から分かる
```

問題になる場面はこうだ。届いた本文に仕込んだ文や、エージェントの言い回しの揺れで、公式の URL を付けた「偽装されていない、詐欺の手口と一致しない」が報告されると、家族の読み上げに「届いたものは本物」という根拠として載る。3回目の指摘1と同じ種類の穴で、言い回しが1つずれただけで通ってしまう。「安全と言わない」の決まりを、根拠の欄から破ることになる。

直す方向の案を置いておく。偽装や詐欺の語に限らず、行の中の打ち消し(`な[いくさか]`、`無[いく]`、`ません`、`ず`、`にく[いく]`、`低い`、`違う`、`異な`、`対象外` など)を全部落とす。そのうえで、公式の言い方だけを先に取り除いて除外から外す。外すのは `こと[はがも](ない|無い|ありません|ございません)` と、呼びかけの `ないよう`、`ないで`、`ないでください` だ。手元の `node -e` で試した結果、上の10行の多くが落ち(試した8行はすべて `DROP`)、「暗証番号を聞くことはありません、と警察庁が注意している」「警察が電話で暗証番号を聞くことはない、と注意を呼びかけている」「SMSのリンクを開かないよう注意を呼びかけている」は残った。テストの `reassure` の配列には上の10行を足すとよい。

### 2. `(では|じゃ)な` が「〜ではなりすまし」の頭に当たり、公式のふつうの根拠を落とす(この直しの退行、軽い、確度は高い)

同じ365行目。`では` に続く `な` が「なりすまし」の1字目にも当たる。同じ方法で試すと、次の行が落ちる。

```text
DROP 最近ではなりすまし SMS が増えていると注意している
DROP SNSではなりすましアカウントの被害が出ている
DROP SMSのリンクではなく公式アプリから確認するよう呼びかけている
```

落ちる側なので安全の側には倒れている。ただ、「なりすまし」は `WARNS` の中心の語で、調べものが空振りする原因になる。`(では|じゃ)な(?!りすま)` にするか、指摘1の書き方に変えれば直る。「ではなく」は「偽装ではなく本物」もあるので、落としたままでよい。
