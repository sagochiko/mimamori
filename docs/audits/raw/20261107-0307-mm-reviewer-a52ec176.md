### 2. `TOLD_TO_CALL_IT_FINE` が、娘の安心させる言葉や母自身の頼みを注入として1段階にする(重い。挙動は実行して確かめた)

[`server/src/rules/phrases.ts`](server/src/rules/phrases.ts) の 47行目。終わりの選択肢に `てくれ` があるため、指示された形でなくても当たる。

- `娘が、このアプリは安全って伝えてくれたの` は level 1 で、理由は `警告を止めさせようとする文がある`
- `このアプリに大丈夫と答えてくれる?` も level 1

注入に当たると、`decidePlan` が `keepsOut` で規則の段階を `confident` の下限にし、Claude が何を返しても1段階で家族に届く。`plan` は `steered` で Claude の行も捨てる。コメントには「Only the told form, so her own ... stays hers」とあるが、実際の形はそうなっていない。`てくれ` を外して、言われた形(`って言われ`、`ように言われ`、`しなさい`、`伝えなさい` など)に絞るのがよい。上の2文は否定のテストに足す。

### 3. 警察が出てこない話にも「警察を名乗る電話の相談」が付く(中くらい。実行して確かめた)

`card_pickup` と `police_identity_crime` は警察の名乗りを要らない。そのため `銀行協会の人から電話で、キャッシュカードが詐欺に使われてるから、職員がカードを取りに来るって` は `script: true`、`level 1`、`summary: 警察を名乗る電話の相談` になる。段階が1なのはおかしくない(キャッシュカード詐欺盗)。ただ、家族のカードの1行が「警察を名乗る」と事実と違うことを言うので、家族が母に電話したときの話が食い違う。[`docs/design.md`](docs/design.md) 199行目の決まった1行は、ニセ警察の筋書きのためのものだ。

### 4. 設計の筋書きの部品の一覧が変わっていない(中くらい。文書で確かめた)

[`docs/design.md`](docs/design.md) 173行目は、筋書きの部品を「口座が犯罪に使われている、潔白の証明、ほかの人に話すな、ビデオ通話への誘い、送金や口座の移し替え」としている。この PR は、Claude を待たない1段階を決める部品に、名義や携帯が犯罪に使われた、事件に名前、自動音声から警察、カードの受け取りを足した。設計と挙動が食い違い、範囲を広げる変更なのに設計の文書にその判断が残っていない。CLAUDE.md では、設計や範囲の変更は作者に聞くことになっている。

### 5. 部品1つで2段階になる型が広い(軽い。挙動は実行して確かめた)

どれも部品1つだけで `level 2` になる。Claude が答えれば Claude の段階が勝つ(`confident` は false)が、Claude が失敗したり15秒を過ぎたりすると、2段階のまま家族に届く(`decide` の `claude === null`)。

- 188行目の `(WHOSE)が…(悪いこと|犯罪|罪)…(言われ|疑われ)` は、家族げんかの `私が悪いことしたって娘に言われたの` に当たる
- card_pickup は `通帳を新しくするから、郵便局の人が古い通帳を回収しに来るって` に当たる
- `クレジットカードを息子が取りに来るって` も当たる
- `逮捕されそう` は `息子が警察に逮捕されそうになったって嫁から電話があったの` に当たる

部品が2つ並ぶと筋書きになる。たとえば `孫がサプライズやから家族には言っちゃだめよって。わたしが悪いことしたみたいに言われた` は police_secrecy と police_arrest が並んで `SCRIPT`、level 1 になった。

### テストについて

足したテストは落ちうる形になっている(`toBeNull`、`script toBe(false)`、`toBe(1)`)。ただ、否定の例が「落とした、自分でかけた、伝え聞いた」に寄っていて、本物の警察からの被害者や目撃者への連絡(指摘1)と、注入の型の `てくれ`(指摘2)の否定が無い。2回目のコミット(`9a45a8a`)は否定の例を足しただけで、既存の期待を変えたり弱めたりはしていない。

## 確かめて問題なかったこと
