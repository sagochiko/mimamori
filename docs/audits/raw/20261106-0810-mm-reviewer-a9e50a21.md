## 指摘

### 1. allow の `gh pr close *` と `gh project *` で、取り消せない削除が判定を通らずに走る

場所は `~/develop/mimamori/.claude/worktrees/harness-drop-deny-ask/.claude/settings.json` の allow で、追加した `"Bash(gh pr close *)"`(57行め)と、もとからある `"Bash(gh project *)"`(59行め)。確かさは高い。

作業の木で `guard-prod.sh` に直接流して確かめた。どちらも何も言わずに通る。

```text
exit=0 [gh pr close 41 --delete-branch]
exit=0 [gh project delete 1 --owner sagochiko]
```

- `gh pr close 41 --delete-branch` は遠隔のブランチを消す。[`CLAUDE.md`](CLAUDE.md) の28行めは「遠隔のブランチを消す push ... は作者に聞く」と書くが、`guard-prod.sh` が見るのは `git push` の形だけ。allow に当たるので auto mode の判定も通らない。
- `gh project delete`、`item-delete`、`field-delete` も allow の `gh project *` に当たり、Projects の板が取り消せずに消える。

どちらも PR の前から `gh pr *` と `gh project *` で通っていたので、この PR で新しく生まれた穴ではない。ただ、この PR は「allow に当たる取り消せない削除が確認も判定も無しに走る」のを塞ぐために allow を分けたもので、`gh pr` のサブコマンドは一つずつ選び直している。その選び直しで `close` を明示的に入れたのは、PR の狙いと食い違う。

[`docs/harness.md`](docs/harness.md) の159行めは、一覧のサブコマンドを「作業の流れで使う書き込み」と書いている。しかし skill とエージェントの中で `gh pr close` を使う所は無い(`grep -rn "gh pr close" .claude/skills .claude/agents CLAUDE.md` で0件)。だから外しても `/mm-task` は困らない。

直し方は2つ考えられる。`gh pr close *` を allow から外して `rule none 'gh pr close 41 --delete-branch'` を足すか、`gh project *` もサブコマンドごとに分けるか。作者が選んだのは `gh issue delete` と `gh pr merge` の2つなので、外す範囲を広げるかは主から作者に確かめてほしい。
