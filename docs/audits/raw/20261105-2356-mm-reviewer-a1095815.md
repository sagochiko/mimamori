## 指摘

### 1. 周りの機能に進む条件が、新しい段落で解かれたのか書かれていない(中、確かな度合いは高い)

`~/develop/mimamori/CONDITIONS.md` の37行目。

前の段落はどれも「周りの機能には、主役が実機で通るまで進まない」と書いている。23行目は Gmail と Safari を名指しで「進まない」の一覧に入れ、25行目は主役の3つがまだそろっておらず実機の確かめ(#48、#106)は作者待ちだと書き、27行目と29行目は「周りの機能には、主役の一続きが実機で通り2台並べて撮れるようになってから進む」と読んでいる。夜の段落(33、35行目)は #14 と #10 だけを「#14 は例外、#10 は一覧に無かった」という理由つきで先に出し、「夜に変わったのは条件ではなく順番だ」と明記している。

新しい段落が決めたのは「11月7日の節目で外す候補にしない」で、これは節目の判断の話であって、進む条件の話ではない。ところが最後の文「そのあと Safari と Gmail のどちらを先に作るかは、まだ決めていない」は、次に作るのがこの2つだと前提している。新しいセッションが上から読むと「進まない」を3回読んだあとに「どちらを先に作るか」に当たり、主役の実機の確かめ(#48、#106)が通る前に #15 や #16 を始めてよいのかが決まらない。残り約2日で作者の言葉が「絶対やる」なので、実際には条件が解けたと読むのが自然だが、それならこの段落に、前の段落と同じ「この段落は、答えをこのセッションがどう読んだかだ」の形で、朝の条件(27行目)をこの2つについて解いたのか、それとも主役の確かめを待つのかを1文で書くべき。

同じことが `docs/plan.md` にも残っている。160行目は「これがそろって実機で通るまで、タスク7(Gmail)、9(Safari)... には進まない」「周りの機能は間に合わなければ提出から外し」のまま、168行目は Safari を11月6日に置いたまま。`CLAUDE.md` の「文脈の引き継ぎ」は決めたことを `docs/plan.md` にも書くとしているが、この PR はどちらも触っていない。`plan.md` の160行目に1行足すか、`CONDITIONS.md` の段落にこの3つについては160行目より優先すると書くかのどちらかが要る。

### 2. 確かめの問いの中身と、伝言で受け取ったことが書かれていない(低〜中)

同じ37行目。27行目と33行目は問いの文をそのまま引いていて、読み方が問いに依るからそうしている。新しい段落は答え(「外す選択肢は無いだから絶対やるでしょ」「これも絶対やる」)だけを書き、何を聞いたかが無い。「これも」の「これ」が文中で何を指すか分からない。親の指示によれば作者の言葉は前のセッションからの伝言だが、段落はそれを書かず、直接聞いたように読める。何を2回聞いたかと、前のセッションの聞き取りを受けたものだという1文を足せば足りる。

### 3. 「偽のショップ」が作者の言葉にも Issue にも無い(低)

同じ37行目の「Safari(#16、広告から入る偽の警告や偽のショップ)」。「偽の警告」は `docs/design.md` の69行目(偽のセキュリティ警告、容量がいっぱいの広告)と合う。「偽のショップ」は Issue #16 の本文、`docs/design.md`、`docs/plan.md` のタスク9、引いた作者の言葉(「広告とか結構課題」)のどこにも出てこない。「作者が...決めた」の文の中に置かれているので、作者が Safari の範囲をこの2つに絞ったように読める。セッションの補いなら、そう分かる書き方にするか削る。

## 確かめて問題なかったこと

- 時刻の決まり。差分の2ファイルとも日付だけで、時刻の形は無い。`SKILL.md` の `on 2026-11-05` は英語の skill の中の日付で、`.claude/rules/docs.md` の範囲(`docs/**`、README)の外。引き継ぎのファイル名の `<YYYYMMDD-HHMM>` は変更前からある

- ハッカソンの決まり。秘密、家族のデータ、外から写したものは無い。`ios/Core` は触っていない
- 設計の約束(段階、「安全です」を返さない、通知先、カードの共有、30日の削除)と、注入の経路。文書だけの変更で、どれにも当たらない
