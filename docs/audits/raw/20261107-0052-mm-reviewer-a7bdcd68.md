## 指摘

### 1. 画像だけの相談で Claude が scam の3段階と答えると、「リンクを開いて」「認証コードを入力して」がそのまま母に読まれる(重い、確度は高い)

網を `kind: "help"` だけに当てたので、`server/src/consult-judge.ts` の行 940 から 944(`claude.kind === "scam"` の3段階の分かれ)は、Claude の `action` を `readable` だけで見ている。`readable` は「安全」「大丈夫」のような言い切りと「家族に伝えました」しか止めない。`SENSITIVE` と `CONTACT` はこの分かれでは見られない。画像だけの相談には母の言葉が無いので、`ownSensitive` も空になる。

`judgeConsult("", [], …, undefined, true)` を `tsx` で直接呼んで確かめた。Claude が scam、`level: 3` で返した場合の結果は次のとおり。

```text
{"a":"メッセージのリンクを開いて手続きを進めて","level":3,"toFamily":false,"record":true,"reply":"メッセージのリンクを開いて手続きを進めて。お金や暗証番号を聞かれたら止めて、家族に確かめて"}
{"a":"届いた認証コードを画面に入力して","level":3,"toFamily":false,"record":true,"reply":"届いた認証コードを画面に入力して。お金や暗証番号を聞かれたら止めて、家族に確かめて"}
{"a":"画面の「送金する」を押して","level":3,"toFamily":false,"record":true,"reply":"画面の「送金する」を押して。お金や暗証番号を聞かれたら止めて、家族に確かめて"}
{"a":"構成プロファイルをインストールして","level":3,"toFamily":false,"record":true,"reply":"構成プロファイルをインストールして。お金や暗証番号を聞かれたら止めて、家族に確かめて"}
```

丸(`tap`)は付かない。最後の `return` でしか付かないからだ。記録は残る。それでも、母に返る最初の1文は危ない案内そのもので、家族には知らせが行かない。困るのは、本物らしく作られた SMS や宅配の不在通知のスクショを Claude が「印が無い、本物か確かめられないだけ」と読んで3にした場面だ。`CONSULT_SCHEMA` の `level` の説明は、まさにそういうときに3を求めている。画像の中の「リンクから再配達の手続きを」という文に引かれた `action` が、決まった1行の前にそのまま付く。母の言葉がある文字の相談でも、Claude の scam の `action` は見られていない(`judgeConsult("このSMS見て", …)` でも同じ答えが返った)。その意味では以前からの穴だ。ただ、文字の相談では母の言葉に「認証コード」「振込」が入ればそこで止まる。画像の経路だけは、Claude の文のほかに止める壁が無い。

実装役は、scam にも網を当てると1段階の警告が下がると説明している。コードで見るとそうはならない。行 906 から 917 の `sensitive.length > 0` の分かれは、`level <= 2` なら段階をそのまま保ち、答えを `basis` と `SCAM_ACTION` と「家族に伝えました」にする。下がるのではなく、Claude の `action` が決まった行に替わるだけだ。本当にかかる代償は、3段階の scam が `HANDOFF_REPLY` の2段階として家族に回ることのほうになる。

家族に回さずに塞ぐ直し方がある。`image && claude.kind === "scam" && level === 3` のときは、`action` に `SENSITIVE` か `CONTACT` が当たれば `lowConcernReply(basis, null)` にする。つまり Claude の `action` を捨てて、決まった1行だけにする。1段階と2段階の答えも、家族への知らせも変わらない。「リンクは開かないで」のような良い案内も落ちるが、決まった1行が残るので害は無い。足す試験は、画像だけの scam、`level: 3`、`action` が「リンクを開いて」「認証コードを入力して」の2件だ。答えに `action` が入らず、`handoff` が false のままになることを確かめる。

## 確かめて問題なかったこと

- help に当てた網。`claudeLines` は `action`、`reasons`、`topic` を `normalize` してから見ている。`SENSITIVE` に当たれば行 919 から 929 の `HANDOFF_REPLY` で家族に回り、`tap` は付かない。`CONTACT` に当たれば行 946 から 952 の `LOW_CONCERN_ACTION` で3段階の記録になり、`tap` は付かない。`askedEarlier` との合わせ方(`guidedLines`)も、文字の相談では前と同じ `normalize(claude.action)` だけを見る。画像の無い相談では `claudeLines` が空なので、`CONTACT` の分かれも前と変わらない。設定画面の「メール」のような help も決まった1行に倒れるが、これは安全な側の取りこぼしで、危なくはない。
- `record: image`。網を抜けた画像の help は、3段階、`notified` 0、push なしで `alerts` に残る(試験 `keeps a record of phone help from an image` が `pushes` の長さ0まで見ている)。`tap` は `consult.ts` 行 284 の記録の経路でも `tapOn` を通して返る。画像の無い help は `record: false` のままだ。
- 聞き返しを飛ばす条件。`!image` は `ASK_AGAIN_REPLY` の分かれだけに入っている。画像があるときの「これ何」と `handoff: true` は、下の家族に回す分かれに進む。
- base64 の両端だけの検査。`length % 4` の検査は残っている。短い `data` では2つの `slice` が重なるだけで、正しく動く。中ほどが壊れていると Anthropic が400を返し、`null` から「うまく答えられませんでした。家族に伝えました」の2段階に倒れる。安全な側の失敗で、試験もある。呼べるのは母の端末の鍵だけだ。
- 足した8件の試験は、直しを外すとどれも落ちる。コードで照らし合わせた。送金、認証コード、構成プロファイルの3件と、リンクの1件、「家族に知らせないで」の1件は `claudeLines` が無ければ help の `action` と `tap` が返る。記録の1件は `record: image` が無ければ行が無い。「これ何」の1件は `!image` が無ければ `ASK_AGAIN_REPLY` になる。base64 の1件は全体の正規表現なら400になり、200を待つ試験が落ちる。`npx vitest run test/consult-image.test.ts test/consult.test.ts` は579件すべて通った。
- `docs/design.md` に足した1文は、help の網、家族に回す条件、決まった3段階の1行、網を抜けた案内の記録の4つとも、コードと合っている。scam の3段階の `action` をどう扱うかは書かれていない。指摘1を直すなら、同じ段落に1文足すのがよい。
- 画像の help の `topic` と `reasons` が記録に入るようになり、家族の記録に画像の文を写した行が載りうる。`quotes` は母の言葉としか比べないからだ。ただ、scam の画像の記録は前から同じ形で、プロンプトの「本人の言葉をそのまま写さず」に任されている。この直しで新しく生まれた重い穴ではないと判断した。
