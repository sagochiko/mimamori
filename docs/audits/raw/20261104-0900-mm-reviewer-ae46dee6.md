### 1. 直すべき(マージを止める)。転送に見えるリンクは、そのホスト自身の似せたドメインと見慣れない形を調べなくなる

### 3. 軽い。「ー」や括弧で書いた電話番号は電話番号に数えず、口止めだけの文面が2段階から null になる

場所は `server/src/rules/phrases.ts` 209行の `PHONE_NUMBER`。

区切りに「-」と空白しか認めないので、日本語でよく書く「03ー1234ー5678」(長音記号)や「03(1234)5678」は電話番号にならない。中の「1234」が4〜8桁の数字に当たり、認証コードだけと見なされて口止めを数えなくなる。

```text
P1  sms「【警視庁】確認番号をお伝えします。この件は誰にも言わないでください。03ー1234ー5678 へお電話を。」
    old L=2 | r2 L=null | now L=null [認証コードの知らせに見える]
P1b 同じ文で「03(1234)5678」
    old L=2 | r2 L=null | now L=null
```

ただし、電話番号を書かずに「確認コード 4821。この件は誰にも言わないでください。」と書けば、作りどおり null になる(P1d)。「確認コード 1234 を入力してください。この件は誰にも話さないでください。警察です」も null(old は L=1 c=1)。「警察です」はニセ警察の筋書きの部分に入っていないため。口止めだけの文面は本物の認証コードと同じ形なので、例外の作りとしては受け入れた範囲と読める。増えた道は電話番号の書き方だけで、軽いとした。区切りに「ー − ‐ ( ) （ ）」を足す案がある。

### 4. 軽い。家族の口止めの型で、「教え」以外の動詞の本物の注意と、家族の話が1段階になる

場所は `server/src/rules/phrases.ts` 30行。

「教え」を外したが、同じ注意を「伝え」「言わ」で書くと今も仕込みの文に当たる。8字に広げたので、家族の内緒話も当たるようになった。どれも confident ではないので迷惑フォルダには行かないが、Claude が失敗すると規則の1段階で母と家族に知らせが行く。計画のタスク4の「認証コードだけの SMS は null」に当たるのは G1 と G5。

```text
G1 sms「認証コード 123456。このコードはご家族にも伝えないでください。」 old L=1 | r2 L=1 | now L=1 c=0
G2 gmail(info@smbc.co.jp)「暗証番号はご家族にも伝えないようにしてください。」 old L=null | r2 L=1 | now L=1 c=0
```

G4 は8字に広げたことで新しく当たった。家族からの SMS は連絡先にあれば SMS の拡張には来ないが、Gmail の経路では起こりうる(推測)。本物の文面に「ご家族にも伝えないで」がどれだけ出るかは、銀行の公開の案内をこの場では開いておらず確かめていない。確かめるなら、分ける前の置き場の本物の認証コードと銀行の注意の例文をこの型に流す。

### 5. 軽い。README と記録の「公式」の説明がコードより狭く、測る数とも合っていない

場所は `eval/README.md` 70行、`docs/dev-log.md` の2026年11月4日 08:05 の項、`server/src/rules/index.ts` 266行、`eval/lib/score.ts` 4行と86行、`eval/README.md` 56行。

README と記録は「公式の送り主か `https://` から始まる公式のリンク」と書くが、コードは `http://` のリンク、本文に書いたメールアドレス、`input.url` と `input.domain` も公式に数える。詐欺の SMS の本文に「問合せ support@amazon.co.jp」と書くと confident が外れる(M1、old L=1 c=1、now L=1 c=0)。公式のリンクを足すのと手間は同じなので引き換えの大きさは変わらないが、README に書いていない入口になっている。転送のリンクを公式に数えないことも README に無い。

README の「この形の見逃しは迷惑フォルダの数には出ない」は、出力に迷惑フォルダの数が無いので読み手に通じない。逆に、`genuine_at_level1` は confident を見ずに段階1を数え、README 56行はそれを「迷惑フォルダ行き、DNS で止める」と説明している。今回の直しで、公式の注意喚起(B1、B2、A4、A4c)は段階1のまま confident でなくなり、迷惑フォルダには行かないのに `genuine_at_level1` には数えられる。「本物を1段階にするのは0件が目標」の数が、迷惑フォルダに回した本物の数を表さなくなる。`genuine_confident` のように confident の本物を別に数えるか、README の説明を直す案がある。

記録の数え方は事実に合っている。`r3/after.txt` は75行で、2回目より下がった行は4件(D1、E1、E2、E3)、直す前より下がった行は13件で、本物の10件と通知の3件(A6、B4、T ignore with link)に分かれる。
