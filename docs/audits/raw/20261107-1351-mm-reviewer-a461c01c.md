## 指摘

1. システムプロンプトの文の順番が逆になり、Claude に「削除なら handoff を true に」と読ませる形になっている(確度は高い。Claude が実際にそう動くかは中くらい)
   [`server/src/consult-judge.ts`](server/src/consult-judge.ts) の331行は次のとおり。
   ```text
   …構成プロファイルを入れることは案内しません。写真、トーク、アプリなどを消すことは、ほかの困りごとと同じく案内します。そのときと、答えきれないときは handoff を true にします。
   ```
   削除の一文を「案内しません」と「そのときと」のあいだに差し込んだため、「そのとき」が直前の削除の文を指して読める。Claude が `handoff: true` を返すと次の2つが起きる。
   - 文字の「写真を消したい」は `claude?.handoff` の枝(992行あたり)に入り、`HANDOFF_REPLY` で家族に回る。作者が外したかった動きがそのまま残る。
   - 画像だけのストレージのスクショは、新しい聞き返しの枝(944〜962行)の `claude.handoff && !CONTACT` に入り、案内も丸も出ずに「この画面で何をしたい?」になる。作者のビルド10の場面が直らない。

   試験は Claude を差し替えて `handoff: false` を渡しているので、この食い違いでは落ちない。`make eval-rules` も Claude を呼ばない。直し方は、削除の一文を「そのときと、答えきれないときは handoff を true にします。」のあとへ動かすこと。直したあと、`rules+claude` で削除の相談を数件流して `handoff` が false で返るかを見るとよい。

2. 初期化とリセットまで案内しない話題から外したのは作者の決定を越えていて、見逃しの道ができている(確度は高い)
   作者が決めたのは「写真、トーク、アプリを消す」だ。実装では古い削除の網(`初期化|リセット|消去`、アカウント、バックアップを含む)を `SENSITIVE` からまるごと外した。151行の `DELETION` は確かめの一言を足すためだけに使い、家族へは回さない。プロンプトも「アプリなどを」と広げた。具体的には次の場面で家族に届かない。
   - 画像だけの相談で、サポート詐欺のページのスクショに「ウイルス除去のため初期化してください」とある。Claude がこれを `help` と読み、初期化の手順に丸を付けて返すとする。PR #186 の網(910〜916行の `claudeLines` と `guided`)は前なら 初期化 で家族に回したが、いまは `SENSITIVE` にしか当てないので通る。`CONTACT` も「設定」「初期化」には当たらない。母には `DELETE_CHECK` 付きの初期化の手順と丸が出て、知らせは行かない(記録だけ3段階で残る)。
   - 文字の「サポートの人に電話で言われて、iPhoneを初期化したい」。`CONTACT` の「電話」で `LOW_CONCERN_ACTION`、3段階、家族へ知らせなしになる。前は家族に回った。[`server/src/rules/phrases.ts`](server/src/rules/phrases.ts) に初期化を見る規則は無い(grep で見た。388行の遠隔操作の規則は「入れて」「インストール」だけを見る)。
   - 「アプリを消す」の中に、みまもり自身を消すことも入る。「みまもりのアプリを消したい」が確かめの一言付きで案内され、家族には何も届かない。消せば見守りそのものが止まる。

   [`docs/design.md`](docs/design.md) の221行は「作者が2026年11月7日に決めた(#234)」のすぐあとに「初期化(…)も同じ網で確かめの一言が付くだけで、家族には回らない」と書いている。実装役が広げた部分を作者が決めたように読める。[`docs/dev-log.md`](docs/dev-log.md) にもこの判断が無い。初期化を試験していた [`server/test/consult.test.ts`](server/test/consult.test.ts) の古い1件(2683行あたり)はプロファイルに書き換えられ、初期化の試験は1つも残っていない。提案は次のとおり。
   - `初期化|リセット|(すべて|全部).{0,8}消去` と、みまもりのアプリの削除を `SENSITIVE` に残す。外すなら作者に聞く。設計の範囲の変更なので AskUserQuestion にあたる。
   - プロンプトの「など」を削る。
   - 上の2つの場面の試験を足す。

3. 画像だけの相談に聞き返したあと、母の答えには画像が付かない(確度は高い。重さは中くらい)
   `VoiceConsult.pictured` は `hasPicture = false` にし(257行)、`AppModel` は `.sendPicture` の効果で `attachedPicture` を空にする。母が「この画面で何をしたい?」に「写真を消したい」と答えると、それは画像の無いふつうの相談になる。丸は付かず、「この画面」が何を指すかも Claude には分からない。アプリの中で画像だけになるのは、`canSend(draft:)`(214行)が言葉の無い送信を許しているからだ(試験の「画像だけでも送れる」)。直し方は2つある。どちらにするかは親が選ぶ。
   - アプリの中では、画像が付いているときは言葉を必須にする。作者の決定1の文言に合う。共有の拡張は作者が受け入れたとおり、そのままでよい。
   - 答えが聞き返しの1行だったら、付けた画像を欄に戻す。

4. 画像だけで Claude が答えきれないとしたときは、記録も残らない(確度は高い。重さは低から中)
   962行は `record: scamRead` で、`handoff` の枝では記録が何も残らない。試験も `alertRow` が null になることを確かめている。この枝が拾うのは、Claude が自分で答えきれないとし、しかも網(`SENSITIVE` と `CONTACT`)に当たらなかった画像だ。銀行のアプリや見慣れない画面が入りうる。詐欺と読んだ枝には「家族があとから見られるように」と3段階の記録を残しているので、同じ理由でここも `record: true` にするのがよい。作者が決めたのは「家族に回さない」で、「記録しない」ではない。作者のビルド10の1回目は削除の網が原因だったと見られ(Claude の案内の「削除」が `claudeLines` に当たった)、指摘2の形に直してもこの枝は要らないかもしれない。

5. 送った直後に自分の泡の上端が顔の列の下に隠れる(コードから読んだ原因で、画面では見ていない。#221 からあったものと見ている)
   `AppModel.apply` の `.sendPicture`(423行)は、送った時点で `shownPicture` を母の行に付ける。これで母の泡と `LiveView` のあいだに、高さ420ptまでの `ShownPictureView` が入る。そのうえ [`ios/App/Views/ProtectedHomeView.swift`](ios/App/Views/ProtectedHomeView.swift) の `reveal` は `.thinking` のとき `proxy.scrollTo(liveID, anchor: .bottom)`(226行)で下端に合わせるので、母の泡が会話の欄の上へ押し出される。この流れは main でも同じなので、#234 が新しく起こしたものではない。ただ、付けてから送る形になって目に付きやすくなった。直し方は2つある。画像が付いているときの `.thinking` は母の行に `anchor: .top` で合わせるか、丸付きの画像を答えが届いてから出す。

6. 精度の記録は、この変更の証拠にならない(確度は高い。製品の不具合ではない)
   [`eval/README.md`](eval/README.md) にあるとおり、`rules` の行は話題で家族に回すかどうかを数えない。なので「変える前と同じ数」は、削除を外しても外さなくても必ず同じになる。`eval/results.jsonl` の新しい行は `git_sha` が docs のコミット(`eb63717`)で、`notes` が空だ。`RESULTS.md` の行には説明が書いてあるので、両者が揃っていない。指摘1と2の確かめには `rules+claude` が要る。
