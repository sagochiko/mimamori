## 指摘

1. 時刻の無い記録が30日を過ぎても端末に残り続ける(設計との食い違い。食い違いは確か、実際に起きる見込みは低い)

   [`ios/Core/Sources/MimamoriCore/Chat.swift`](ios/Core/Sources/MimamoriCore/Chat.swift) の `restored(from:at:)`(212行目あたり)で、`at` の無い記録は消す対象から外れる。

   ```swift
   // One with no time cannot be aged, so it stays, within the newest 50.
   log.messages.removeAll { $0.at.map { now.timeIntervalSince($0) >= keptFor } ?? false }
   ```

   [`docs/design.md`](docs/design.md) の205行目は「50件より少なくても、30日たったものは読み込むときに落とす」と決めており、238行目は「残す期間は30日」としている。この PR では時刻の無い記録が、新しい50件に押し出されるまで何か月でも画面に出て、`save()` のたびにファイルへ書き戻される。母があまり相談しなければ、いつまでも残る。main では `at` が必須で、こういうファイルは読めずに空の会話になり、次の書き込みで上書きされて消えていた。この PR でその逃げ道が無くなり、「30日で消す」が守られない道が初めてできた。

   PR の本文にあるとおり `at` は最初の版から書いているので、今の端末にこういう記録はまず無い。ただ、Issue の「古い記録は時刻なしで読めるようにする」と設計の30日の決まりがぶつかっていて、コードは30日の決まりを捨てる側を黙って選んでいる。直し方は2つある。年齢が分からない記録は読むときに落とす(設計どおりで1行。`untimedRecord` と `untimedThenTimed` の試験は直す)か、残すなら設計の205行目にその例外と理由を書く。母の言葉を端末に長く残さない側として前者を推す。

   裏側へ送る道は無い。`history(at:)` と `history(for:at:)` は時刻の無い記録を必ず外していて、`untimedRecord` の試験で確かめられる。

2. 開いたまま一度も指で送っていないと、指を使わない上への移動のあとで下へ引き戻されることがある(確度は中から低。シミュレータでは確かめていない)

   [`ios/App/Views/ProtectedHomeView.swift`](ios/App/Views/ProtectedHomeView.swift) の177〜181行目。`opening` を下ろすのは `onScrollPhaseChange` の `.interacting` と、声の段階が変わったときだけだ。VoiceOver の3本指の送り、ステータスバーを押して上の端へ戻る操作のように、指でつかまない送り方は `.interacting` を通らないと思われる(推測で、確かめていない)。その場合 `opening` が true のまま残り、`old.showsEnd || opening` が通る。そこで知らせの帯が開閉したりキーボードが出たりして高さが変わると、`position.scrollTo(edge: .bottom)` で下の端へ戻される。main は `old.showsEnd` が必須だったので、この戻りは起きなかった。指で送る母にはまず起きない。VoiceOver を使う人と、ステータスバーを押す人の場合に限られる。直すなら、`opening` を「初めて下の端が見えたとき」か「開いて少し経ったとき」に下ろす。または `shrank` の枝では `opening` を見ず、元の `old.showsEnd` だけにする(下の端まで送り切る役目は `grew` の枝が持っている)。直すべき扱いにはしない。実機の確かめの項目3に、VoiceOver で上へ送る場合を足すとよい。

## 確かめて問題なかったこと

- `history(for:at:)` の guard は `messages.last?.at` を使う。最後の記録に時刻が無いのは、時刻の無い記録だけのファイルを読んだ直後の1回目の `send` に限られる(`send` は `history` を取ってから足すため)。そのときは60分の窓に戻り、そこでも時刻の無いものは外す。前の日の会話を送る道は増えていない。前の日を送るほうの絞り込みは `now.timeIntervalSince(at) < Self.keptFor` を残していて、30日を超えたものは送らない(#118 の決まりどおり)
- 前を指す問いの窓は、最後の時刻付きの記録から数える。時刻の無い記録が混ざっても窓は広がらない
- `reveal` とぶつからない。声の段階が `.listening` か `.thinking` に変わった時点で `opening = false` になるので、答えが届いて `.answered` で答えの頭を上に合わせるときには `grew` の枝は動かない。相談の最中は `followsConsult` の guard も効く。指で上へ送ったあとは `opening` が false になり、`shrank` の枝は `old.showsEnd` を求めるので、勝手に下へは戻らない(上の2つ目の、指を使わない送り方は除く)
- 画面の文言は日付の行(「11月4日」「今日」)と時刻(「14:55」)だけで、説明の文は足していない。VoiceOver は「あなた、本文、14時55分」「答え、本文、14時55分」と読み、日付の行には見出しの印が付く。時刻の無い記録は時刻なしで読む
- `ios/Core` が取り込むのは `Foundation` だけ(`grep "^import" ios/Core/Sources` で全ファイルが `import Foundation`)。`Calendar` と `String(format:)` も Foundation の範囲
- 撮影用の `days` の会話は `#if DEBUG` の中([`ios/App/Debug/ScreenshotStubTransport.swift`](ios/App/Debug/ScreenshotStubTransport.swift) の1行目)で、例文は作り話。実際の家族の情報は入っていない
- 試験は働きを確かめている。`untimedRecord` は `at` の無い JSON を読ませていて、main の必須の `at` なら読めずに空になって落ちる。日本時間の0時をまたぐ試験は、`Calendar` を Asia/Tokyo に固定しているので、走らせる環境の時間帯に左右されない。`swift test --filter "ChatRowTests|ConsultHistory|ChatLog"` は11件が通った
- 家族への知らせ、カード、段階、知らせる相手には触れていない。差分は母の端末の画面と記録だけ
