1. 省略形の `--forc` で `git add -f` の止めを抜けられる（確度は高い、再現済み）

2. 例文を git に入れたあとは、実装役を止めるという記述が成り立たなくなる（確度は中、ただし原因は次の PR）
   [`docs/harness.md`](docs/harness.md) の `guard-holdout.sh` の行に「`mm-implementer` と `mm-eval-curator` は git の行も止める」「主の会話の Read、grep、ls、cat は測ったあとも止める」とある。フックが見るのは道筋の文字だけだ。次の PR で `.gitignore` の2行を外してコミットすると、例文のフォルダを名前に出さない形で中身に届く。`git show <sha>`、`git log -p`、`grep -r <語> eval/`、Grep ツールで `path: eval` を指す形がそれにあたる。Grep ツールの ripgrep は `.gitignore` を外すと例文も探すので、フックの頭の注（4行目の「recursive grep and the Grep tool skip them」）も外れる。今の PR の時点でも、主の会話は `git diff --no-index eval/cases/holdout/<file> /dev/null` で、まだ追跡されていない例文をそのまま画面に出せる（`git diff` で始まり、禁じる文字が無いので通る）。主の会話の `cat` を止める意味は、ほぼ形だけになっている。測ったあとの調整を止める仕組みは、フックではなく「測ったあとは直さない」という決まりに頼っている。そう書き直すか、次の PR で何が止まらなくなるかを書いておくのがよい。
