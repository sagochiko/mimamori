## 指摘

1. 通話のあとの問いかけの記録が消えない(中程度、確度は高い)

   [`ios/App/AppModel.swift`](ios/App/AppModel.swift) の67〜80行にある `onRouteChange` の `.chooseRole` の分岐は、`invite`、`cases`、`smileBoard`、`gmail`、`photoCache`、`chat` を消す。しかし `followUp`(`UserDefaultsCallFollowUpStore`、`UserDefaults.standard` の `mimamori.callFollowUp`)と、手元に持っている `followUpPrompt` には触れていない。`CallFollowUpState` には母の3分以上の通話の id が最大50件(`handled`)、待っている通話の id と終わった時刻(`pendingCallId`、`pendingEndedAt`)、最後に尋ねた時刻(`lastAskedAt`)が入っている([`ios/Core/Sources/MimamoriCore/CallFollowUp.swift`](ios/Core/Sources/MimamoriCore/CallFollowUp.swift) の35〜46行)。Core にも消す口が無い(`clearPending` は待っている分しか消さない)。

   具体的にはこうなる。母が長い電話のあとに「すべて消す」を押す。役の選択に戻ったあとも通話の記録は端末に残る。同じ起動のうちに母役で入り直すと、12時間以内なら新しい家族の画面に「さっきの電話、大丈夫だった？」が残ったまま出る。`lastAskedAt` のせいで、その日の毎日の声かけも飛ぶ。Issue の完了の条件は「端末の鍵、母の会話のファイル、キャッシュを消して」で、PR の本文も「何も残らない」寄りに読める。この記録だけが漏れている。

   直し方は、`CallFollowUpStore` に `clear()`(または `CallFollowUp.forget()`)を足し、`.chooseRole` の分岐で `followUp` の記録を消して `followUpPrompt = nil` にする。Core の試験も1件足す。これは 401 や家族を抜けたときの既存の経路にも前からある漏れなので、同じ分岐で直せば両方がふさがる。通知センターに届いたままの `call-follow-up` の通知(`removeDeliveredNotifications`)も、ついでに消すとよい。

2. 「すべて消す」の 401 の試験が無い(軽い、確度は高い)

   [`ios/Core/Tests/MimamoriCoreTests/SessionTests.swift`](ios/Core/Tests/MimamoriCoreTests/SessionTests.swift) の新しい組には、204、502、つながらない、家族に入っていない、の4件がある。別の家族がもう消したあとに押す場面(401 で鍵が消えて役の選択に戻り、`Problem(deleting:)` が nil になる)は、`ProblemTests` の1行でしか見ていない。共通の `perform` の 401 の扱いは既存の試験で見ているはずなので、実害は小さい。それでも、この操作でいちばん起きやすい失敗なので、`StubTransport(status: 401, ...)` で `store.load() == nil` と `route == .chooseRole` を確かめる1件があるとよい。

## 確かめて問題なかったこと

- 2xx のときだけ鍵を消すこと。`APIClient.deleteEverything` は `perform` が 2xx を返したあとにだけ `store.clear()` を呼ぶ。502、500、オフラインのときは throw するので鍵は残り、`route` は今のまま。Core の試験7件を手元で流し、すべて通った(`swift test --filter "DeleteEverything|ProblemTests"`)
- 401 の扱い。`perform` は 401 で鍵を消して `APIError.unauthorized` を投げる。`Problem(deleting:)` は nil を返すので失敗のアラートは出ず、役の選択に戻る。別の家族が先に消していた場面として筋が通っている
- 裏側の約束との食い違い。[`server/src/families.ts`](server/src/families.ts) の191〜251行は、外の分(Gmail、Managed Agents)が残ると `502 cleanup_failed` を返して D1 を消さず、全部済めば `noContent()`(204)を返す。アプリは 2xx 全体を成功、それ以外を「消せませんでした」として扱い、押し直せば続きから消える。これは [`docs/design.md`](docs/design.md) の「データの扱い」の段落(外の分を断られたら家族のデータと鍵を消さずに失敗を返し、押し直すと続きから消す)と合う。どの家族からでも呼べる点も、242行の「母か家族の誰か」と合う
- 端末のデータ。会話は `chat.clear()` でファイルごと消える(`store.remove()`)。カード、笑顔、写真のキャッシュ、招待、Gmail の状態はメモリから消える。`cameToFront()` が通話の見張りを止め、毎日の声かけの予約を空にする。App Group の鍵は、`KeychainDeviceKeyStore.clear()` がアクセスグループを付けない問い合わせで消すので、共有のグループの項目にも届く。App Group には ほかに `containerURL` や `UserDefaults(suiteName:)` で置いたものは無かった(grep で確認)。家族役のほかの端末は、次の呼び出しで 401 になり同じ経路で片付く
- 押し間違いの守り。メニューの中の破壊的なボタンから、題が「すべて消す」のアラートに進み、ボタンは「消す」(destructive)と「やめる」(cancel)だけ。「やめる」は何も送らない。処理中は `isBusy` でメニューが押せない
- 画面の文言。アラートに説明文は無く、消えるものの説明は `accessibilityHint` に、メニューの名前は `accessibilityLabel("その他")` にある。[`.claude/rules/ios.md`](.claude/rules/ios.md) の決まりに沿っている
- 主役の相談の画面。母の画面の変更は、笑顔の列を `HStack` に入れて右端にメニューを足しただけ。知らせの帯、会話、下の欄には手を入れていない。家族の画面は `topBarTrailing` に1つ足しただけで、ほかのツールバーの項目とぶつからない
- スタブの経路。`ScreenshotStubTransport.swift` は全体が `#if DEBUG` に入っていて、`WipeMenu` の `onAppear` での参照も `#if DEBUG` で囲まれている。Release には入らない
- `ios/Core` は Foundation だけを使っていて、iOS 専用のフレームワークの import は増えていない。差分に秘密、実在の家族のデータ、外から写したコードは無い
- 差分の中に、注入された文が通知の宛先、共有の範囲、段階を変えられる経路は無い
