## 指摘

### 1. 偽装の語を打ち消す行が `DISGUISE` で網を抜けて家族の根拠に載る(この直しが作った退行、確度は高い)

場所は [`server/src/agents.ts`](~/develop/mimamori/.claude/worktrees/issue-12-managed-agents/server/src/agents.ts) の349行目の `DISGUISE` と、352〜353行目でそれを付けた2本だ。

```ts
const DISGUISE = "(?![^。]{0,12}?(装|そっくり|に似せ|をかた|を騙|騙っ|になりすま|かたっ))";
```

この先読みは、偽装の語が12字以内にあれば無条件に「注意喚起」と見なす。偽装の語が打ち消されていても同じだ。`装` は1字なので `偽装` にも当たる。打ち消しの形はほぼどれも `WARNS` の `偽` か `なりすまし` に当たるので、`WARNS` の関門も素通りする。関門の正規表現と `soundsSafe` を写したスクリプトで、直す前の網と並べて流した結果はこうなる。

```text
PASS (old DROP) 本物の案内で、偽装ではない
PASS (old DROP) 正規の連絡で、偽装された形跡はない
PASS (old DROP) 宛先の宅配業者は実在し、偽装の手口ではない
PASS (old DROP) 本物の連絡で、偽サイトに似せたものではない
PASS (old PASS) 公式からの連絡で、なりすましを装ったものではない
```

上の4行は直す前なら落ちていた。最後の行は、この直しが「公式から」を落とすために足した2本目の網を、同じ先読みで自分から外している。

起きる場面はこうなる。エージェントが公式サイトの URL を付けて「本物の案内で、偽装ではない」と報告する。`parseEvidence` はこの行を残し、家族のカードの読み上げに、届いたものは本物だという根拠として載る。これは「安全と言わない」の決まりを根拠の欄から破る。調べものは届いた本文を読むので、本文に仕込んだ文でこの形を書かせる道もある。

直し方は2つある。1つは、偽装の語のあとに打ち消しが続く形を、先読みの中で除外から外すこと。たとえば `(装|そっくり|…)` のあとに `[^。]{0,8}(では|じゃ)(な|ありません)|形跡は(な|無)|ものではな` が続くときだ。もう1つは、`(偽装|偽|装っ?た?|なりすまし)[^。]{0,8}(では|じゃ)(な|ありません)|形跡は(な|無)` を `REASSURES` に別の1本として足すこと。こちらのほうが安く済む。`server/test/agents.test.ts` の `reassure` の配列に上の5行を足せば、この退行を捕まえられる。

ここからは網の抜けで、退行ではなく、重くもない。「本物と見分けにくい偽 SMS」と「正規の業者を名乗る偽 SMS」は今も落ちる(`見分け` と `名乗る` が `DISGUISE` に無いため)。安全の側に倒れているので、直すかどうかは任せる。
