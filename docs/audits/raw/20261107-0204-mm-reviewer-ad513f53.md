## 確かめて問題なかったこと

- 半分までに抑える判定は正しい。
  - `leave = 始めの残り - 20` と置き、`残り - 4 < leave` で抜ける。これは「使った回数 + 4 > 20」と同じで、使った回数には最初の SELECT の1回も入る。
  - 1 + 4n ≤ 20 なので1回の Cron で4件、使うのは17回(断られた端末の UPDATE は別)。5件目は21回になるので取らない。
  - 試験の「20件で5回の Cron」とも合う。
- 見張りは必ず回る。
  - 最初の知らせが17回使うと残りは23回。見張りの入口に要る5回を超え、1 + 4×5 = 21 回で5件まで回る。
  - 410 以外で断られ続ける場合、端末を忘れる UPDATE は走らないので、残りは減らない。
- 抜ける位置は `tellFamily` の claim の前で、ループの先頭にある。
- Cron の外では上限がかからない。
  - `d1Remaining` が `Infinity` のとき `leave` も `Infinity` になり、`Infinity - 4 < Infinity` は false なので抜けない。
  - 相談と Queue の `openCase` は `sendFirstNotices` を通らないので、もともと影響が無い。
