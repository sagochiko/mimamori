## 指摘(深刻度の高い順)

### 中 画面の写真を貼る決まりが、公開リポジトリの個人情報の決まりより狭い(docs/mother-feedback.md:9)

「画面の写真を貼るときは、通知や連絡先に個人の情報が映っていないかを確かめてから貼る」は、母や家族の実機の画面写真をリポジトリに入れることを前提にしていて、確かめる範囲が「通知」と「連絡先」に絞られている。止める仕組みは無い。`scripts/scan-private.sh staged` は `diff --cached -U0` の `+` で始まる文字の行だけを見る(scripts/scan-private.sh:78〜85)ので、画像は pre-commit の関門を素通りする。この文のまま通ると、次の場面で漏れる。

- #48 の手順4は、妹の iPhone のカードが「(作者の名前)が解決」に変わるかを確かめ、「違ったところの画面のスクショ」を作者に求めている(gh issue view 48)。そのスクショには家族の本名が載るが、カードは「通知」でも「連絡先」でもないので、この文の確認では引っかからない。CLAUDE.md の「ハッカソンのルール」は家族の名前をどこにも書かないとしている
- 母の画面にも家族の画面にも毎朝の笑顔の写真が並ぶ(docs/design.md:115、123)。design.md:220 は「笑顔の写真は家族の間だけで共有し、Claude にも Managed Agents にも渡さない」としている。貼れば母の顔が公開リポジトリに出るうえ、映り込みを確かめるために Claude に画像を読ませること自体が、写真を Claude に渡すことになる
- 母の実機の Messages やカードの画面には、実際に届いた SMS の文字が映りうる

直し方は1文で足りる。貼る画像をシミュレータの画面(今の `docs/screens/` の使い方)に限るか、実機の写真を貼るなら、顔(笑顔の写真)、カードや通知に出る家族の名前、実際に届いた文面、設定画面の Apple ID や番号を挙げて確かめる対象にし、フックは画像を見ないと書き添える。
