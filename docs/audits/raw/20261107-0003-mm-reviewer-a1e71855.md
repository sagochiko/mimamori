## 指摘

1. 体験の家族のカードの理由が、裏側が同じ相談に付ける理由と違う(確実。小さく直せる)

   [`ios/Core/Sources/MimamoriCore/DemoTour.swift`](ios/Core/Sources/MimamoriCore/DemoTour.swift) の `reason` は「警察を名乗る相手から連絡があった」1つで、`familyCase` の `reasons: [Self.reason]` に入る。一方で、裏側に `herWords` を渡すと別の理由が返る。

   ```sh
   npx tsx -e 'import {judgeConsult} from "./src/consult-judge.ts"; judgeConsult("<herWords>", [], async()=>null)...'
   ```

   実測の結果は `{"s":true,"level":1,"reasons":["口座が犯罪に使われたという話がある","ほかの人に話さないよう言われている"],"summary":"警察を名乗る電話の相談","reply":"詐欺で使われる説明と一致しています。送金せず、いったん電話を切って家族に確かめて","toFamily":true}` だった。`policePlan` は規則の理由があればそれを使い、この文では `警察から電話があって` が `phrases.ts` の警察の理由に当たらない。

   困る場面はこうなる。家族のカードの読み上げ(`CaseCardView.summaryLabel` は理由を VoiceOver で読む)で、審査員には本物が言わない理由が聞こえる。コメントの「so the tour shows what her phone and the family's would」とも食い違う。`usesTheServersFixedLinesForTheFakePolice` は文字の値を固定しているだけなので、裏側と食い違っても落ちない。

   直し方は2通りある。`reasons` を裏側の2つにする(`reason` を配列にして `phrases.ts` の64行と86行の文字を写す)か、`herWords` を警察の理由に当たる言い方に変える。

2. 「母の版では体験が出ない」は #133 が済むまで成り立たない(確実。この PR で悪くなる範囲は小さい)

   [`ios/App/AppConfig.swift`](ios/App/AppConfig.swift)、[`ios/App/Views/RoleSelectionView.swift`](ios/App/Views/RoleSelectionView.swift)、`DemoTour.swift` の `DemoMode` のコメント、[`docs/plan.md`](docs/plan.md) 311行、[`docs/dev-log.md`](docs/dev-log.md) は、どれも母の版には母の token が入る前提で書かれている。しかし #133 はまだ OPEN で、本文には「母は審査員と同じ外部テストのグループ「審査員と家族」で受け取っている」とある。[`.claude/skills/mm-release/SKILL.md`](.claude/skills/mm-release/SKILL.md) の `xcodebuild ... archive` にも `-xcconfig ios/Config/Mother.xcconfig` が無い。

   なので、この PR のあとに `/mm-release` で上げた版は `MIMAMORI_SMS_FAMILY_TOKEN = demo` のまま母に届き、`AppConfig.isDemo` が true になる。ただ、入口は役を選ぶ画面(`RootView` の `.chooseRole`)にしか出ないので、家族に入ったあとの母には見えない。体験は誰にも何も送らない。見えるのは、入り直しや入れ直しのあとだけになる。

   仕組みそのものは #133 の形(コマンドラインの `-xcconfig` は App のターゲットにも効く)で正しく働く。マージ前に文書へ「#133 が済むまでは母の版にも出る」と1行入れるか、#133 のやることに「`Info.plist` の `MimamoriSMSFamilyToken` が `demo` でないことをアーカイブで確かめる」を足すのがよい。後者は、mm-release の手順3で `MimamoriAPIBaseURL` を読むのと同じ形で書ける。
