## 確かめて問題なかったこと

- 1日1回の関門が止めるのは、通話のあとの声かけだけだった。`callEnded` の `.nothing` で止まるのは `CallFollowUpNotifier.post()` と `refreshFollowUp()` だけ(`ios/App/AppModel.swift` 611〜623行)で、相談、Message Filter、Safari、家族への知らせの経路には触れていない。通話の声かけを出した日に毎日の声かけを外す動きは PR の前からあった(`DailyCheckIn.swift` 89行、`docs/plan.md` 457行)。この PR で増えたのは、同じ日の2本目以降の通話で何も出ない場面だけで、作者が受け入れた範囲に収まる。ただ、その日の毎日の声かけも出ないため、2本目以降の通話を拾う網は無くなる。設計どおりだが、作者がこの重なりを承知しているかは PR に一行書いておくとよい。
- 出さなかった通話は何も書かない。105行の `return .nothing` は `store.save` より前にあり、テスト `onceADay` が `store.load() == afterFirst` で確かめている。関門を外すとこのテストは落ちる。

- `-mimamori-followup-reset` は Release に入らない。`DebugLaunch` は `ios/App/Debug/DebugLaunch.swift` 全体が `#if DEBUG` から `#endif` までに入っていて、呼び出し側の `AppModel.swift` 90〜92行も `#if DEBUG` で囲まれている。`resetDailyLimit()` が消すのは `lastAskedAt` だけで、`handled` と待っている声かけは残る(テスト `resetDailyLimitAllowsAnotherToday`)。
