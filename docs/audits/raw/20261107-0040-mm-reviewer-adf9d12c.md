## 指摘

1. 本番で使う `{ urls }` の形を試験が1つも通っていない。確かさは高い。
   [`server/src/agents.ts`](server/src/agents.ts) の338行目で `Array.isArray(urls)` の枝を読んでいる。v2 のエージェントが返すのはこの形だけになる。ところが [`server/test/agents.test.ts`](server/test/agents.test.ts) の `parseEvidence` と `collectInvestigation` の試験は、すべて古い `{ items: [...] }` で報告を組んでいる(`reports.set(sessionId, { items: [GOOD] })` が397、422、442、459、518、599、637行目にある)。`grep -n "urls" server/test/agents.test.ts` は0件だった。`input_schema` が `urls` を求めているかを見る試験も無い(187行目が見るのは道具の名前だけ)。
   起きうる場面を挙げる。誰かが338行目の分岐を書き違える(`urls` と `items` を取り違える、文字列の配列を `.url` で読む、など)。それでも29件の試験は全部通る。本番の v2 のエージェントは `{ urls: [...] }` だけを返すので、根拠はいつも `[]` になり、家族のカードからは黙って消える。直し方は2つ。`parseEvidence({ urls: [...] })` の試験を足し、古い形の試験と同じ網羅(公式でない、http、ホストのすり替え、同じサイトの2回目、最大3つ、問い合わせの落とし)を `urls` でも確かめる。`collectInvestigation` の試験の `reports` も少なくとも1件は `{ urls }` にする。

2. URL の道筋(pathname)はエージェントが自由に書けるのに、そのまま D1 と `GET /cases` に出る。確かさは高く、害は小さい。
   133行目は `${parsed.origin}${parsed.pathname}` を返す。落とすのは問い合わせと `#` のあとだけだ。たとえば注入でエージェントに `https://www.npa.go.jp/090-1234-5678/` や、届いた本文をパーセント符号にした道筋を書かせると、通ってしまう。それが `alerts.evidence` に入り、家族の端末への JSON にも載る。[`docs/plan.md`](docs/plan.md) の154行目の「エージェントが書いた文は家族にも D1 にも出さない」と食い違う。前の作りの `carriesContact` と `quotes` が見ていた「届いたものを家族の知らせに写さない」の守りも、道筋については無くなった。
   iOS が使うのは `url.host()` だけ(`CaseCardView.swift` の83行目)なので、画面や読み上げには出ない。だから重くはない。直すなら、保存を `origin` だけにするか、道筋を ASCII の英数字と `/._-` に限って長さに上限を置き、外れたら `origin` に落とすのがよい。試験の「puts out nothing the agent wrote, even in the stored url」は問い合わせとフラグメントしか見ていないので、道筋の例も足す。

3. `server/.claude/state/` はまだ無視されておらず、次の `git add server` でまた入る。確かさは高い。ハーネス側の話で、この PR を止めるほどではない。
   [`.gitignore`](.gitignore) の17行目は `.claude/state/` で、途中に `/` があるのでリポジトリの根に固定される。`git check-ignore -v server/.claude/state/author-waiting` は何も返さなかった(終了コード1)。b29c47d で追跡から外したことは確かめた。`git diff main...HEAD --name-only` に `.claude/state` は0件で、ファイルは手元に残っている(中身は `<epoch> <count>` の1行だけで、個人の情報は無い)。
   原因は [`.claude/hooks/lib.sh`](.claude/hooks/lib.sh) の4行目と6行目にあるとみる。`STATE_DIR` が `$CLAUDE_PROJECT_DIR/.claude/state` から作られ、`server/` を作業場所にして起動したセッションでは `server/.claude/state` に書かれる、という推測だ(起動の経緯は確かめていない)。`.gitignore` に `**/.claude/state/` を足す小さなハーネスの PR を勧める。

iOS の読み上げで「出典、」が2回続く点は、直す必要は無いと判断した。ラベルは「…。出典、日本郵政グループの注意喚起」で、ヒントは間を置いてから「出典、www.post.japanpost.jp」と読まれる。言っていることが表示名とホストで違い、どちらも決まった文字で、言い切りも安心させる言葉も無い。くどく感じるなら、ヒントの頭を「サイト、」に変える程度で足りる。

## 確かめて問題なかったこと

- 家族に出る `text` はいつも `SITE_NAMES[site]` に「の注意喚起」を足した1行で、エージェントの文は一切入らない(`agents.ts` の338〜350行目)。`SITE_NAMES` は固定の表で、エージェントの入力からは変えられない。
- ホストの判定は `URL` で解いたあとの `hostname` に対する完全一致か `.<site>` の末尾一致だった。`npa.go.jp.example.top` は落ち、`evil-npa.go.jp` も末尾一致に当たらず落ちる。`http`、資格情報つき、`javascript:`、解けない文字列は null になる。ホストの末尾に `.` がある形も一致せず落ちる。
- 1サイト1回(`named` の集合)、最大3つ(`EVIDENCE_MAX`)、読み戻せないときは足さない(`report && sent.length > 0`)、同じ結果を2回書かない(`finish` の `investigated_at IS NULL`)のどれも壊れていない。
- 古い `items[].url` は `url` だけを取り出して読み、`text` は捨てる。v1 の残りのセッションが文を返しても家族には出ない。`RESEARCH_AGENT_NAME` は `research-agent-v2` に上がり、計画の表(`agent_resources`)の記述も v2 に揃っている。環境は道具の許すサイトが変わらないので v1 のままでよい。
- 裏側はまだデプロイしていない(PR #183 の本文の17行目「本物の API では、まだ流していない」)。なので、`storedEvidence` が古い作りの文を D1 からそのまま返す心配は今は無い。
- 1回目から4回目で直した予算、打ち切り、セッションの消し方は、この3つのコミットで変わっていない。`collectInvestigation` の差分は `summary` の列を読まなくなったことと `parseEvidence` の引数だけだった。`dropSession`、`giveUp`、`watchInvestigations` の `budget.remaining` の確かめ、`startInvestigation` の後片付けの削除は元のまま。
- 外した網に頼っていた試験は、「どの文でも決まった1行になる」という試験に置き換わり、これまでのレビューで出た25の文を `AGENT_LINES` で全部流している。網が守っていたものは、入口で文を受け取らない作りがより強く守っている。抜けているのは上の指摘1と2だけだ。
- [`docs/design.md`](docs/design.md) と [`docs/plan.md`](docs/plan.md) の書き方は、実装とも互いとも合っている。「安全です」と言わず、「同じ手口が載っている」とも言い切らない。dev-log の新しい項も事実と合っていた。
- 母の言葉は調べものに渡らない(相談と電話は `SOURCES` の外)。通知先と段階は調べものの結果で変わらない(`finish` が書くのは `evidence` と `investigated_at` だけ)。
- 試験を流した結果。`npx vitest run test/agents.test.ts` は29件すべて通った。`npx vitest run` 全体は15ファイル1540件が通り、`npx tsc --noEmit` は何も出さなかった。`ios/Core` の `swift test` は41スイート259件が通った。
- 秘密、実際の家族の情報、外から写したもの、`ios/Core` での iOS 専用の framework の import は、差分に無かった。スタブの例は `example.top` と日本郵便の公開ページだけだった。
