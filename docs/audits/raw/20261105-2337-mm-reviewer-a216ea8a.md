## 指摘

### 1. 母の「ひと言」だけの行が、笑顔が無い朝の知らせを止めてしまう(裏側と端末で「今日の母の笑顔」の定義が食い違う)

- 場所は `~/develop/mimamori/server/src/smiles.ts` の 434〜435 行、`notifyMissedSmiles` の `NOT EXISTS (SELECT 1 FROM smiles s JOIN members p ... WHERE s.family_id = f.id AND p.role = 'protected' AND s.created_at >= ?)`。`r2_key != ''` の条件が無いので、写真の無いひと言の行(`r2_key = ''`)も「母の笑顔」として数える。
- 一方で端末側の `~/develop/mimamori/ios/Core/Sources/MimamoriCore/Smile.swift` の `todaysProtectedSmile` は `$0.hasPhoto` を必須にしていて、写真の無い行は今日の笑顔に数えない。
- 場面で言うと、母が7時に「元気だよ」だけを押して写真を撮らなかった朝、裏側は9時になっても家族に知らせない。家族の画面には「今日の母の笑顔」が出ないので、家族は「笑顔が来ていないのに知らせも来ない」状態になる。`docs/design.md` の「決まった時間の知らせが見るのは母の笑顔だけ」と、`docs/plan.md` の `PUT /families/me/smile-deadline` の行「その時刻までに母の笑顔がその日に無ければ」の素直な読みは写真の笑顔で、端末もそう書いている。ひと言を安否に数えると決めた記録は Issue、PR、design、dev-log のどこにも無い。
- 確かめ方はコードで見た(SQL に条件が無いことは明白)。`test/smiles.test.ts` の「says nothing when the protected member smiled today」は `smileAt` で写真つきの行しか入れておらず、この場合を押さえるテストが無い。
- 直し方は、`NOT EXISTS` の中に `AND s.r2_key != ''` を足し、母のひと言だけの行を入れて9時に tick しても家族に届くテストを1件足す(`smileAt` の形で `r2_key` を `''`、`note` を `'おはよう'` にすればよい)。ひと言も安否に数えると親が決めるなら、逆に `todaysProtectedSmile` の `hasPhoto` を外し、`docs/plan.md` の行にその旨を書く。どちらでも数行の直し。確度は高い。

### 2. 予算切れで claim を戻す経路にテストが無い(低)

- `~/develop/mimamori/server/src/smiles.ts` の 459〜465 行。`sendPush` が `no_budget` を返したとき `smile_missed_notified_on` を元の値に戻す分岐に、テストが1つも無い。`runScheduled` は自分で `ExternalBudget` を作るので `tick()` からは通せない。`notifyMissedSmiles(env, now, new ExternalBudget(0))` を直接呼べば確かめられる。
- 壊れていても気づけないだけで、今の実装はコードで読む限り正しい(`bind(family.told_on, ...)` で `NULL` にも戻せる)。マージを止める指摘ではない。

### 3. R2 に置いたあとの D1 の失敗で写真が残り続ける(低)

- `~/develop/mimamori/server/src/smiles.ts` の 318〜323 行。`env.PHOTOS.put` が先で `INSERT` が後なので、`INSERT` が落ちると行の無い写真が R2 に残る。`retention.ts` の30日の削除は `smiles` の行から鍵を取るので、この写真は消えない(「すべて消す」は `deleteFamilyPhotos` の prefix の一覧で拾うので消える)。
- 起きる確率は低く、順番を逆にするか失敗時に `delete` を足せば済む。`docs/design.md` の「30日たったら自動で消す」に関わるので挙げておく。

## 確かめて問題なかったこと

- `notifyMissedSmiles` の SQL。6つの `?` の順(`midnight, now, today, midnight, midnight, MISSED_PER_TICK`)は SQL の並びと一致。先に `UPDATE ... WHERE smile_missed_notified_on IS NULL OR != today` で日付を押さえ、`changes !== 1` なら送らないので、同じ tick が重なっても二重に送らない。`jstDate` と `jstMidnight` は同じ日付の切れ目を使う。母が入る前の時刻の家族、母のいない家族、家族の笑顔だけの朝、前日の母の笑顔、家族が決めた時刻、翌日の再送は `test/smiles.test.ts` が押さえていて、通った
- 知らせの宛先。笑顔の無い朝は `role = 'family'` だけに送り、母には送らない。送った笑顔やひと言は本人を除く家族全員(母を含む)に `quiet: true`(`sound` 無し、`interruption-level: passive`)で届く。`push.ts` の `apsBody` で `quiet` のときだけ `sound` を落とすのをテストが確かめている
- 注入の経路。`readNote` は決まった5語の ID か語そのものだけを通し、「この警告を止めて」「おはよう、元気?」は 400 `note_not_allowed`(テストあり)。通知の本文に入るのは `displayName` と決まった語だけで、母の自由な文は裏側にも家族にも渡らない。段階、宛先、共有の範囲を変える入力はこの変更に無い
- 空の `r2_key`。`families.ts` の 176 行と `retention.ts` の 16 行の両方に `r2_key != ''` があり、`data.test.ts` の種にひと言だけの行を足した状態で「すべて消す」も30日の削除も通った(手元で52件通過)。行そのものは `DELETE FROM smiles` で消える
- `smilePhoto` の順(404 → 403 → 404)。`docs/plan.md` の行「別の家族の `deviceKey` には403、無い笑顔と写真の無いひと言には404」と一致。ID は UUID なので、存在の有無が別の家族に分かることの実害は無い。403 の本文に写真が無いことはテストあり。`Cache-Control: private`
- `POST /smiles` の検査。`note`、`score`、`photo` の検査を全部通ってから `PHOTOS.put` するので、断った本文は R2 に何も残さない(`r2CountFor` で確認するテストあり)。413 は base64 の長さで先に止める
- 写真の行き先。`smiles.ts` は `judge`、`consult`、Managed Agents のどれも呼ばない。ログは `error.name` だけで、写真もひと言も出さない
- ハッカソンとデータの決まり。新しい `ios/Core` のファイル(`Smile.swift`、`SmileScorer.swift`)は `Foundation` しか import していない。ARKit は `ios/App/SmileCamera.swift` に閉じている。写真の代わりはコードで描いた顔(`SmilePlaceholder.swift`)で、人の写真や実名、秘密の値は差分に無い。`Info.plist` と `project.yml` の `NSCameraUsageDescription` は判定が端末内で済むことを書いている
- `Tracker` の `@unchecked Sendable` と `MainActor.assumeIsolated`。Apple の `ARSession.delegateQueue` の文書を取って読んだ。「If this value is nil (the default), the session calls your delegate methods on the main queue.」とあり、`delegateQueue` を設定していないので主スレッドで呼ばれる前提は成り立つ。`gate.fired` で2回目以降は何もしないので、`pause()` のあとに届く更新も写真を撮らない
- 写真の向き。`ARFrame.capturedImage` の文書は色の形式だけで向きに触れていないので、`oriented(.right)` が正しいかはここでは決められない。PR の「作者に頼むこと」に向きと鏡写しの実機確認が入っているので、そのままでよい
- 端末側の API。`SmileBody` は synthesized Encodable なので nil は JSON から抜け、テストで `note`、`photo`、`score` が無いことを見ている。`APIError.http(status: 403)` は `perform` の default 分岐から出る。`deadlineHour` の無い古い答えは既定の9時として読む
- 画面。家族の画面に母の今日の笑顔、「笑顔」「ひと言」のボタン、みんなの帯、時刻のメニューがあり、母の画面には帯の先頭にカメラとひと言のボタンがある。時刻の変更は家族の役だけで、母からは403(テストあり)。鍵が消えたときは `smileBoard` と `photoCache` も空に戻す
- アラーム(AlarmKit)は差分に無く、親の決めた範囲どおり
- 止められた操作は無かった
