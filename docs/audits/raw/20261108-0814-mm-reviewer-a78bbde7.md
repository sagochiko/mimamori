## 確かめて問題なかったこと

- `add_re` が `^git add( eval/cases/(holdout|pool)(/[A-Za-z0-9._-]+)*/?)+$` なので、シェルが語を変える文字はどれも入れられない。グロブの `*?[`、チルダ、`{}`、`$`、引用符、バックスラッシュ、`;&|<>`、バッククォートがそれにあたる。語の区切りは半角の空白1つに限られ、タブは通らない。bash の `=~` は `REG_NEWLINE` なしで組まれるので、`$` は文字列の終わりにしか当たらない。改行を挟んだ2行目は通らない（試験もある）。
- どの道筋の語も `eval/cases/` で始まるので、`-` で始まる語（オプション）は入れられない。`eval/cases/holdout/-x` や `.../--force` は道筋として渡るだけだ。`:` で始まる pathspec の魔法も入れられない。`..` は外側の条件で、グロブも外側の条件と65行目で止まる。`.` の語（`eval/cases/holdout/.`）は木の中にとどまる。
- `nocasematch` の下で `GIT ADD EVAL/CASES/HOLDOUT` も当たるが、大文字小文字を区別しない APFS では同じ git と同じフォルダになるので、抜け道ではない。前置きの空白、前置きの環境変数、`git -c`、`git -C`、`cd … &&` は `^git add ` に当たらず、試験もある。
- `-f` が無いので、`.gitignore` の2行を外す前の `git add` は git 自身が拒む。SKILL.md の手順の順番がそのまま守られる。
