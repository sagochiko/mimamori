## 指摘

### 1. `plain` の外にある詐欺の印があっても口止めの文を消すので、確かな1段階が2段階や `null` に下がる(確度は高い、再現済み)

場所は [`server/src/rules/index.ts`](server/src/rules/index.ts) の292〜302行目(`plain` と `hushText`)。`plain` が見ているのは、公式でないリンク、電話番号、口止め以外のニセ警察の部品、送金の4つだけだ。暗証番号を求める文(`CONTENT_RULES`)、急がせる言い回し(`URGENCY`)、名乗る会社と違う送り元(`brand_mismatch`)、メールアドレス、送り元が公式かどうかは見ていない。そのため、本物の注意の一文を書き足すだけで、main では口止めが担っていた1段階が消える。

main の規則(`git show origin/main:server/src/rules/*.ts` をスクラッチパッドに写したもの)とこの版に、同じ文を `tsx` で流して比べた。作業の木は変えていない(`git status` は空)。

```text
main=1c br=2    sms   確認コード 5678。ご家族に伝えないで、担当者に伝えてください。
main=1c br=2    sms   確認コード 5678 をこの番号に返信してください。家族に言わないで
main=1c br=2    sms   【ゆうちょ銀行】不正利用を確認しました。暗証番号はご家族にも言わないでください。このメッセージに暗証番号を返信してください。
main=1c br=2    gmail x@gmail.com  【三井住友銀行】暗証番号はご家族にも伝えないようにしてください。口座が凍結されました
main=1  br=null sms   パスワードは家族にも話さないで。お母さん、今日中にお金がいるの。
main=1  br=null sms   検察庁です。暗証番号はご家族にも言わないでください。
main=1  br=null sms   暗証番号を、ご家族には言わないでください。手続きのため担当者が伺います。
main=1  br=null sms   暗証番号はご家族にも言わないでください。キャッシュカードを封筒に入れて職員にお渡しください
main=1  br=null sms   暗証番号はご家族にも言わないでください。現金をご準備ください
main=1  br=null sms   暗証番号はご家族にも言わないでください。kakunin@gmail.com まで返信してください。
main=1  br=null sms   【三井住友銀行】お客様の口座が一時停止されました。暗証番号はご家族にも言わないでください。
main=1  br=null gmail x@gmail.com  暗証番号はご家族にも伝えないようにしてください。
```

場面ごとの影響は次のとおり。

- `1c` が `2` になる文は、迷惑フォルダに回らなくなる。`decide`([`server/src/claude.ts`](server/src/claude.ts) の189行目)では確かな規則の段階が下限なので、その下限も失い、Claude が軽く読めばそのまま軽くなる。1行目はコードを担当者に伝えさせる典型の手口で、`CODE_GUARD` が「ご家族に伝えないで」を消すため、残るのは `CREDENTIAL_FROM_CODE` の1つだけになる。
- `null` になる文は、Claude が答えないと `decideFor` が3段階にし、母にも家族にも知らせない。main では1段階で家族に届いていた。
- メールは送り元を見ていないので、`x@gmail.com` からでも `plain` になる。テストは `info@smbc.co.jp` からの例しかない。

直し方の案を2つ書く。1つ目は、消すのを `codeOnly` の SMS と、送り元が公式のメールだけに絞ること。2つ目は、消した文で判定したあとに口止め以外の印(`CONTENT_RULES`、`URGENCY`、`brand_mismatch` など、海外の番号の弱い印のほか)が1つでも残っていれば、元の文面で読み直すこと。2つを合わせれば、上の表はすべて main と同じ段階に戻る。

### 2. `plain` は詐欺の要素の否定の一覧で、書き方の揺れでそのまま外れる(確度は高い、再現済み)

依頼の「#84 と同じ語の一覧の追いかけになっていないか」に対しては、なっていると読む。リンクと電話番号の揺れは、どれも `plain` を通って `null` になった。

```text
main=1 br=null  暗証番号はご家族にも言わないでください。smbc-kakunin[.]com で手続きを
main=1 br=null  暗証番号はご家族にも言わないでください。smbc-kakunin。com で手続きを
main=1 br=null  暗証番号はご家族にも言わないでください。〇三-一二三四-五六七八 へ
main=1 br=null  暗証番号はご家族にも言わないでください。電話 3-1234-5678 へ
main=1 br=null  暗証番号はご家族にも言わないでください。LINE ID: abc123 を検索
main=1 br=null  あなたの名義が事件に関わっています。この番号はご家族にも言わないでください。
main=1 br=null  番号は家族に言わないで。この件は警察の捜査中です
```

筋書きの部品を言い換えた文(「名義が事件に関わって」「捜査中」)は `POLICE_SCRIPT` の型に当たらないので、`plain` のままになる。部品や表記を足すたびに次の揺れが出る形で、PR #156 の呼びかけと同じ追いかけになる。指摘1の案(本物だと言える正の条件で絞り、ほかの印が残れば消さない)にすれば、この揺れは問題にならない。

### 3. `codeOnly` の `null` はキューにも積まれず、Claude が一度も見ない(確度は中、影響は狭い)

`codeOnly` の SMS は理由が `CODE_ONLY_REASON` だけになり、[`server/src/sms.ts`](server/src/sms.ts) が判定のキューから外す。PR が受け入れた変わり方の「確認番号 1234 をお伝えします。この番号はご家族にも言わないでください。」もこれにあたる。この文だけなら、母が動かされる先が無いという読みには同意する。ただ、`CODE_GUARD` は家族で始まる文なら後ろに何が続いても消すので、`認証コード 1234。ご家族には言わないでください。この件は大事なお話です。` も main の1段階から、Claude が見ない `null` になる。こちらは後ろの文に印が無い作り例なので、程度は軽い。受け入れるなら、そう決めたことを [`docs/plan.md`](docs/plan.md) のタスク5の近くに書いておくのがよい。

### 4. 新しい家族の型で、理由を挟む口止めを取りこぼす(確度は高い、影響は小さい)

[`server/src/rules/phrases.ts`](server/src/rules/phrases.ts) の58〜61行目では、家族に「に」か「へ」が付かないと当たらない。次の文は `INJECTION` から外れ、残るのは `police_secrecy` の1つだけになる。

```text
main=1 br=2  家族は心配するので言わないでください
main=1 br=2  家族も心配するから内緒にしておいて
main=1 br=2  家族が心配するから話さないで
main=1 br=2  息子さんが事故を起こしました。家族は動揺されるので言わないでください
main=1 br=2  家族全員言わないで
```

どれも main でも確かでない1段階で、2段階になっても家族には知らせが届く。違いが出るのは Claude の答えが無いときの段階の表示くらいだ。とはいえ、「家族は心配するので言わないで」は息子を装う詐欺がよく使う形で、`INJECTION` の「家族を外す文」の筋そのものでもある。「は」「も」「が」に理由が続く形を戻すか、意図して外したなら試験に残る場合として書いておくのがよい。

### 5. 「段階を下げない」試験が、`plain` の定義をなぞるだけで落ちようがない(確度は高い)

[`server/test/rules.test.ts`](server/test/rules.test.ts) の782〜789行目の3件は、筋書き、電話番号、送金と一緒の文だけを使っている。この3つは `plain` が外すと決めているものなので、この版の作りでは必ず通る。指摘1と2の表の文(暗証番号の返信、担当者に伝えさせる、公式でない送り元、揺れたリンクと電話番号)を入れれば、今の版で落ちる。Issue #51 の4つ目の項目(試しの入力で毎回段階が下がらないことを確かめる)の趣旨にも、こちらの例のほうが合う。
