## 指摘

1. 弱い試験が1つある(確度は高い、重さは低い)。[`server/test/consult-findings.test.ts`](server/test/consult-findings.test.ts) の最後の `never answers that it is safe, even with a finding at hand` は、偽の Claude が `kind: "scam"` を返す形になっている。詐欺の相談の答えは段階ごとの決まった文に置き換わるので、記録をどう扱っても通り、壊れても落ちない。確かめたいのは「記録を見た Claude が `kind: "help"` の案内で『このメールは安全です』と書いたとき、網(`soundsSafe`)で止まる」ことのはずだ。偽の答えを `help` にして `action` に「安全」を入れる形なら、落ちうる試験になる。
2. `FINDINGS_NOTE` の文が実際の記録と少しずれる(確度は中、重さは低い)。[`server/src/consult-judge.ts`](server/src/consult-judge.ts) の `FINDINGS_NOTE` は記録を「家族に知らせた件」と書く。ところが [`server/src/consult.ts`](server/src/consult.ts) の `recentFindings` は `notified` で絞っていない。1時間の重複の抑えで知らせなかった行(`judge.ts` の `notified = 0`)も Claude に渡る。安全側にも家族への知らせにも害は無く、文の正確さだけの話だ。
3. 設計と計画で、渡す段階の書き方が揃っていない(確度は高い、重さは低い)。[`docs/design.md`](docs/design.md) の記録の段落(diff の232行目)は「相談以外の知らせのうち、7日以内の新しいほうから3件まで」とだけ書いている。[`docs/plan.md`](docs/plan.md) とコード(`level <= 2`)にある「1段階と2段階まで」が抜けている。

## 確かめて問題なかったこと

- 母の帯の絞り込み(`ProtectedNotice.notice(for:now:)`)で、母の相談が消える場面は見つからなかった。
  - 相談の行を書くのは `consult.ts` の `insertAlert` だけで、`source` は `'consult'` に決め打ちしてある。
  - 判定のジョブを積むのは `sms.ts`、`gmail.ts`、`page.ts` で、それぞれ `sms`、`gmail`、`page` を渡す。`call` を作るところはどこにも無い。電話のあとの声かけ(#238)からの相談も `/consult` を通るので `consult` になる。
  - `alert` が null になるのは、`alert_id` が無いか、30日の削除で行が消えたときだけ。帯は3日しか出さないので、母の相談が該当することは無い。
- 30分の見張り(`watchUnanswered`)
  - 家族(`role === "family"`)はどの `source` でも残り、「まだ解決していません」と1行がこれまでどおり届く。
  - 母に届くのは `source === "consult"` のときだけ。
  - 通知の枠(`needed`)は絞ったあとの人数で数えるので、多く取らない。
  - 新しい `it.each` は、4つの経路それぞれで、母に届かないこと、作者と妹に届くこと、`renotified_at` が付くことを見ており、落ちうる。
  - `source` が null の件は母に送らない。端末の帯の扱いと揃っている。
- 相談の Claude に渡す記録
  - 列は `source, level, summary, reasons, created_at` だけで、届いた文、URL の全体、送り主は D1 に無いので渡らない。
  - `summary` と `reasons` は、もともと `judge.ts` の `cardReasons` と `summarize` で、届いた文を写した理由を落としたものだ。
  - 電話番号やアドレスを含む理由は `carriesContact` で落ちており、試験もある。
  - 家族の情報(名前、メンバー)は渡していない。
  - 記録は母の言葉と別の `<untrusted>` に、`JSON.stringify` のあと `neutralize` をかけて入れている。中の `</untrusted>` や改行で区画を閉じたり行を足したりできないことを、試験が確かめている。
  - 記録は Claude への入力が1つ増えるだけで、通知先、共有の範囲、段階の下限を変える道は無い。
  - 「安全です」を返さない網(`soundsSafe` など)は、記録があっても同じように答えに当たる。
  - 記録が空のときは、`buildConsultRequest` の結果が前と `toEqual` で一致する。システムプロンプトにも注意書きが入らない。
  - 記録が読めないときは `.catch(() => [])` で、記録なしに Claude に聞く。
- 試験の既定を `call` から `consult` に替えた点は、主張を緩めていない。`cases.test.ts` の `newAlert` と Swift の `caseJSON` の既定を `consult` にしたことで、帯に出る、母に30分の通知が届く、という既存の試験は新しい絞り込みを通る形で落ちうるままだ。前の `call` のままだと、絞り込みのあとでは帯に出ず、通知も届かなかった。
- 設計の帯の段落、知らせの段落、30分の段落、計画の2つの手順は、上の3件目を除いてコードと合っている。家族のカードを変えないことも、`FamilyCard` の試験で見ている。
- `ios/Core` に iOS だけのフレームワークは入っていない。秘密、家族の実データ、外から写したコードも無い。
- `server` で `npx vitest run test/consult-findings.test.ts test/cases.test.ts` を流すと、2ファイル62件が通った。
- 差分には、変更と関係の無い整形の行(`pointsBack`、`policeInHerWords`、`decidePlan`、`consultRoute` の折り返し)が混ざる。動きは変わらない。
