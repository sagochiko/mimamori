## 指摘

### 1. `dropTags` が、ブラウザでは見える詐欺の本文と URL を消してしまう（重い。確かさは高く、再現済み）

場所は [`server/src/gmail.ts`](server/src/gmail.ts) の `dropTags`（707行目あたり）で、`if ((c === '"' || c === "'") && before === "=" && j < last[c])` の行が問題になる。2回目のあとの直しで入った後戻りだ。

`before` は直前の空白でない1文字を見ているだけなので、HTML の字句の決まりで「引用符の値の始まり」にならない `=` の直後でも引用符を開いてしまう。そこから同じ引用符が次に出るところまで飛ぶので、間にある `>` やタグ、本文がまとめてタグ扱いで消える。ブラウザのほうは最初の `>` でタグを閉じるので、母の画面には本文が出る。

本物の `mailPayload` に `tsx` で当てた結果を下に並べる。本文は `text/html` だけのメールにした。「直し前」は `3741db6` の `gmail.ts`、「直し後」はこのブランチの先頭（`c58eddb`）。

| 入れた HTML の形 | ブラウザの見え方 | 直し前 | 直し後 |
|---|---|---|---|
| `<p =">本文…">`（属性名の位置の `=`） | 本文が見える | text と url に残る | text は件名と後ろだけ、url なし |
| `<p a=b=">本文…">`（引用符なしの値の中の `=`） | 本文が見える | 残る | text は件名だけ、url なし |
| `<b c=d='>本文 '>`（単引用符） | 本文が見える | 残る | 消える、url なし |
| `<br =">本文…">` | 本文が見える | 残る | 消える、url なし |
| `<span a=b="></span><div>本文</div><a href=…>ここ</a><span c=">">` | 本文が見える | 残る | 本文は消え、`<a>` の href だけ残る |

本文は「至急、警察です。口座の確認のため `https://evil.example/pay` に暗証番号を入力してください」にした。1つ目の形の出力は次のとおり。

```text
直し前 {"text":"件名\n至急、警察です。口座の確認のため https://evil.example/pay に暗証番号を入力してください\"> 以上","url":"https://evil.example/pay"}
直し後 {"text":"件名\n以上"}
```

起きることを場面で書くとこうなる。リンクを `<a>` にせず本文に URL を書いただけの HTML メールで、送り手が冒頭に `<p =">` を1つ置き、末尾に `">` を置く。それだけで、規則にも Claude にも件名しか渡らない。`url` と `domain` も空になる。主役のニセ警察の文面がそのまま素通りし、段階は上がらない。`<a>` があるときは `anchorHrefs` が別に読むので url は残るが、警察、暗証番号、急がせる言い回しといった本文の印は消える（表の5つ目）。ブリーフの言う「詐欺の本文や押せるリンクが text にも url にも残らない形」に当たる。

ちなみに `<=" 本文 ">`（`<` の直後が `=`）は、直し前も直し後も消える。ブラウザでは文字として見えるので見逃しだが、今回増えたものではない。

直し方の案は2つある。

- 引用符を値の始まりと見るのを、HTML の字句の決まりどおりに絞る。タグが開くのは `<` の直後が ASCII の英字か `/` と英字のときだけにする。引用符を開いてよいのは、その `=` が属性名のすぐ後ろにあり、引用符なしの値の途中でも、`=` で始まる属性名の中でもないときだけにする。
- もっと安全側に倒す手もある。引用符の中に `>` があったら、そのタグは最初の `>` で閉じたとみなし、後ろを本文に戻す。消しすぎるより、ブラウザが見せない文字を余分に渡すほうを選ぶ形で、`anchorHrefs` の注記にある「迷ったら残す」と同じ向きになる。

どちらの案でも、上の表の5つの形を `server/test/gmail.test.ts` に「本文と url が残る」テストとして足してほしい。

## 確かめて問題なかったこと

- `İ` で `dropBlocks` の位置がずれる件（`b55c15e`）は直っている。`"İ".repeat(200) + "<style>a{}</STYLE>警察です https://evil.example/pay"` を当てると、本文と url が残り、`domain` は `evil.example` になった。閉じのタグは、`(style|script|head)` に限った名前から作る大文字小文字を問わない正規表現で元の文字列を探しており、正規表現に外の文字は入らない。
- 属性の値の中の `<` で href を落とす件（`0bacd2b` の `anchorHrefs`）も直っている。`<p title="x>y">` の形では本文と url の両方が残った。引用符が閉じずに次の `<a` まで続いても、href の正規表現はその範囲の全体を読む。`<a x=y=" href="https://evil.example/pay">` でも url が残ったので、`anchorHrefs` のほうに取りこぼしは見つからなかった。
- `header.from` のドメイン（`cf43212`）は、`<untrusted>` の外には DMARC の決まった語だけが残る形になった。ドメインは `neutralize` を通したうえで、`fields` の先頭として中に入る。指示の文と `docs/design.md`、`docs/plan.md` の書き換えも、この形と合っている。
- 時間は長さに比例している。`<a x="`、`<p a=">`、`<`、`="` の繰り返しと、それらを混ぜたものを5万、10万、20万、40万字で流した。かかった時間はどれも 4〜9ms、8〜17ms、15〜26ms、31〜53ms で、ほぼ倍ずつ増えた。
- `server/test/gmail.test.ts`、`claude.test.ts`、`judge.test.ts` は `vitest run` で 399 件すべて通った。
