## 指摘(重い順)
重いものはない。軽いものが2つある。どちらも採らずにマージしてよい。

1. 軽い。[`ios/SafariExtension/Resources/manifest.json`](ios/SafariExtension/Resources/manifest.json) 4行目の `description` は「怪しいページを開いたときに知らせます」だが、今の拡張にはコンテンツスクリプトが無い。manifest には name、description、version、icons しか入っておらず、[`docs/plan.md`](docs/plan.md) のタスク9はまだ手を付けていない。TestFlight の版で母や審査員が Safari の拡張機能の設定を開くと、まだ動かない働きが書いてある状態になる。タスク9は「ページを読めなかったら飛ばす」ことになっているので(plan.md 353行)、飛ばしたときはこの文を直すか拡張を外す必要がある。文の中身は [`docs/design.md`](docs/design.md) 147行の「ページの上に警告を出す」と食い違っておらず、「安全」とも言っていない。画面の文言の決まりとの関係でいうと、ここは App Store Connect が必須にしている欄で(PR に断られた理由の原文がある)、アプリの画面ではないので外れていないと判断した。manifest.json を読み、ディレクトリの一覧と plan.md、design.md を照らして確かめた。
2. 軽い。仮のアイコンの「み」は、どのフォントからどうやって作ったかがリポジトリにも PR にも残っていない。描かれ方からすると macOS に入っているゴシック体を書き出したものに見える(推測)。システムのフォントで書き出した文字を画像にすることは普通に許されている範囲だと考えるが、「期間中に作った」ことを示す記録として、作り方を PR か dev-log に1行書いておくと安心できる。差し替えるまでの仮のものなので、急がない。画像を目で見て、PNG の中身を strings と mdls で調べて確かめた。

## 確かめて問題なかったこと
- `.pbxproj` は `project.yml` から生成したものと一致する。`git archive HEAD ios` で scratchpad に写しを作り、XcodeGen 2.45.4 の `xcodegen generate` で生成し直して `diff` で比べた。結果は IDENTICAL だった(写しはもう消した)。`ASSETCATALOG_COMPILER_APPICON_NAME = AppIcon` は main の時点で pbxproj の2か所(631行と680行)に入っていた。XcodeGen が application のターゲットに最初から入れる値なので、`project.yml` に足しても pbxproj は変わらない。今の設定をはっきり書いたものなので害はない。
- アイコンは Apple の single size の形に合っている。Contents.json は `idiom: universal`、`platform: ios`、`size: 1024x1024` の1枚だけ。sips で調べると icon-1024.png は 1024x1024、RGB、`hasAlpha: no` だった。PR に貼られたアーカイブの中身では、120x120 の AppIcon60x60@2x と CFBundleIconName = AppIcon が作られている。
- Safari 拡張のアイコン5枚(48、96、128、256、512)は、ファイル名どおりの寸法で、アルファは無い。manifest の `icons` は数字の名前に文字列の値で、PR にある断られた理由(numerically-named properties)に合う。`description` は19文字で、112文字以内の決まりを満たす。MV3 の形も崩れていない。5枚とも pbxproj で SafariExtension の Resources ビルドフェーズに入っている。
- ビルド番号は `project.yml` と pbxproj の Debug と Release の両方で 2 になっていて、食い違いはない。
- 公開してはいけない情報は入っていない。PNG に作った人やパスのメタデータは無かった(mdls の kMDItemCreator と kMDItemWhereFroms は null)。新しく出てくる ID は DEVELOPMENT_TEAM だけで、これは main にもともとあり、CLAUDE.md で公開してよいとされている。コミットメッセージにも個人の情報は無い。
- 変更は `ios/` の下だけ(`git diff origin/main...HEAD --name-only`)。`ios/Core` には触れていない。設計の約束(危なさの段階、「安全」と言わない、家族への知らせ)に関わるコードはこの PR に無い。
