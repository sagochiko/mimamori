## 指摘

### 1. 詐欺の相談が「今は調べられなかったよ」に落ち、家族に回らず記録にも残らない道ができた(重い、確度は高い。再現した)

場所は [`server/src/consult-judge.ts`](server/src/consult-judge.ts) の1521行目からの新しい分岐(`plainLevel3 && !image && claude.kind === "help" && !handoff && search_query あり && !usable(claude.action)`)。

この分岐は、規則にも CONTACT にも案内しない話題の網にも当たらない詐欺の話を拾ってしまう。Claude が `kind: "help"` に取り違え、`search_query` を書き、action を空にするか、網に当たる文(「大丈夫だよ」など)にした場合だ。main ではこの形は `UNANSWERED_REPLY`(段階2、家族に知らせる、記録あり)に落ちていて、Claude の取り違えを受け止める最後の網になっていた。この PR で、その網が `search_query` が付くだけで外れる。

`judgeConsult` に固定の Claude の答えを渡して、このブランチと `origin/main` で比べた。スクラッチパッドで `npx tsx` を使い、リポジトリには何も書いていない。

| 母の言葉 | Claude の答え | main | このブランチ |
|---|---|---|---|
| `息子が風邪で声が変わったって言ってた。今から上司の人が来るらしい` | help、action 空、query あり | 段階2、家族に知らせる、記録あり | 段階3、家族なし、記録なし、`SEARCH_FAILED_REPLY` |
| 同じ | help、action `大丈夫だよ`、query あり | 段階2、家族に知らせる | 同上 |
| `国税庁から未払いがあると言われた` | help、action 空、query あり | 段階2、家族に知らせる | 同上 |

前の段で `ASK_SCREEN` や `LOW_CONCERN` に落ちる形(「示談金」「お金」を含むもの)は影響を受けなかった。抜けるのは、警察の語、お金の語、連絡の語のどれにも当たらない、オレオレ詐欺の後半や役所を名乗る話のような言い方だ。

Claude の取り違えが前提だが、取り違えは注入の旗が立たない形でも起きうる。そのときの網を外す変更で、見逃しは誤報より重いという決まり(`docs/design.md` の「誤報は家族への要らない知らせで済み、見逃しは…」)とぶつかる。

直し方の案は3つ。
- 分岐を `claude.action.trim() === ""` のときだけにする。網に当たる非空の action は、今までどおり `UNANSWERED_REPLY` に落とす。
- `record: true` にして、家族があとで見られるようにする。
- 天気やニュースの形だと分かるときだけに絞る。

今回の不具合は「action が空」だったので、1つ目の案だけでも本番で起きた不具合は直る。テストの `says it could not look it up when the first answer cannot be read out`([`server/test/consult-search.test.ts`](server/test/consult-search.test.ts) の action が `安心して、明日は晴れ` の例)は、まさにこの抜け道を正しい動きとして固定している。

### 2. Claude が handoff を立てたスマホの相談でも「調べられなかった」になり、記録が消える(中くらい、確度は高い。再現した)

場所は同じ分岐。条件の `!handoff` はローカルの変数で、`firstAnswer` が真のときは `claude.handoff` が真でも偽になる(1382行目 `handoff = stuck || (claude.handoff && !firstAnswer)`)。そのため、`claude.handoff: true` で query があり action が空の答えは、`firstAnswer` の分岐(`ASK_AGAIN_REPLY`、`record: true`)より先にこの分岐へ入る。

`judgeConsult` 側は `claude.handoff` のときは2回目を呼ばない(1661行目)。その結果、母には毎回「今は調べられなかったよ」が返り、記録も残らない。上の表と同じ3つの文に handoff: true を足すと、main では `ASK_AGAIN_REPLY` で記録あり、このブランチでは `SEARCH_FAILED_REPLY` で記録なしになった。

Claude が家族に渡したいと言った相談なのに、「少したってからもう一度」と案内してしまう。直し方は、分岐の条件に `!claude.handoff` を足すこと。

### 3. テストが抜け道を見ていない(軽い、確度は高い)

`still does not answer it so on %s` は `not.toBe(SEARCH_FAILED_REPLY)` しか見ていない。家族に回ったか(`toFamily`)も記録されたか(`record`)も見ていないので、別の固定の1行に落ちれば通ってしまう。

指摘1のような、網に当たらない詐欺の話を help と取り違えた例のテストもない。追加してほしいのは次の2つ。
- `息子が風邪で声が変わったって…上司の人が来るらしい` に help、query あり、action 空(または網に当たる文)の答えを返したとき、`toFamily: true` になること
- handoff: true のときに `SEARCH_FAILED_REPLY` にならないこと

## 確かめて問題なかったこと

- `parseClaudeConsult` が空の action を受け取るのは、`search_query` が空でないときだけになっている(669〜672行目)。query のない空の action は、今までどおり null になる。kind が scam のときに空の action が通っても、段階1と2は決まった文で、段階3は `lowConcernWords` が空行を外して `LOW_CONCERN_ACTION` だけになる。母に空の文が届くことはない。
- `judgeConsult` の2段目の条件では、`judged.reply === SEARCH_FAILED_REPLY` を足しても、`toFamily`、`unguided`、`claude.handoff`、`image`、`level !== 3` の除外はそのまま残っている。2回目の答えは今までどおり `searchReply` の網を通り、段階、通知先、記録は変わらない。通知先や段階を下げる道は増えていない(指摘1と2は2段目ではなく `decidePlan` の側で起きている)。
- `consult_trace` のログ([`server/src/consult.ts`](server/src/consult.ts) の `logTrace`)に入るのは、`event`、`script`、`claude_null`、ミリ秒、`query` と `search_called` と `search_used` の真偽、`level`、`to_family`、それに決まった名前の `reply` の種類だけ。母の言葉、Claude の文、検索の語、出典のホスト、家族や端末の印、トークンは入っていない。`.claude/rules/server.md` の最後の行に沿っている。`consult` から返る2か所(`!p.record` のときと、最後)の両方でログを出していて、その間にほかの return はない。
- 小さな点で、`reply` の分類は `p.reply` を見ていて、家族に届かなかったときに実際に返す `notReachedReply(...)` は見ていない。調べるときに少しずれるだけで、個人の情報の問題ではない。
- `npx vitest run test/consult-search.test.ts` を流すと、50件すべて通った。
- `docs/design.md` の追記は、コードの動き(家族に知らせない、記録しない、ログの中身)と合っている。ただし指摘1を直すなら、追記の「自分の答えを…読み上げられない文にしたりしたときも」のくだりも合わせて直す必要がある。
