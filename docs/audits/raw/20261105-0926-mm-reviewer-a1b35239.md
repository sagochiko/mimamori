## 指摘(重い順)

### 1. `CallEndWatcher.start()` が `observer.calls` を読むのは最初の1回だけで、途中から開いた通話を測れない

場所は `~/develop/mimamori/.claude/worktrees/issue-99-followup/ios/App/CallEndWatcher.swift` の31〜42行。`guard observer == nil else { return }`(32行)が先にあるので、`tracker.started(with: observer.calls...)`(37〜41行)は観察者を作った最初の `start()` でしか走らない。

起きる場面。母の役でアプリを一度開き(観察者ができる)、ホームに戻って止まる。詐欺の電話がかかってきて出る。話の途中で不安になってみまもりを開く(`cameToFront()` → `start()` は guard で即戻る)。そのままアプリを前面にしたまま電話を切る。#25 の結果どおり止まっているあいだに `hasConnected` が届いていなければ、`CallTracker.connectedAt` にこの通話が無く、前面で届いた `hasEnded` は `changed`(`ios/Core/Sources/MimamoriCore/CallTracker.swift` 29行)で nil になり、声かけは出ない。Issue #99 の完了の条件「アプリが前面のあいだ `CXCallObserver` を持ち、通話の終わりを `CallFollowUp.callEnded(_:)` に渡す」と、この関数自身のコメント「A call already under way when she opened the app counts from now」のどちらにも反する。主役の場面(電話の最中に母がアプリを開く)に当たる。

直し方は、`tracker.started(with:at:)` の呼び出しを guard の外に出し、`start()` のたびに `observer.calls` を読み直す。`changed` は `connectedAt[id] == nil` のときだけ始まりを入れる(32行)ので、既に測っている通話の始まりは変わらず、何度呼んでも悪くならない。

確からしさ。コードの経路は確かめた(中〜高)。実機で再開時に `callChanged` が遅れて再送されるか、`observer.calls` がそのとき最新かは #25 で測っていないので未確認(中)。再送されるなら今の作りでも再開時から数えるので同じ結果になり、直しは損にならない。

### 2. `UserDefaults.didChangeNotification` は「設定」アプリの書き込みでは届かない(動きは正しいがコメントが誤り)

場所は `~/develop/mimamori/.claude/worktrees/issue-99-followup/ios/App/AppModel.swift` の76〜81行。コメントは「Settings > みまもり writes here」とあるが、Apple の文書(`developer.apple.com/documentation/foundation/userdefaults/didchangenotification`、取得して確かめた)は「If a different process changes your app's settings, the system doesn't generate this notification. To detect changes made by another process, register a key-value observer object.」と書いている。この観察者は同じプロセスの書き込み(`UserDefaultsCallFollowUpStore.save` など)でしか動かず、それは `appliedCheckIn` の比較(277行)で弾かれるので、実質何もしていない。「設定」の変更は `.active` の `cameToFront()`(254〜257行)で拾われるので、設計の「アプリが次に動いたときに読む」どおり動く。直すべき不具合ではなく、コメントの誤りと不要なコード。確からしさは高(文書で見た)。

### 3. 遅れて届いた `hasEnded` の `endedAt` が再開時刻になる(未確認の場面)

`CallEndWatcher.swift` 50〜61行は `now = Date.now` を `endedAt` にする。もし iOS が止まっていたあいだの `hasEnded` を再開時に遅れて届けるなら、通話は何時間も前に終わっていても「さっきの電話、大丈夫だった？」になり、`CallFollowUp.swift` 102行の `lastAskedAt` も再開した日になる(日付をまたぐと、飛ばす毎日の声かけの日が通話の日とずれる)。ファイルの頭のコメントは長さの面(長めに数える)だけを論じている。実機で測っていない場面なので、直すかどうかは親の判断。確からしさは低(未確認)。

### 4. 夜の通話の声かけと12時間の期限の組み合わせ(軽い)

夜(22時〜7時)に前面で通話が終わると `.askOnNextOpen` で画面に出し、`lastAskedAt` でその日の毎日の声かけを外す。画面の声かけは `promptLifetime`(`CallFollowUp.swift` 70、113行)の12時間で消えるので、母がそのまま閉じて昼までに開き直さないと、その日は何も聞かれない。夜にアプリを前面にしたまま通話する場面に限るので軽い。止める指摘ではない。
