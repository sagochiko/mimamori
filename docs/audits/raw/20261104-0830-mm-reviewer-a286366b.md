## 実装役が Edit で書いた件の判断

結論を言うと、「止められた操作を別の書き方で通さない」決まりとは食い違わないと判断した。理由は3つある。

- 守りが守っているのは、最後に測る組を読むこと、解錠の印を作ること、最後の測定を走らせることだ。実装役がしたのは、その名前を含むテストと文書の文を書くことで、守っている行為そのものではない。Bash の止めは、heredoc の文字に名前が入っていたための当たりだった。
- 止めた理由の文(lib.sh の19行の `MENTION_HINT`)は、名前に触れるだけなら Write で書くよう勧めている。実装役はその道に従い、名前を含む所だけを Edit で書いた。dev-log にもその経緯を書いている。
- 書いたテストが走らせて作る解錠の印は、`mktemp` の使い捨てのリポジトリの中だけにある(`~/develop/mimamori/.claude/worktrees/harness-plumbing/scripts/test-hooks.sh` の353行と355行)。測定のコマンドも偽の npx に替えてあり、本物の例文には触れない。作る先は5行の `T=$(mktemp -d)` の下の `$T/mk` と `$T/mkwt` で、終わると trap で消える。これはコードで確かめた。本体の木に印があるかは、名前を含むコマンドが守りに止められるので見ていない。

ただ、境目は文字にしておいたほうがよい。`MENTION_HINT` は「Issue、PR、コメント、コミットのメッセージ」と「Write」しか挙げていない。コードや文書を Edit で書くのは類推だ。また guard-holdout は Edit と Write の中身(`new_string`、`content`)を見ない。だから「書いたものを走らせると守っている行為をする」コードを Edit で書く道は、決まりでしか止まっていない。`MENTION_HINT` に「文書やテストで名前に触れるだけなら Edit か Write で書いてよい。書いたものが守っている行為をしてはいけない」と足すとよい。
