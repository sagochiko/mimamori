# 過去の受賞作の調べもの

2026年11月3日に作者が頼み、11月4日に、過去の Anthropic のハッカソンの受賞作を調べた。作者の問いは「日時つきで何をしたかを書いているか」「受賞作に共通する Claude の設定や書き方があるか」の2つ。

調べたのは3体のサブエージェントで、受賞作の一覧とリポジトリを集める役(Sonnet)、各リポジトリの設定と記録を読み比べる役(Sonnet)、その結果をこのリポジトリと [`docs/judging.md`](../judging.md) に当てはめる役(Opus)に分けた。報告の原文は次の3つにある。

- [`raw/20261104-0815-winners-list.md`](raw/20261104-0815-winners-list.md) 受賞作の一覧と出典
- [`raw/20261104-0815-winners-compare.md`](raw/20261104-0815-winners-compare.md) 11件のリポジトリの読み比べ
- [`raw/20261104-0815-winners-apply.md`](raw/20261104-0815-winners-apply.md) このリポジトリへの当てはめ

ほかの人の作品のコードは写していない。読んだのは設定、記録、README の書き方と構成だけで、取ったリポジトリの中のものは何も実行していない。

## 分かったこと

公式の受賞発表があったのは Built with Opus 4.6(2026年2月)、Built with Opus 4.7(2026年4月)、Claude Opus 4.8 Build Day(2026年6月13日)の3つで、受賞作は14件、公開リポジトリが見つかったのは11件だった。

1つ目の問いについて。11件のうち開発の経過を書いたファイルを持っていたのは5件で、時刻まで書いたのは 4.6 の1位の CrossBeam だけだった。見出しは「Wednesday, February 11 — 10:30 PM PST」の形で、出来事の時刻ではなく、まとめを書いた時刻だった。4.7 の1位の Medkit は日の単位で、記録の型を決め、コマンドに下書きさせて作者が承認する仕掛けを置いていた。このリポジトリの [`docs/dev-log.md`](../dev-log.md) は時刻まで書いていて、細かさは足りている。足りないのは、記録からコミットと PR へ辿る道と、作者自身の言葉だった。

2つ目の問いについて。11件に共通していたのは `CLAUDE.md`(7件)と Claude の共著のコミット(8件)くらいだった。サブエージェントの定義は0件、Claude Code のフックは1件、MCP の設定は0件。大会ごとに審査の仕方が違い(Tekton のリポジトリにある参加者ガイドは、自律をセッションログから、統率を指示書と採点基準とワークフローのスクリプトから採り、統率は使った機能の種類では見ないと書いていた。ガイドの題は「Claude Fable 5 Build Day」で、4.8 の大会のものかは確かめていない)、11件では設定の有無と受賞を結びつけられない。今の大会はキックオフで「Skills、サブエージェント、MCP、フックなどを目的に応じて使い分けているか」を見ると説明しているので、受賞作に無いことはハーネスを減らす理由にも増やす理由にもならないと判断した。

## 親が確かめたこと

当てはめる役は、根拠に使った5つの原文(CrossBeam の `progress.md`、Medkit の `docs/evolution.md` と下書きのコマンド、Medkit の `CLAUDE.md`、4.8 の参加者ガイド、ARIA の `decisions.md`)を開いて確かめたと報告している。親のセッションは、このうち2つを取ったリポジトリで読み直した。CrossBeam の `progress.md` の見出しは「## Tuesday, February 10 — 6:20 PM PST」のように曜日、日付、時刻の形だった。Medkit の `CLAUDE.md` の88行と89行には、分野ごとの専門家のサブエージェントを作らないことと、長い決まりの箇条は Opus 4.7 が文字どおり従いすぎるのでフックか lint にすることが書いてあった。残りの3つは確かめていない。

今の大会の審査基準と提出フォームの設問は、大会のページに載っておらず、[`docs/judging.md`](../judging.md) に書いたとおりとして扱った。

## 決めたこと

すぐに入れたのは1つだけで、開いていた PR のうち4本が開発の記録に足していて、当てはめる役が複製で #40 と #41 を併合すると衝突したため、手元の git の設定(`.git/info/attributes`)で `docs/dev-log.md` を union で併合するようにした。リポジトリの中身は変えていない。これから切るブランチにも効かせるため、次のハーネスの PR で `.gitattributes` に同じ1行を入れる。

当てはめる役が挙げた次の4つは、主役の一続きを母に届けたあとに、作者に聞いて決める。

1. 開発の記録の終わりに、変更を運んだコミットと PR を書く。見出しの時刻は記録を書いた時刻だと冒頭に書く
2. 1日の終わりに作者のひとことを聞いて残す(作者の時間を1日2〜3分使う)
3. README の Claude の節を、仕組みと、それが失敗を捕まえた跡のリンクの組で書き、動画のリンクを冒頭に置く
4. テストの関門が止めた回数を、通した回数と分けて数える

採らないと決めたものは3つある。生のセッションログをリポジトリに置くこと(今の大会に自律の基準は無く、公開するリポジトリに家族の情報や秘密が混ざるおそれのほうが大きい)、定期的に記録の下書きを回すこと(記録の切れ目は `/mm-task` の終わりと合っている)、サブエージェントを skill に寄せて減らすこと(Medkit の一文は分野ごとの専門家の役の話で、書いた本人と別の文脈で確かめる役の話ではない)。

[`docs/harness.md`](../harness.md) の「過去の受賞作で公開リポジトリを確認できた8件のうち、サブエージェントの定義を置いていたものは無かった」は、今回11件で数え直しても0件で合っていた。ただこの書き方は「受賞作に無いのになぜ置いたのか」を招くので、役を分けた理由と使った回数で書き直す案も、上の4つと一緒に作者に聞く。
