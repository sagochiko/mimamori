# 精度の記録

`make eval` を走らせるたびに1行増える。測り方と、測る前に決めた件数、分母、許容する失敗は [`eval/README.md`](README.md) にある。もとになる決まりは [`.claude/rules/eval.md`](../.claude/rules/eval.md) と [`docs/design.md`](../docs/design.md) の「精度の測り方」にある。holdout は提出前に1回だけ測る。

2026年11月5日の #74 の行から、声の相談(`consult`)の例文は母の相談と同じ道で測っている(測り方は [`eval/README.md`](README.md) の「相談の測り方」)。`rules` の行の `consult` は、ニセ警察の筋書きに当たれば1段階、当たらなければ `judgeByRules` の段階で、本番で Claude が答えられないときの2段階は数えない。`rules+claude` の行の `consult` は、筋書きに当たれば Claude を呼ばず1段階、当たらなければ相談用の `requestClaudeConsult` と `judgeConsult` で決めた段階だ。それより前の行の `consult` は、`judgeByRules` だけ(`rules`)の数字になっている。

測り方を変えた最初の `rules` の回(2026年11月5日、99633ed)で、dev の `consult` の見逃しは 15/25 のまま変わらなかった。誤判定も 0/20 のままだった。筋書きに当たったのは詐欺の5件(c-fp-acct-01、02、05、09、c-inj-01)で、そのうち4件が2段階から1段階に上がり、`consult` の詐欺で1段階になったものは2件から6件になった。見逃しが減らないのは作りのためで、筋書きは警察の部品を1つ以上要し、警察の部品があれば `judgeByRules` だけでも2段階以上になる。筋書きの規則は2を1に上げるが、規則が見逃した相談を拾うことはない。見逃した15件(あいまいな話し方の8件、c-fp-acct-04、07、08、10、c-fp-war-03、04、c-inj-02)には警察の部品が無く、相談用の Claude に任せる分になる。`rules+claude` の行は、鍵が無く測っていない。

2026年11月6日の #137 から、`rules+claude` の SMS、メール、ページは本番と同じ関門と `decideFor` で測る(測り方は [`eval/README.md`](README.md))。それより前の `rules+claude` の行は、本番がまだ Claude に見せていなかった印の無い24件(dev の SMS、メール、ページから8件ずつ。うち詐欺はページの p-sc-12 の1件)も Claude に渡していて、見逃しが本番の流れより少なく出ている。今の関門でも、ページの8件(p-sc-12 を含む)は Claude に渡さない。Claude が答えなかった例文の段階も、規則が決められなければ2段階で数えていた。
