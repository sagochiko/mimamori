# 監査役のチェック項目

`mm-auditor` がこれまでの判断の記録と突き合わせる一覧。項目は審査の4基準、設計の「見落としやすいところ」、ハッカソンのルール、記録の取り方から作った。

## 進め方

- 今のマイルストーンの主役(通話のあとの声かけ、声の相談、家族の引き受け、母への返事)より先に、周りの機能に時間を使っていないか
- 実機と母に早く届けることより、手元で磨くことを優先していないか。母に渡せない日が続いていないか
- 人が要る作業が「作者: 」の Issue にならず、どこかで止まっていないか。開いたままの「作者: 」の Issue が、どの Issue を止めているか
- 1つの Issue を4時間以上抱えていないか。分けるか、範囲を削るか、人に回すかを決めたか
- 同じ直し方(プロンプトの言い回しだけ、など)を3回以上続けていないか

## 精度の測り方

- 規則だけと、規則と Claude の組み合わせを、同じ条件で比べたか
- 1件の差をぶれではなく改善として扱っていないか
- 見逃しと誤判定を、1件ずつ中身を見てから直したか
- 本物の SMS(認証コード、宅配の本物の通知)を迷惑フォルダに回していないか
- 仕込みの例(「家族に知らせないで」)で、危なさが上がることを確かめたか
- holdout を見ていないか。dev の数字だけで判断しているか

## 見落としやすい5つ(docs/plan.md)

- 本物の SMS を迷惑フォルダに回す
- DNS が落ちて母の iPhone がネットにつながらなくなる
- 本文の仕込みに Claude が従う
- 2人がほぼ同時に引き受け、2人とも受け持ちになる
- Gmail の許可が7日で切れ、知らないうちに止まる

## 審査の4基準

- インパクトでは誰が、どんな場面で、どれくらい困っているかを、数字と母の言葉で示せる材料がそろっているか
- デモでは冒頭15秒で「誰の、どんな課題を、どう解決するか」が言えるか。保存した結果ではなく動いているものを映せるか
- Claude の活用ではサブエージェント、skill、フック、MCP を目的ごとに使い分けた記録が `docs/dev-log.md` と `docs/claude-usage.md` にあるか。作品の核で Claude が何をしているかを説明できるか
- 深さと実行力では試行錯誤の跡(捨てた案と理由)が残っているか。母が手助けなしで使えたことを確かめたか

## ルールと安全

- 作者の既存アプリのコード、権利のない素材、秘密、家族の個人情報がリポジトリに入っていないか
- どこかで「安全です」と返していないか
- 開発の記録が日付つきで残っているか

## ハーネス

マイルストーンの終わりに、判断の見直しとは別にこの節だけで1回走らせる。Anthropic の文書は、CLAUDE.md と `.claude/rules/` を定期的に読み直し、古い指示と食い違う指示を消すよう勧めている(https://code.claude.com/docs/en/memory)。

- `.claude/settings.json` の allow、ask、deny と、フックが止めるものが食い違っていないか。deny で止めたものをフックが通す、またはその逆になっていないか
- CLAUDE.md、`.claude/rules/`、skill に書いた「必ず」「してはいけない」のうち、どのフックにもテスト(`scripts/test-hooks.sh`)にも守られていないものはどれか。破られたことがあるなら、フックか deny に移したか
- フックが正当な作業を止めた記録が `.claude/logs/usage.jsonl` と `docs/dev-log.md` にないか。止められた作業を別の書き方で通していないか
- 古くなった指示、ほかと食い違う指示、もう無いファイルやコマンドを指す指示が残っていないか
- 各 Issue の PR の「振り返り」で、同じ種類の失敗が2回出ていないか。出ているのにハーネスを直していないものはどれか
